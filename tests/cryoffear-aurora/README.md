# Cry of Fear first-pistol Aurora

run.py builds aurora.cpp and aurora_render.cpp with actual GoldSrc client/model/Triangle SDK and executes the private original script supplied beside --sample's samples directory. Required arguments: --environment <x86 compiler-env.json> --sample <private original client.dll> --output build/cof-client-aurora-20261111. Original assets/bytes are never published.

Prepare(scriptBytes) is cold and loads sprites/fog2.spr through pfnSPR_Load/GetSpritePointer. It parses the supported fields of the two-type gunsmoke resource, rejects unknown fields and unsupported resources/remote/bone/special modes explicitly, and prepares immutable trig/sprite data. Call Add(owner, aurora/gunsmoke.aur, 1, exactViewModelPath, 0, explicitLimit) only for the authenticated first-four-pistol event. Frame receives real elapsed time, original render mode and right/up camera vectors. Actual SDK engine provides time/entities/random and the Triangle API. No empty success sink or CS smoke substitute exists.

Call KillLocal(false) for original soft weapon-particle kill, KillLocal(true) for hard kill, DeleteOwner for first owner match, Clear for original manager clear and VideoInit for exported HUD_VidInit/reset clear plus host resource invalidation. After VideoInit prepare resources again cold. Clear alone preserves prepared sprite; full unload must destroy/invalidate this owner. The original ordinary HUD Reset virtual is empty: do not invent a death/ResetHUD clear.

The original expires main life into a three-second drain, keeps emission until its strict deadline, retains empty systems until delete/clear and skips updates/removal for body70/184/137 or nonzero render mode. Each system owns20 original pool slots; newly emitted head is not updated in the same traversal. A fixed64-system host bound returns CapacityExceeded without deleting another system; the original dynamic list has no64 bound or natural system deletion; sustained firing remains blocked pending an explicit host capacity strategy. The owner thread controls all calls.

2026-11-11 human-authorized defect fix: initialize proven uninitialized bounce/yaw/inherit/water controls and initial pool positions to0, preserving reused slot positions. evidence_probe.py executes the original constructor/parser/pool against three raw heap patterns and demonstrates the defect; this is explicit host deviation, not an invented original default. Other original arithmetic/order/lifecycle remains instruction-matched.

Tests: main.cpp checks actual script/SDK sprite and quads, pool order, no same-frame child update, body/hard-kill gates, unknown fields, clear/vidinit and capacity. oracle.py runs original manager/parser/pool/lifecycle/particle/render instructions for3561 continuous frames in11 scenarios (including zero-owner natural/delete/hard-kill paths) with all20slot state/float bits and RNG count compared. render_oracle.py compares2362 original render cases including UV, corners, color/fade and frame endpoint. Viewpunch has independent5947 cases under cryoffear-view-punch.

Compilation and instruction tests do not establish host hook correctness, delivery, visible smoke, runtime frame time or gameplay. Those remain pending. Resource preparation/immutable caller lifetime is a documented host adaptation for performance, not a claim of measured FPS improvement.

Owner zero is valid: original local Particle overwrites owner with exact viewmodel.index, including0. Particle.owner0 then takes the original free-particle branch; do not substitute player identity or force attachment following. Negative owner is outside this implementation scope and rejected. The SDK check confirms a displaced viewmodel attachment does not move the zero-owned main.
