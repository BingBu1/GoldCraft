# IEEE CRC32 宿主等价验证

本夹具验证 ReHLDS 既有 CRC 接口的结果、分段与内存访问边界，不改变校验范围，也不把硬件 CRC32C 当作 IEEE CRC32。原 CSOL 证据与宿主适配边界见 [原版取证报告](../../docs/2026-11-07_取证-CSOL引擎CRC32与宿主模型校验边界-report.md)；算法修改前合同见 [优化报告](../../docs/2026-11-07_优化-模型CRC等价批量计算-report.md)。

## 可复现输入

- 使用真实 ReHLDS SDK 的 `CRC32_t`、Windows 页保护 API，与当前 `native/engine/crc32_ieee.h`；编译为 x86、C++20、O3、ThinLTO、AVX2、precise。
- 旧 oracle 从 ReHLDS 提交 `550f2d62f13f4ebeb029c1d9d1c212133202611d` 的 `rehlds/engine/crc.cpp` 提取原表、Init、Final、ProcessByte、ProcessBuffer。Git blob 为 `df6f52ba991e081d0226fd636f1a964fbfed259a`，完整旧文件 SHA-256 为 `a24e83238af6bf397eb825e000debadb119a82b39dd65cb475713d81b685ad85`。
- 当前 wrapper 从实际工作树同文件提取，直接调用生产头文件。只生成必要函数摘录，不复制源码树。每段偏移、SHA、编译命令和实际 include 身份写入本地证据。
- 独立逐位 oracle 不使用任何查找表；实际模型另与 Python zlib 比较。每轮使用不同未取反种子，原/新计时次序交替。
- 默认复用 `build/engine-studio-storage-tests/plan.json` 的已核编译配置及 `build/engine-studio-safety-bench/plan.json` 的实际 150 个角色路径。运行时读真实资源，逐个释放，不生成资源副本。

```powershell
python tests/engine-crc32/run.py --prepare-only
python tests/engine-crc32/run.py
```

先协调单 TU 编译与测试窗口。输出固定在 `build/engine-crc32`；准备模式不调用编译器、不运行测试。结果中的模型 SHA 在执行前后重新读取比对，哈希会预热文件缓存，所以计时仅表示缓冲区内 CRC 计算，不能代替换图时间。

## 2026-11-07 独立审查与执行

静态审查未发现接口变化：同一 `0xEDB88320` 多项式，保持未取反中间状态；仅在剩余长度至少 8 时读取两个 DWORD，通过 `memcpy` 支持未对齐地址，余数逐字节；零及负长度不读取输入、不改变状态。输入与输出状态字发生别名时，仍在完成输入计算后写结果。保留全部调用方及完整原文件校验，没有缓存或跳过 CRC。

真实 x86 编译、链接、执行均成功，**303,085 个断言通过**：

| 范围 | 结果 |
| --- | --- |
| 标准 `123456789 → CBF43926`、空输入、256 项旧表 | 通过 |
| 全部 0–1024 短长度、16 种偏移、8 个固定种子；长至 4 MiB；2048 组任意种子/长度/偏移 | 与旧函数及逐位 oracle 相同 |
| 每个分割点、逐字节、随机多段、段间负长度、Final | 状态相同 |
| 输入别名输出状态字、1024 个逐位修改位置 | 原/新相同且变更均检出 |
| 首地址前不可访问、末字节后不可访问、输入只读；NULL/无效地址配零或负长度（含 INT_MIN） | 无越读、无写入、状态相同 |
| 150 个真实模型，共 1,229,174,960 字节，3 轮共 450 项 CRC | 原/新/zlib 全同 |
| 每个真实模型首/中/末各改一位，共 450 次 | 原/新同值且均不同于未修改值 |

功能断言 285,094，保护页断言 17,090，真实模型断言 901。记录了 593 个实际 include 身份；生产源码和全部模型执行前后 SHA 不变。编译器仅报告现有 SDK 字符串告警及测试文件 `u8path` 的弃用提醒。
