# Actual native jump prediction

The probe loads the exact, unmodified native client sample in a separate x86
console process and calls its real `HUD_PlayerMoveInit` and `HUD_PlayerMove`
exports. Public engine callbacks supply a flat floor. No graphical client or
server is launched. Samples and dependencies must remain in workspace
`analysis` and `sandbox` respectively; the protected installation is read-only.

Run `run.py` with `--compiler`, `--environment`, `--native`, `--dependencies`
and a fresh `--output` under `build`. The environment is an existing verified
x86 Visual Studio environment JSON. The sample SHA is checked before loading.

The receipt records source identities, compilation, native execution and input
stability. `layout.json` is generated by the same SDK compilation and is consumed
by `tools/Observe-NativeMovement.py` for bounded external reads. Engine callbacks
and offline native execution do not measure physical input, network latency,
camera presentation, real-map collision or game FPS.

The sufficient-balance gate must preserve native same-command departures. The
probe deliberately retains the original air/held-button latch and native jump
fatigue; it does not add automatic bunnyhopping or pretend a denied jump passed.
