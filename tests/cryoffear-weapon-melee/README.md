# CoF multiplayer pistol WeaponMelee differential

Run from the project root through Git Bash with Python Unicorn and the matched x86 clang-cl environment:

    python tests/cryoffear-weapon-melee/run.py --sample <private-original-hl.dll> --compiler <clang-cl.exe> --environment <compiler-environment.json> --output build/<fresh-directory>

The original private x86 server module must have SHA-256 0036b91c01e92ed205513f52563053a55a66a32d257efb5f476b8f1f3dde0e63. Keep original binaries, assets, IDA/decompiler material, build receipts and machine-specific environment JSON out of source publication. Output and temporary compiler files stay inside a fresh workspace build directory; output paths traversing links/junctions are rejected.

The oracle executes original 0x100F9790, sound/breath/recoil, hull-correction, trace, fixed-point shake and multi-damage instructions. Engine and virtual entity callbacks provide controlled boundaries. The C++ executable compiles the production adapter and actual ReGameDLL CBasePlayer/engine types. Generated unreached virtual definitions come from actual SDK declarations and abort on any call; they are not replacement gameplay methods. The fixture uses a presence-only active-item marker which is never dereferenced, so this does not establish real weapon ownership or scheduling.

The 512 cases compare exact callback order and float/packet fields across line hit/miss, hull3, BSP center/corner correction, all six breath choices, zero and positive damage, both classification orders, explicit quiet-audio state, recipients grounded/free/missing, strict radius2 and NaN/infinite recipient coordinates. Separate checks cover 23 cancellation positions/occurrences, packet completion, serial/private-data removal/replacement, sound precache failure, preflight rejection and a genuine recursive melee preserving pending outer multi-damage. Empty/truncated/wrong/trailing result gates must fail. Compile precise floating point with contraction disabled (-ffp-contract=off), preserving original scalar operation order. The actual compiler discovers the transitive include closure; source/dependency/compiler identities are recorded before and after.

Call CheckPistolWeaponMelee before initiating presentation/scheduling. The parent must supply the active-pistol owner/life/map/weapon generation guard and original recoil backend (viewpunch.sc consumer), a valid shake message ID, and all eight cold-prepared immutable sample paths. Pass the same table to PrecachePistolMeleeSounds and PistolMeleeEffects; absent or empty entries reject before any side effect. There is no automatic original-path fallback. No missing backend becomes a no-op. This adapter executes the already scheduled multiplayer callback; the parent owns the original .3-second delay and cancellation lifecycle. Explicit quietAudio snapshots original 10226489 instead of reproducing its last-player global coupling. Singleplayer and weaponID10 are unsupported.

The namespaced host table is checked against the real resource manifest. Twelve hit cases cover every voice and quiet-volume branch through actual engine sound callbacks that reject original paths; all sixteen missing/empty entries reject before precache, RNG, audio or damage. These path changes are host resource placement, not changes to the original channel, pitch, volume, RNG, hit, or shake order. The 512 original-function cases continue using explicitly prepared original paths.

This verifies original instructions against actual SDK types at controlled edges. Full scenario TraceAttack/TakeDamage consumers, real recoil/shake rendering and sounds, full DLL build/link, deployment, multiplayer/gameplay and live CPU/frame-time performance remain unverified. The production path has bounded stack work, up to one hull and nine BSP correction traces, at most 32 shake recipients, and no allocation, I/O, mutable cache or new thread. No performance improvement is claimed without real sampling.
