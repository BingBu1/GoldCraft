# 大灾变免费自动复活专项

本专项验证 `native/csol/scenario/automatic_respawn.hpp` 及其真实 SDK 使用边界。原版证据见 [晚加入报告](../../docs/2026-11-01_分析-灾变晚加入自动复活-report.md)。独立计时 209 项和实际规则方法的受控 SDK 253 项均已通过；完整 GameDLL 构建和单 B 实机仍由主任务验收，不重复既有消耗品服务 226 项检查。

`prepare.py` 冻结计时器测试；`prepare_sdk.py` 冻结完整生产源并提取 10 个未改动的方法／结构，`sdk.cpp` 提供可控实体、回调及原生生成边界。测试中的 `FPlayerCanRespawn` 确实调用实际 `CanRespawn`，不会恒定放行。每次使用新的 `build` 输出目录，以保留前次版本。`audit.py` 核对冻结哈希、真实 Ninja 包含依赖、x86 产物和编译选项。

最终证据为 `build/csol-scenario-automatic-respawn-20261101/helper-01/audit.json` 和 `sdk-03/audit.json`：分别 5／12 个冻结输入、224／250 个实际包含记录；最终 SDK 源零漂移。helper 的唯一后续源差异是 CMake 新增 SDK 可选目标，实际计时器和测试源码保持相同。编译采用 x86 Clang、C++20、O3、ThinLTO、AVX2 和 precise。SDK01 的 200 项、SDK02 的 223 项保留为中间版本，不能与最终 253 项累加计算覆盖。

## 实际 SDK 接线验收

冻结并编译父任务的实际调用方法，不把模拟 `CanRespawn=true` 当作接线通过。覆盖下面的调用次序和失效点：

1. 自定义角色菜单和原生 joinclass 的合法选择均保存选择时刻。拒绝选择、取消、重复命令不延长时钟。
2. GETINTOGAME 完成前不生成；JOINED 后进入 DEAD_RESPAWNABLE 观察仍经过自动规则。`Observer_Think` 的 return 不能跳过该规则。
3. 正常死亡完整跑到 PlayerDeathThink 的 DEAD_DYING→DEAD_DEAD 后再起表，保留原尸体／死亡动画。
4. 到期调用实际 Spawn／RoundRespawn；在进入、选出生点、插件回调、最终提交各处替换 EHANDLE／userid／连接／地图／回合，旧许可全部拒绝。
5. 许可未授予时原 `FPlayerCanRespawn` 保持拒绝；授予仅被精确玩家同步消费一次，异常与失败后撤销。
6. 最后一个存活 CT 死亡与候选者到期处于同帧时，重新确认实际 aliveCt；不使用上一帧缓存挽救已经团灭的阶段。
7. 阶段失败、续关等待、恢复、换回合分别只执行其自身生命周期，不由自动复活 BeginRound／重载 TRG。
8. 首次观察者的连接生命标识有效；成功 Spawn 更新实际角色／武器／HUD和生命标识，后续帧不得沿用旧许可。

本轮受控结果还包含：旧缓存 aliveCT=1、实际为0；CanRespawn 插件回调中最后队友死亡；临时插件否决后下一帧再许可；插件重入 Spawn；五类 SDK 回调处地图／回合／实体序号／新生命／会话／访问权限失效；选角 Count／GETUSERID 回调的12种状态变化。成功自动生成返回 false，结束旧观察帧；下一活帧恢复正常处理。实际完整 Spawn 的装备、HUD和物理出生点，以及用户画面，仍不由本夹具证明。

## 单 B 与32槽实机计划

只启动一个图形 B，使用穷途末路。先保持一名受控存活 CT，让 B 在战斗中进入并选角，记录选择、JOINED、首个提示和 Spawn 的实际时间。再分别验证正常死亡、队友在到期前死亡、续关后恢复、断线重连、换图与返回。需保留服务端时间与生命周期记录，以及 B 的观察／倒计时／生成画面，不能只看日志中的调用次数。

32 槽第一层使用实际 SDK枚举的受控玩家状态，覆盖所有槽位、不同加入时刻、slot32、断开后替换实体和一次团灭。它只证明32槽服务端生命周期；32真人并发网络和真实物理出生仍需单独实机证据。
