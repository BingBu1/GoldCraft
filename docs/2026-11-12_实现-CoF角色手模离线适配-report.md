# CoF 角色手模离线适配

用户要求CoF武器也覆盖CSOL人物手模。本轮完成显式几何作者工具及实际适配器检查，已产出Glock男女手候选；**尚未部署或完成手掌/枪把的实际画面验收**。原CoF武器、其余25项范围和完整Goal继续。

## 修改前依据与适配范围

原Glock视模SHA-256为 `80cc917866e61fbb23337f6a990dc72f42277f2bd3d5a1d77201d1d57a406ffe`，实际CSOL双性别供体为 `7bc4a343f5e165ca1507bb8efa562bf13dd1f8979a0c8c61d0bded31d4ce2f03`。修改前完整骨名/父骨/变换/网格消费者及身份保存在私有 `analysis/cof-weapons-20261111/model-evidence/hands-20261112/before.json`。

E-1：运行日志 `hand skeleton does not match` 与生产 `AdaptViewmodelHands` 对照。CoF使用r_/l_骨，CSOL模板使用Bone*骨；掌长、指节轴和单位也不同。仅替换贴图或删除现有骨架校验不足以得到正确手模。

E-2：实际供体hands组有618/1026顶点的男女手，原Glock为49骨、43序列。原视模只有独立手部材质fingers/glove/sleeve可删除，枪身、弹匣及战术灯分别保留。当前 `ViewHandAsset` 只在真实角色/供体注册/资源可读时启用，角色失效回退原武器。

E-3：既有 `docs/CSOL_HAND_ADAPTER.md` 和匹配原CoF视模消费者证据继续适用。这里是用户明确要求的宿主几何适配，并非声称原CoF本来会换CSOL手部；没有改其已证机瞄、动画时序、声音或角色玩法。严格保留[IDA优先规范](CSOL_IDA_POLICY.md)。

## 作者工具

F-1（host adaptation，E-1/E-2）：`tools/Prepare-CryOfFearHands.py` 要求匹配目标/供体完整SHA及每个加权骨的显式局部变换。仅接受有限、保向的刚体旋转及均匀几何缩放，拒绝缺映射、重复映射、剪切、镜像和非均匀缩放。其输出是专用供体资源：采用目标骨架/原动画块，追加CSOL男女手网格、法线、UV及完整像素；顶点按标定变换，法线仅受旋转。原枪身和完整目标payload没有覆盖修改，输出只写新build资源目录。

P-1（callflow，E-1/E-2→F-1）：显式标定与SHA → 离线供体作者 → 原生产AdaptViewmodelHands删除原手网格并导入男女手 → 角色男女选择/手部材质 → 继续原CoF骨动画。转换和上传保持现有冷缓存生命周期，没有把作者计算放进游戏帧内。

初版按掌根和四指根校准，离线对照发现推搡时手指不应张开，因此保留第一候选并撤出交付。第二候选按每个指节实际子骨方向/长度和掌面法向重新标定，保留原指节中心；这是待验收的作者数据，不作为运行时自动猜测规则。私有calibrate脚本、输入SHA和两轮对照图保留，未发布游戏模型。

## 剩余工作

当前引擎通用依赖扫描仅将供体加入generic下载，客户端还要求该供体存在真实模型预缓存索引。需要接通同一权威地图的供体预缓存、旁置profile下载及资源准备，检查供体中复制的动画事件不会引入未映射声音依赖。候选握把/指节/袖口继续校准，再按男女角色、待机/开火/机瞄/换弹/推搡、角色/地图/视角变化实测，并做真实性能采样。保持安全检查，不能用强制模型索引或去掉资源门填补。

此阶段没有编辑CoF gameplay还原逻辑；发布作者工具和验证源码不等于人物手模交付，也不关闭Glock整枪或完整Goal。
