本阶段把原 CSOL 的 Shift 输入消费者接入实际 CSOLSupport 构建与生命周期。它由明确的服务端生命授权激活；当前服务端尚未发布授权，完整疾跑能力继续关闭。本阶段新 DLL 未部署，正在进行的致命陷阱测试保持原版本。

模式身份已由 MP 工厂 `11433E55`、模式33分支 `11435173`、构造 `1080D280` 与虚表 `117CFFE4` 闭合；原 x86 客户端 `02A55017/02A55031` 对应模式 `21h` 并安装键 `1000h` 的处理器。

- 原发送器 `02A59180..02A591C5` 共25指令：相同整数状态返回false；先保存新状态，再在1/0时发送 `sprintON/sprintOFF` 并返回true，忽略命令回调返回值。其他整数只保存状态并返回false。
- 原按下 `02A98010`／释放 `02A98060` 经分派器 `02A98940`；处理器返回true才跳过原生回调，false继续原生 `+speed/-speed`。因此不能使用 CoF 的双实体按键模型或始终吞键。
- 原客户端 `Initialize` 在 `02A2D703` 复制引擎表至 `03AE8DA8`；实际 hw 表 `382FEBC0+54` 指向 `3782F6C0`。这个函数经 `3785F250` 追加命令和换行至客户端命令缓冲。宿主适配使用具名 `engine.pfnClientCmd`，不使用 `pfnServerCmd` 或套用 CSO 扩展表偏移。
- 原规则更新进一步追到多玩家 Think →模式虚函数+44→`1143DE00`→模式+70→`1080E080`→`10858EC0`→各玩家 `10859030`。最后包装器先调用实际空函数 `10611B70` 再尾跳，不能因IDA共用的导出别名误认成删除力场。构造前缀只用于确认虚表；不宣称整段构造均已分析。真实宿主 PM 顺序仍需接线验证。

修改前合同为私有 `analysis/csol-standalone-stamina-20261115/INPUT-PREEDIT.md`；原输入、引擎命令与帧链分别保存在 `client32-input-ida.json`、`client-command-route-ida.json`、`frame-chain-ida.json`。错误的服务器引擎表候选已明确排除。

## 源码与宿主适配

- `native/csol/scenario/custom/standalone_input.hpp`：原整数状态机，以及固定14字节的版本／生命／修订号／启用授权；拒绝非法、重复、旧生命和已退役生命重新启用。
- `native/csol/client/scenario/core/standalone_movement_input.cpp/.hpp`：实际 SDK 命令和消息链、InitHUD／会话／关闭清理、诊断；加入现有 CMake、插件和 session 生命周期。
- 授权缺失、关闭、线程不符或缺命令 API 时保留原生输入。状态更新在外部回调前完成，重入和回调中退役不能回写旧状态。
- 命令额外携带生命编号是 GoldCraft 权威适配；后续服务端必须检查该编号，不能将其当原 CSOL 协议。状态转换只使用64字节栈缓冲，不读盘、不分配，也不逐次查找命令。未修改绑定、移动轴、CVAR或用户存档。
