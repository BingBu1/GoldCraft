# 中文 NAR 解包器兼容 nar-tools 重打包格式

原中文程序仍通过“打开”和“全部提取”读写资源。修复集中在配套的 .NET Framework 2.0 程序集 `CSOToolLib.dll`。源码基线为 GPL-3.0 的 CSOTools 修订 `44906e33eaf2c0c28f6d99b2bf345c3a8abc1d90`。 [上游源码](https://github.com/dptetc/CSOTools/tree/44906e33eaf2c0c28f6d99b2bf345c3a8abc1d90) · [兼容补丁](../patches/csotools-nar-compat.patch)

## 格式和导出行为

两种格式都以 `4E 41 52 00` 开头。下表按磁盘字节顺序列出版本和文件末尾标记，读取器核对两者的组合。

| 归档 | 偏移 4 处的四字节版本 | 文件最后四字节 |
| --- | --- | --- |
| 原版 | `00 00 00 01` | `4E 41 52 00` |
| 本次 nar-tools 重打包 | `BD D5 30 4F` | `00 00 00 00` |

四个重打包的目录索引和资源编码仍采用原有算法。每个包的 `/LICENSE` 与 `//LICENSE` 共享相同偏移、存储长度、展开长度和 CRC，但后者误标为压缩。读取器在确认这组标记、路径、存储类型和数据引用后只列出一份许可证。两条记录指向不同内容时，额外的前导斜杠编码为 `%2F`，两份均可提取。

目录名按 CP949 显示，文件密钥直接使用原始路径字节。原中文程序用显示路径创建 Windows 文件，重打包文件名中的半角问号以 `%3F` 保存，字面百分号以 `%25` 保存。关闭、重开与加载失败后的文件句柄均按来源释放。旧解压流在最后一次回引用跨过 8 KiB 输出边界时会丢掉末尾字节，新版先排完待输出内容，并核对总长度。

## 构建和回归

把补丁应用到上述上游修订。在 Git Bash 中把 `tool_dir` 设为中文解包器目录的绝对路径，并从上游仓库根目录运行以下命令。构建只需要 .NET Framework 2.0 C# 编译器和工具自带的 SharpZipLib。

```bash
mkdir -p nar-release
(
    cd CSOToolLib
    MSYS2_ARG_CONV_EXCL='*' "$WINDIR/Microsoft.NET/Framework/v2.0.50727/csc.exe" \
        /nologo /target:library /platform:anycpu /optimize+ \
        "/out:$(cygpath -aw ../nar-release/CSOToolLib.dll)" \
        "/reference:$(cygpath -aw "$tool_dir/ICSharpCode.SharpZipLib.dll")" \
        *.cs "$(cygpath -aw Properties/AssemblyInfo.cs)"
)
```

关闭解包器后，备份原 `CSOToolLib.dll`，把构建出的同名 DLL 放到 `Extractor_zh-CN.exe` 所在目录。从 GoldCraft 根目录运行 `python tests/csotools-nar/run.py "$tool_dir"` 即可复测两种格式、路径、许可证别名、跨缓冲区回引用、截断和失败后重开。测试使用生成的短样本。 [回归测试](../tests/csotools-nar/run.py)

## 实际验证

通过已安装的中文 EXE 启动四次，分别读回含相应归档路径的中文窗口标题。随后调用该 EXE 的实际目录树、“全部验证”和导出实现，以关闭自动解密模型的选项写出原始资源。独立解码器逐文件比对落盘字节并复核 CRC，四份源包的 SHA-256 与测试前相同。

| 归档 | 原始目录项 | 导出文件 | 逐字节相符的字节数 |
| --- | ---: | ---: | ---: |
| cstrike.nar | 9,923 | 9,922 | 2,391,993,087 |
| cstrike_chn.nar | 1,551 | 1,550 | 258,994,783 |
| dstrike.nar | 4,979 | 4,978 | 1,651,242,261 |
| valve.nar | 1,063 | 1,062 | 57,885,172 |
| 合计 | 17,516 | 17,512 | 4,360,115,303 |

韩文 `#256256m1887[샷건]_p.bmp` 的 BMP 头与 66,614 字节内容均已核对。两个含原始半角问号的 WAD 在包内长度即为零，按目录声明导出为空文件。另以官方 `valve.nar` 对照，新旧库各导出的 1,243 个文件逐字节相同，其中 925 项使用压缩存储。共享模型接口在版本 9、10、20、21 的各一份实际模型上返回相同状态和输出哈希。
