# 模型加载的纹理调试标签

已从真实游戏调用栈确认纹理调试命名进入模型加载热点，现将其改为按需开启。默认上传纹理时不格式化标签、不调用驱动命名接口；纹理内容、上传、mipmap、模型验证和绘制保持。真实 GL 行为检查通过，完整 Renderer 构建与本地部署结果在本报告后续检查点记录；不把独立 GL 结果当作整图换图提速。

## 原因与证据

这是 Renderer 的宿主诊断开销优化，不是 CSOL 玩法还原，不更改大灾变 AI。修改前范围、模块身份和采样文件 SHA 保存在 `analysis/texture-label-stall-20261116/PREEDIT.json`。

F-001，`status=validated`、`severity=n/a_re`、`confidence=high`，依据 E-001／E-002／E-004：正常纹理加载中存在可避免的诊断字符串和驱动调用。默认关闭标签只移除调试元数据，不跳过模型／资源校验或降低视觉效果。E-001 是历史真实游戏采样，不能据它推算当前 DLL 节省的秒数。

## 修改及验证方法

实际源码在 `external/MetaHookSv-20261007/Plugins/Renderer/src/gl_rmisc.cpp`、`gl_rmain.cpp`、`gl_local.h`。`r_debug_texture_names` 是客户端归档 CVAR，默认 0；设 1 后为后续纹理上传保留原诊断名称。该值直接在调用时读取，不需要换图；不会为已有纹理补跑上传或命名。

改动以 `patches/renderer-goldcraft.patch` 发布，保留上游代码与许可。补丁只更新本次三段，其他 owner 的改动保持。原补丁与原位导出存在的无关空白和文件排序差异在修改前已记录，没有借导出夹带。

`tests/renderer-texture-labels/run.py` 读取实际生产函数，生成小型测试适配器，用实际 HLSDK CVAR 类型、C++20／AVX2／精确浮点构建。窗口保持不可见，不向游戏或桌面发送输入。基线与新实现分别保存回执。

```bash
python -X utf8 -B tests/renderer-texture-labels/run.py \
  --compiler "$GC_CLANG_DIR/clang-cl.exe" \
  --environment "$GC_COMPILER_ENV" \
  --output build/renderer-texture-labels-review
```

环境变量引用项目既有固定编译器目录和 SDK 环境 JSON；完整命令和输入身份保存在回执。基线另加 `--original-labels` 并使用新的输出目录。

独立 GL 负载每组 192 张 256×256 纹理，上传与 mipmap 相同，交替三轮并分别记录排队与完成时间。当前驱动上两组范围重叠，没有据此宣称稳定的游戏加速比例。游戏换图仍有完整 VFS、模型解码、纹理上传与原生加载工作；172 个玩家模型的延迟登记已在最近运行记录中生效，不把该优化重复宣称为本次新成果。

## 构建、部署与剩余边界

首轮完整编译在工具内核退出时中断，之后实际进程快照确认没有原编译／链接进程，且没有完成回执；保留 `build/renderer-texture-labels-full-20261116-01/interrupted.json`。后续复用原编译缓存，记录新的输入和输出，未覆盖旧失败记录。

第二次完整构建成功，但部署前独立解析 Ninja 实际依赖时，发现沿用旧清单漏记了 43 个实际头文件／数据文件；没有改标为完整通过或更新 B。拒绝记录在 `analysis/texture-label-stall-20261116/actual-closure-rejected.json`。随后将实际 340 项编译输入纳入封存，逐个删除并重编引用这些漏项的 164 个既有编译对象。删除仅限已验证位于本构建缓存、非共享链接、无重解析点的 `.obj`，没有复制或改写源树。

真实换图前后对照、跨不同地图、加载窗口响应、公网和多人仍需实测。此项不关闭整体换图故障、不表示全部自定义玩法或完整大灾变目标已经完成。
