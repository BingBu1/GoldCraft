# 每玩家、每怪物的伤害返金上限

这是用户指定的自定义规则：每名玩家对每只灾变怪物累计获得的伤害返金受限，致死击杀奖金继续沿用原规则。配置仍只有 `addons/goldcraft/config/gameplay.json`，`damage_refund_cap` 分区含开关和 `damage_refund_max_per_monster`；默认关闭、上限默认1000、允许0..32000，两个字段在下次地图会话生效。同图重玩不重新读取该策略。

## 账户和身份

Session 持有45×33固定账本；新怪物租约才产生新的怪物额度，替换命中奖励对象不会清账。玩家使用真实登记对象映射到地图内单调编号；弱引用避免保留 Session 环。死亡、重生、换角色不重置登记编号；登记器重建后即使自身从1重新编号，也不会碰撞旧账本。

只有普通怪物命中奖励的最后一次 `AddAccount` 带专用同步标签。真实 wrapper 在 ReAPI prehook 之前认领一次；原账户函数在 prehook 后裁最终正金额，保留原生账户上限，再在第一条 Money 回调之前提交实际正向到账。取消和被拒绝的重定向不占额度，重复调用 original 不能重复发放。嵌套普通 `AddAccount` 屏蔽外层标签；独立击杀奖、墙体奖励、初始钱和其它普通 RT_NONE 钱款不受此上限影响。满额仍执行原 RNG、XP和零金额观察；负金额不返还额度。

配置仅在 Precache 冷路径读取；命中时 O(1) 索引，无文件/网络访问、无临时堆分配。新增一份固定账本和33项弱登记缓存，账户标签在同步栈中持有。此成本说明不等于实际帧时或多人性能通过。
