# 原生 CS 水中移动参数

2026-10-18：海豚恩惠的水平阻力、垂直阻力和水中属性加速已拆分，并接入原生服务端及匹配客户端预测。生产 Core、GoldCraft 和 mp 构建通过，373 项 JUnit、两组真实 NeoForge 对照和真实双服水体检查通过。此轮候选未部署，完整水中玩法及真人预测仍待验收。

## 原因与行为

旧移动模块通过临时放大 CS 的摩擦、加速和速度上限模拟海豚恩惠，垂直方向也受到同样影响。固定 Minecraft 1.21.1 / NeoForge 21.1.256 的实际 `LivingEntity.travel` 使用水平阻力 0.96，但垂直仍为 0.8；水中效率在离地时减半，再与移动速度、NeoForge 游泳速度属性及重力共同计算。疾泳玩家还会在移动前按视线调整垂直速度。

新 `NativeWater` 从唯一服务端效果所有者读取这些真实参数。代理实体自身的 no-gravity 是实现细节，不应使原生玩家丢失重力，因此代理改读实际重力属性。没有相关效果或属性变化时继续原生 CS 水中移动；MC 控制形态保持 MC 自己的物理。

两端共用 `native_water.hpp`。移动前按输入方向和参数加速，仍调用匹配引擎的原始 `PM_WaterMove` 完成 hull、台阶和滑动碰撞，再施加水平/垂直阻力和流体重力。计算按命令时长换算 20Hz 速度规律，保留原生最大速度限制与传送带 basevelocity，不向本地玩家直接写坐标。原生水中跳跃和出水路径目前保留原生实现。

## 协议与生命周期

协议版本仍为 30，新增可选能力 `67108864` 和消息 `102`。固定 56 字节：world/revision 两个 uint64，slot/serial/spawn/life/flags 五个 uint32，drag/speed/efficiency/swim/gravity 五个 float32。独立能力协商与既有降级链兼容，图形连接不能宣称服务端能力。

ReHLDS 检查认证连接代次、世界、身份、出生、生命、存活、单调序号及数值范围。状态租约为 350ms，死亡、MC 形态、受控移动、旧连接及过期状态不参与原生移动。`GCWater` 只可靠发送给声明 `_gc_water=1` 的真实客户端；客户端继续核对本人世界/身份/生命并应用相同租约。预测钩子必须通过既有精确客户端符号匹配才能声明能力。

## 已验证与剩余边界

- 365 个冻结 Java 输入构建通过，373 项 JUnit 无失败或跳过。最终原生构建使用指定 Clang/C++20、O3/ThinLTO/AVX2 和精确浮点选项。
- 实际抽取的 `PM_WaterMove` 有 95 项检查，包含旧版垂直阻力负对照、斜向输入、不同命令时长、天花板、传送带、极小合法 Mod 阻力及普通/死亡/观战/岩浆回退。实际服务端派发器另有 36 项身份、租约、消息投递和重入检查。
- `Test-NativeWater.py` 在无附加 Mod 与 Epic Fight/NightFall 环境各执行 196 项检查，实际调用原版玩家 `travel` 得到 64 组结果，其中 62 组启用本模块；这些结果直接送入编译的原生消费者逐轴比较，两组均通过（每组共 159 项原生检查）。参考场景为平视、固定方向和单个 50ms 步长，不能代替任意视角及帧率的真人验证。
- `Exercise-NativeWaterServers.py` 使用真实 ReHLDS/NeoForge、真实 MC 水体与原生 `RunPlayerMove`。八项检查验证新 DLL、代理重力、水中分轴阻力、实际位移、水中属性、普通行为恢复、效果自然到期及重生清除。50ms 样本在初速 `(100,0,100)` 下，海豚状态得到 `(108.288,0,76.8)`；效率/游泳属性样本水平速度为约 `118.9864`。假玩家及效果授予是测试驱动，中继不生成或改写物理状态包。
- 同一最终 Core/mp 的真实双服爆炸击退九项、受伤回调十四项回归通过，后者同时确认 AMXX 1.10 与 Floating Damage 单次加载。所有测试服务均停止并恢复；已有 AMXX 升级及本地整合批次保留。

证据在 `build/native-water-20261018`：最终原版对照 `candidate04`/`full02`，双服 `servers03`。保留早期失败记录：错误的测试属性预期已按原版纠正；扩展疾泳对照发现缺少视线预处理，已修复并重新构建两端，最终 62 组均通过。

37 项 `combined-native-water-20261018` 候选继承上一轮爆炸击退与已部署 AMXX 1.10/飘字，仅更新 Core、GoldCraft 和 mp 三项。749 个原生输入与构建前冻结一致，完整候选逐项哈希验证；未部署，图形客户端没有自动启动。

完整原版跳跃浮力、攀爬/出水跨沿、流体流向、自定义流体和 no-drag 语义尚未实现为通用原生适配。原生当前行为在这些路径继续保留，不能称为完整 vanilla travel。客户端真实预测、浅深水/不同视角、低帧率、梯子/门、换图重连及多人仍需与爆炸击退一起实测。此项不关闭全部 39 种状态效果或完整项目目标。
