# 单文件分组玩法配置

所有服务器玩法设置继续写入同一个 `addons/goldcraft/config/gameplay.json`。用户担心项目太多难编辑，因此 v2 将每个功能的开关、数值和中文说明放在同一功能区；没有拆成多个配置文件。

可直接查看 [完整示例](../native/csol/config/gameplay.example.json)。例如时间区是：

```json
"time_cycle": {
  "enabled": false,
  "comment": "正午与黄昏按秒推进，之后保持永夜；BGM资源由服务端另验。",
  "values": {
    "midday_seconds": { "value": 180, "comment": "正午持续秒数；之后进入黄昏。" },
    "dusk_seconds": { "value": 120, "comment": "黄昏持续秒数；之后永久保持夜间。" }
  }
}
```

这段位于根 `features` 中，根 `version` 为2。关闭功能保留原数值；未确定的可选值用 `null` 显式保留说明，不伪造数值。注释既支持 JSON 解析时的行/块注释，也以 `comment` 字段持久保存，管理员菜单修改同样写回这个文件。

`settings.hpp/.cpp` 的快照、描述目录、默认值和编辑接口保持不变。解析器继续接受 v1；下次保存或离线生成采用分组 v2。跨功能错放参数、重复/未知字段和非有限值仍拒绝，启用缺少必需参数的功能仍报告具体问题，不把格式更新当作消费者已实现。

实际验证：`build/csol-custom-settings-grouped-20261113-01/receipt.json` 的773项检查通过（保留原504项并新增269项），输入前后稳定；生成单文件9643字节，SHA-256 `540c12d2813ec70b0eaea1e35db970cd883c823651fef11eefb29d1bb7ebd0ef`。真实存储使用新分组格式重新编译运行，`build/settings-store-grouped-20261113-08/receipt.json` 成功，62项Windows文件保存/重读/失败保护检查通过。离线生成器已接受 v1/v2，实际生成与示例逐字节相同，重复输出拒绝覆盖。

这批是格式与持久层验收；完整客户端/专服部署、所有玩法消费者和管理员真实权限/重启操作仍分别验证。示例里尚未上线的功能默认关闭，不据开关存在宣称昼夜、盲盒或熟练度已经生效。
