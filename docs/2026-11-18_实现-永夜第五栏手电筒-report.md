# 永夜第 5 栏手电筒

永夜按 `5` 把手电筒拿在手上并开灯。拿着手电时按 `F` 开关。选回枪械或使用上件武器键时，手电收起，灯光保持当前状态。主武器保留原有栏位和弹药。手电复用玩家实体和装备状态。

永夜阶段 HUD 显示 `[5] 手电筒`，拿出后改为 `[F] 开关`。第一人称和队友视角使用 GoldCraft 自制的 Studio 模型。服务端在开图时准备两份模型并加入下载清单，客户端收到本轮永夜状态后确认两个模型索引。缺件时地图仍可进入永夜，第 5 栏沿用原有按键处理。

## 按键和生命周期

- AMXX 文字菜单优先接收数字键。永夜持握期间重复按 `5` 不会再次发命令或消耗治疗道具。`6` 仍可使用大治疗，永夜外 `5` 返回原有治疗逻辑。
- 开灯使用宿主的光束、电池与 HUD。手持时 `F` 控制灯光，收起后 `F` 恢复灾变踢击。枪械在灯亮时仍显示手电电量。关闭时间机制或离开永夜时熄灯，手持手电的玩家切回先前武器。死亡、断线与换图清掉手电状态。
- `weapon_inventory.cpp` 处理数字键和待确认的武器选择，`night_player_lights.cpp` 接收地图阶段与模型状态，`challenge_environment.cpp` 管理服务端持握和清理，宿主入口通过 `patches/regamedll-goldcraft.patch` 发布。

## 模型与资源

永夜限定、直接拿出、宿主电池和库存处理由 GoldCraft 的规则负责。`tools/Generate-NightFlashlight.py` 使用项目自制几何与纹理生成双视角模型。运行制品目录内的 `resource-plan.json` 记录模型路径与哈希。

## 切回武器后继续照明

旧版切回枪械后，服务端在玩家帧中同时清除手电模型和灯光。现在切枪只更换手持模型，原生光束继续随玩家移动，电池和灯光状态由服务端更新。手持手电期间按 F 开关灯。切回枪械后，按 5 可以再次拿出手电。

- 实际 GameDLL 回归在旧版复现切枪熄灯、重复发灯光消息等五处失败。新版五组共 7,835 项通过，覆盖按 5、切回同一把 AK47 后射击、上件武器键、重新拿出手电、结束永夜、重玩及死亡清理。服务端使用现有玩家槽位保存当局所有权。
- 完整 x86 服务端构建通过，SHA-256 为 c10382825d64540dfd4dbcc4de04e5dc043a8dd76055913a5c4aa10c9630f194。客户端沿用首次接入时验证的构建。
- 穷途末路隔离专服核验了 257 项 HUD 资源和 3,079 个清单路径，两份手电模型的实际 HTTP 响应与服务器文件一致。第一次清单查询在 RCON 收包时截断，加大隔离测试的 UDP 接收缓冲后取得完整清单。测试文件已恢复。
- 沙盒 B 的配套部署、第一人称照墙和队友视角仍待联机验收。构建和回归记录位于 build 中的 night-flashlight-switch 目录。

## 11 月 19 日穷途末路单 B 实测

常用本地专服和 B 已装有手电逻辑，服务器缺少两份自制模型。补入第一人称模型（17,632 字节）和队友模型（14,032 字节）后，两者都出现在地图预缓存表里。模型生成器现在直接输出包含两个模型的 `resource-plan.json`。使用同一 StudioMDL 重新生成的文件与服务器实际 HTTP 响应逐字节核同。

- 隔离服首轮启动超时，第二轮的通用资源清单只收到前 1,011 条。第三轮取得完整清单并核对 3,079 个文件、257 项 HUD 和两个模型的实际 HTTP 内容，随后恢复了隔离服。当前 GameDLL 的五组 SDK 回归共 7,835 项通过。
- 常用专服通过 322 项 HUD 预检，客户端和服务端的购买菜单配套检查覆盖 115 项。唯一的 B 在 `zs_deadend` 实际收到 v4 清单，校验 3,481/3,481 项，下载 2 项。客户端内容缓存里的两个模型与服务器 SHA-256 一致。客户端实际加载 `96f1d843`，服务端实际加载 `7d3544fe`。B 安装目录的旧 PDB 与 DLL 不匹配，读取客户端状态时使用与内存 CodeView 匹配的构建 PDB。
- B 出生后显示 K3 和 150/200 发。永夜画面可见第一人称手电、地面光斑和 `[F] 开关`。专服读到 K3 处于活动状态时玩家灯已点亮，随后玩家切换到手电的 V/P 模型，持握期间照明标志有开关变化。截图和状态采样没有覆盖一次可归因于指定按键的完整切回开火，也未取得同机位照墙和第二人视角。
- 实体 Esc 停止了界面操作。测试时临时缩短过阶段时长，结束时已从控制台核实正午恢复为 180 秒、黄昏恢复为 120 秒。受保护安装的基线核对通过。
