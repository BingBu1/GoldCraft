# 永夜第 5 栏手电筒

永夜开始后，存活玩家按 `5` 收起当前武器，把手电筒拿在手上并开灯。`F` 切换灯光，选择另一把武器或按 `lastinv` 收起手电。进入永夜即开放手电。拿出手电保留原有枪械、弹药和资金，无需占用武器 ID、服务端库存栏或额外实体。

永夜阶段 HUD 显示 `[5] 手电筒`，拿出后改为 `[F] 开关`。第一人称和队友视角使用 GoldCraft 自制的 Studio 模型。服务端在开图时准备两份模型并加入下载清单，客户端收到本轮永夜状态后确认两个模型索引。缺件时地图仍可进入永夜，第 5 栏沿用原有按键处理。

## 按键和生命周期

- AMXX 文字菜单优先接收数字键。永夜持握期间重复按 `5` 不会再次发命令或消耗治疗道具。`6` 仍可使用大治疗，永夜外 `5` 返回原有治疗逻辑。
- 开灯使用宿主的光束、电池与 HUD。手持时 `F` 控制灯光，收起后 `F` 恢复灾变踢击。切回武器时，服务端发送原生关灯状态。关闭时间机制或结束永夜时恢复先前武器。死亡、断线与换图清掉手电状态。
- `weapon_inventory.cpp` 处理数字键和待确认的武器选择，`night_player_lights.cpp` 接收地图阶段与模型状态，`challenge_environment.cpp` 管理服务端持握和清理，宿主入口通过 `patches/regamedll-goldcraft.patch` 发布。

## 模型与资源

永夜限定、直接拿出、宿主电池和库存处理由 GoldCraft 的规则负责。`tools/Generate-NightFlashlight.py` 使用项目自制几何与纹理生成双视角模型。运行制品目录内的 `resource-plan.json` 记录模型路径与哈希。

源码回归覆盖实际 `slot5` 命令和 AMXX 菜单路由，服务端夹具使用真实 GameDLL 的生命周期和武器方法。游戏画面验收关注穷途末路永夜的第一人称模型、同队玩家视角、墙面照明与切回武器。

- 完整 x86 构建通过。客户端 `CSOLSupport.dll` 的 SHA-256 为 `98543d886478ad767f51fde95a7793cfc72f65bcaa1ea394324ef23ddedce615`，服务端 `mp.dll` 为 `f86aa94f8acf89698c0fe771175681cf63517ccebde98864519df3c3e3565581`。两份回执均确认构建期间的源码输入一致。
- 客户端四组共 176 项通过，覆盖第 5 栏命令、AMXX 菜单优先级、F 键转交、夜间模型探测和阶段清理。服务端使用完整构建的 SDK 对象，三组共 4,448 项通过，覆盖取出、关灯、切回原枪、电量、死亡及缺模型。模型索引查询在首次进入永夜或资源所属会话变化时执行。
- 使用同一服务端候选冷启穷途末路。实际灾变规则生效，HUD 下载预检 257 项通过，两个手电模型通过服务器清单及实际 HTTP SHA-256 校验。验证后隔离专服文件已恢复。
