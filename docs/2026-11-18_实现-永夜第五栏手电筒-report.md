# 永夜第 5 栏手电筒

永夜按 `5` 把手电筒拿在手上并开灯。拿着手电时按 `F` 开关。选回枪械或使用上件武器键时，手电收起，灯光保持当前状态。主武器保留原有栏位和弹药。手电复用玩家实体和装备状态。

永夜阶段 HUD 显示 `[5] 手电筒`，拿出后改为 `[F] 开关`。第一人称和队友视角使用 GoldCraft 自制的 Studio 模型。服务端在开图时准备两份模型并加入下载清单，客户端收到本轮永夜状态后确认两个模型索引。缺件时地图仍可进入永夜，第 5 栏沿用原有按键处理。

## 按键和生命周期

- AMXX 文字菜单优先接收数字键。永夜持握期间重复按 `5` 不会再次发命令或消耗治疗道具。`6` 仍可使用大治疗，永夜外 `5` 返回原有治疗逻辑。
- 开灯使用宿主的光束、电池与 HUD。手持时 `F` 控制灯光，收起后 `F` 恢复灾变踢击。枪械在灯亮时仍显示手电电量。关闭时间机制或离开永夜时熄灯，手持手电的玩家切回先前武器。死亡、断线与换图清掉手电状态。
- `weapon_inventory.cpp` 处理数字键和待确认的武器选择，`night_player_lights.cpp` 接收地图阶段与模型状态，`challenge_environment.cpp` 管理服务端持握和清理，宿主入口通过 `patches/regamedll-goldcraft.patch` 发布。

## 模型与资源

永夜限定、直接拿出、宿主电池和库存处理由 GoldCraft 的规则负责。`tools/Generate-NightFlashlight.py` 使用项目自制几何与纹理生成双视角模型。运行制品目录内的 `resource-plan.json` 记录模型路径与哈希。

## 切回武器后继续照明

旧版切回枪械后，服务端在玩家帧中同时清除手电模型和灯光。现在切枪只更换手持模型，原生光束继续随玩家移动，电池和灯光状态由服务端更新。手持手电期间按 F 开关灯。切回枪械后，按 5 可以再次拿出手电。

- 实际 GameDLL 回归在旧版复现切枪熄灯、重复发灯光消息等五处失败。新版五组共 7,835 项通过，覆盖按 5、切回同一把 AK47 后射击、上件武器键、重新拿出手电、结束永夜、重玩及死亡清理。服务端使用现有玩家槽位保存当局所有权。
- 完整 x86 服务端构建通过，SHA-256 为 c10382825d64540dfd4dbcc4de04e5dc043a8dd76055913a5c4aa10c9630f194。客户端沿用首次接入时验证的构建。
- 穷途末路隔离专服核验了 257 项 HUD 资源和 3,079 个清单路径，两份手电模型的实际 HTTP 响应与服务器文件一致。第一次清单查询在 RCON 收包时截断，加大隔离测试的 UDP 接收缓冲后取得完整清单。测试文件已恢复。
- 沙盒 B 的配套部署、第一人称照墙和队友视角仍待联机验收。构建和回归记录位于 build 中的 night-flashlight-switch 目录。

## 11 月 19 日穷途末路单 B 实测

常用本地专服和 B 已装有手电逻辑，服务器缺少两份自制模型。补入第一人称模型（17,632 字节）和队友模型（14,032 字节）后，两者都出现在地图预缓存表里。模型生成器现在直接输出包含两个模型的 `resource-plan.json`。使用同一 StudioMDL 重新生成的文件与服务器实际 HTTP 响应逐字节核同。

- 隔离服首轮启动超时，第二轮的通用资源清单只收到前 1,011 条。第三轮取得完整清单并核对 3,079 个文件、257 项 HUD 和两个模型的实际 HTTP 内容，随后恢复了隔离服。当前 GameDLL 的五组 SDK 回归共 7,835 项通过。
- 常用专服通过 322 项 HUD 预检，客户端和服务端的购买菜单配套检查覆盖 115 项。唯一的 B 在 `zs_deadend` 实际收到 v4 清单，校验 3,481/3,481 项，下载 2 项。客户端内容缓存里的两个模型与服务器 SHA-256 一致。客户端实际加载 `96f1d843`，服务端实际加载 `7d3544fe`。B 安装目录的旧 PDB 与 DLL 不匹配，读取客户端状态时使用与内存 CodeView 匹配的构建 PDB。
- B 出生后显示 K3 和 150/200 发。永夜画面可见第一人称手电、地面光斑和 `[F] 开关`。专服读到 K3 处于活动状态时玩家灯已点亮，随后玩家切换到手电的 V/P 模型，持握期间照明标志有开关变化。截图和状态采样没有覆盖一次可归因于指定按键的完整切回开火，也未取得同机位照墙和第二人视角。
- 实体 Esc 停止了界面操作。测试时临时缩短过阶段时长，结束时已从控制台核实正午恢复为 180 秒、黄昏恢复为 120 秒。受保护安装的基线核对通过。

隔离回执、实机截图、玩家状态和本地部署记录位于 `build/night-flashlight-current-20261119-01`。


## 固定机位的 Renderer 聚光灯

用户实测确认基础手电可用，随后报告灯光缺少 Renderer 效果。在穷途末路复核时，服务端下发的 Gamma 混合为 1，旧 Renderer 在这个配置下一律跳过延迟照明，玩家灯因此无法进入聚光灯路径。原 CoF 的 x86 hl.dll 在 VA 0x10040190 与 0x10040110 设置及清除玩家照明位。样本 SHA-256 为 0036b91c01e92ed205513f52563053a55a66a32d257efb5f476b8f1f3dde0e63。透明特效实际使用的 CSOL hw 混合路径见 VA 0x378EDD90、0x378EE07D。

宿主 Renderer 的 G-buffer 现在在线性空间写入和计算不透明材质、光照与阴影。最终合成依据目标场景选择 Gamma 转换，之后的透明效果继续按场景设置混合。设置页允许同时打开 Gamma 混合与延迟光照。源码补丁在锁定的上游版本 872d151c9a03 上回放，五个相关文件分别核同。

- 完整 x86 Renderer 构建成功，448 个构建输入前后稳定。沙盒 B 实载 Renderer 的 SHA-256 为 90562f0471a2151c9ff873d5a55b2e8506725ef2c3036c924f02904c0f2724d8，最终合成片元着色器与 DLL 配套。入服前 322 项 HUD 预检通过。
- 单 B 在穷途末路的永夜开灯时，延迟照明、Gamma 混合及阴影均为 1。Renderer 的玩家聚光灯类型为 2，有灯锥投影纹理和阴影纹理。按 F 关灯后该光源清除。切回 K3 实际开火，弹匣从 150 降为 141，射击后聚光灯仍在。
- 采用同一服务端玩家坐标与同一客户端视角，对阳台墙面拍摄一开一关两张 1280×720 图。中央固定区域的 8 位平均灰度从 8.80 升至 43.95，左右控制区分别保持 11.69 与 10.37。首组视角不同的截图和第三张重新开灯时发生视角漂移的帧均未用于比较。实测资料在本地 build/night-equipment-20261119 下，fixed-wall.jpg 左关右开，fixed-comparison.json 记录像素范围，k3-shot.json 记录开火。该结果限于单 B；动态遮挡物投影、队友视角及帧时间仍缺同场景实测。

## 提灯和照明弹的购买、栏位与照明

用户指定持有提灯后用 5 取代手电筒，照明弹使用 4 号投掷栏。两件都列在购买菜单的装备分类。本地宿主定价为提灯 600、照明弹每支 150。原 CoF 服务端 VA 0x100501A0、0x1003DC00 给出道具身份和照明弹上限 5。0x1003DD10 点燃，0x1001AF3F 接收投出，0x1003DA40 处理地面燃尽。客户端 0x100B1148 至 0x100B1444 消费持握和着火状态，0x100602DE、0x10060470 分别处理落地照明弹和提灯。两份 x86 样本 SHA-256 见本地 analysis/cof-weapons-20261111/lighting-equipment-20261119 下的 light-consumers-preedit.json。

服务端使用库存判定能否购买和取出。提灯替换夜间栏位和原手电灯光。照明弹的数量随道具走，购买、武器箱转移和成功投出使用同一份计数。客户端从实际 Studio 骨骼取得提灯的两个灯位与照明弹的弹头位置，点燃的 P 模型通过服务端模型索引传递。原 CoF 浮点光源后端不可用时，宿主使用原生 dlight 的字节颜色接口。照明弹的六份 Aurora 脚本已随包准备，现有只接受 gunsmoke 的解析器仍须扩展才能播放全部火焰、烟和火星。

- 资源工具在实际游戏素材上生成 38 项，包含两份 P 握姿。提灯的两个附件位于引擎上传纹理后保留的数据区域。照明弹 P 保留一个附件。校验包括重新读取模型、像素和顶点。购买菜单随服务器下发的版本选择 v16 或 v17。
- 完整 x86 客户端 d05091a7 和 GameDLL 10215ef2 输入稳定。客户端第一次生成新的 Ninja 工程后链接成功，封存检查拒绝了发生变化的构建控制文件。服务端首轮也记录了源码变化，两端均已重新构建。回执位于 build/cof-equipment-live-20261119/client-02 和 server-02。
- 穷途末路隔离服通过 325 项 HUD 预检，实际广告 3295 个资源，41 次 HTTP 返回逐文件与服务端 SHA-256 相符，涵盖两件装备的全部 38 项。冷服还原成功。此轮没有玩家，扣款、点燃、投出、动态遮挡和队友视角须以实机单独验收。回执位于 build/cof-equipment-live-20261119/cold-01。

后续永夜实测覆盖了菜单扣款入包、扩大后的提灯、照明弹投掷和自然熄灭。见[照明弹实测与配套发布](2026-11-19_实现-CoF照明弹火焰伤害-report.md)。
