# 入服消息轮询热点：无 Minecraft 文本目标时跳过前台查询

普通启动的真实主线程调用栈发现，未打开 Minecraft 菜单时，GoldCraft 输入法桥接仍在每次 SDL 消息轮询中查询前台窗口。已直接修改项目源码、通过实际适配器回归并部署单个隔离 B。整体入服/换图速度尚未验收，不把局部修复称为全问题解决。

## 修改前证据

build/skill-sampling-20261108/normal-admission.json：5198 个样本、15 秒片段、debuggerAttached=false；2726 个栈包含 host_text::poll，其中1569个相同栈顶为 NtUserGetForegroundWindow → GoldCraft!host_text::poll+0x46（RVA 0x67446）。其余包含 SDL/Steam overlay/Windows 消息处理，不能把所有 inclusive poll 栈当成该查询的自身耗时。采样中存在前后台变化；不能由此预测完整入服节省比例。

native/client/plugin.cpp 注册的 Query 仅读取菜单/世界/控制台状态；native/client/host_text.cpp::target 在 world/menu 为空时必定返回空目标，但旧代码先进行 GetForegroundWindow/GetWindowThreadProcessId。修改前合同记录在 analysis/skill-voice-perf-20261108/host-text-preedit-contract.md。

这是自有宿主桥接的等价优化，不是 CSOL 玩法还原，不用资源名或截图推断原版行为。CSOL 语音修改的原版 IDA 证据仍见独立首次技能报告。

## 修改及验证

- native/client/host_text.cpp：先读取文本目标，无 world/menu 时直接返回空目标；仍执行 sync 清理旧文本会话，仍调用原 SDL 事件处理，不截断原输入。有效 MC 菜单仍执行前台/SDL 焦点校验。
- tests/native/host_text_adapter_tests.cpp：实际生产 TU 覆盖2000次无菜单轮询零前台查询、关闭旧会话、后台重开拒绝及恢复前台接收中文；保留长中文、候选、延迟文本、外窗隔离和修饰键回归。
- 完整 GoldCraft DLL 构建成功，构建输入前后哈希一致；goldcraft_text_input / goldcraft_host_text_adapter 两项 CTest 通过。回执 build/skill-sampling-20261108/host-text-build-result.json、host-text-tests.log。
- 仅原子更新 B 的 GoldCraft.dll/PDB，DLL SHA 37427b0ecdd8451ad6dae89ce2c6abb501962736c76bb31c37cca3ff0a601cdf；PDB SHA d0e1d1f9cf401b9ee59db29a96a7b1d9226bd1ace59f87b423eb7fe98e3aba20。专服未重启，正式安装未写。收据 host-text-deployed.json。
