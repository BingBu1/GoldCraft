# 入服资源校验、缓存与失败回退

本阶段完成独立下载、缓存及回退组件。它们尚未接通运行客户端的 v4 能力，不能据此声称玩家的旧资源已经能够自动更新。当前运行版继续使用原协议；整套字体、模型消费者和断线清理接通之后才部署。

这是用户要求的宿主扩展，不修改 CSOL 武器或灾变行为，也不禁用模型 CRC 校验。

## 会话事务

检查旧 VFS 时保持上一版本挂载；相同 SHA 直接复用，缺失或不一致才下载。下载成功后挂载摘要缓存，再从真实 VFS 分帧读取并复核，而不是只检查输出目录中的文件。

消费者刷新成功后，调用方才执行 Commit。此前的失败或 Reset 会恢复上一挂载；回退文件遭外部删除时明确返回失败，不伪报取消成功。已提交的挂载由调用方在安全断线边界退休，Session 析构不会偷偷撤掉仍被使用的资源。

同一个 generation 数字不作为跨服务器或跨连接的信任依据。新正文仍按长度与完整 SHA 校验。当前每帧哈希最多八块 256 KiB，并受约 3 ms 时间预算限制；网络使用两个 worker。该预算尚未经过游戏帧率测量。

## 验证层级

- 下载器：真实 WinHTTP/CNG，原 13 组 468 项加同一 Job 重复提交的 5 项通过，共 473 项。证据 `build/resource-sync-20261105/download-tests/handoff.json`。
- 完整缓存会话：真实 x86 FileSystem、GAME/PAK、HTTP 与最终 VFS，16 组 277 项通过。包括同长度旧内容、相同摘要不下载、缓存复用、坏摘要、取消、不同正文使用相同 generation、硬链接原件保全、最终 VFS 被改、提交后保持及回退失败。证据 `build/resource-update-validation-06/result.json`。
- 原生模型缓存：生产模块及匹配 x86 SDK，547 项通过；验证原停声会先释放 stream 缓存、SPR 不误用分配器、外序列/皮肤先于主头、缺消费者接口和部分失败均不继续入服。证据 `build/resource-refresh-client-20261105/model-test/result01.log`。
- Renderer 配套候选：三个实际 SDK TU 编译通过；资源 owner 29 项组件检查通过，覆盖工作项等待、排队上传不能复活旧缓冲、已被替换但仍有引用的绘制对象、分组 SPR、原生及外部纹理、错误线程/上下文/不完整依赖集合的拒绝。这不是实际 GPU 或游戏验证，仍未进入运行 DLL。
- 新符号目录：九个宿主符号，经实际 GameData 解析器 114 项检查通过；新增六段 1311 原字节核同。其构建/运行接线仍待。

首轮 Renderer 夹具缺 StudioConVar 构造/析构链接依赖，第二次整 TU 又引入无关解析器依赖；最终抽取实际构造/析构原文用于独立 owner 夹具。保留全部失败日志，不将这些链接失败当生产 Renderer 故障。实际 Renderer TU 编译另有独立记录。
