## 连续命中的权威速度衔接（2026-10-19，仅静态检查）

原增量方案中，同一宿主移动快照内的多个hurt分别从旧速度计算，再把多个差值叠加到原生速度；横向减半和垂直上限因此不能正确衔接。新增可选能力 `NATIVE_KNOCKBACK_STEPS`（1073741824）和消息106，只依赖既有近战击退能力，旧64/72字节消息保持不变。握手可降级至旧能力，未协商的图形端不能发送这一消息。

NeoForge仍只执行一次真实 `takeKnockback`。两个严格单匹配的调用包装点记录抵抗属性及事件取消/改值之后的方向、强度和最终写入；随机方向继续使用原版已算出的结果。只有实际结果符合固定1.21.1的原版计算时，才记录“横向减半＋推力／落地垂直上限”操作；Mod在其前后直接写速度的部分记录为原有增量，不重复执行Mod回调或重新读取受击时的属性。

宿主收到对应伤害确认的一次性许可后，在真实当前 `pev.velocity` 上顺序执行这一击的操作。被取消、过期或已被原生插件处理推力的命中无法领取许可，也不会给下一击留下假定速度；后续击打直接读取实际结果。每次请求按当时原生落地状态处理垂直计算，同一请求内的所有操作使用该状态；最后一次性写入速度，上推后解除落地，由引擎继续碰撞和移动。重放、世界/连接/身份/阵营/生命、快照接触和存活步行检查均复用原通道。

新载荷为64字节原冲量头（delta必须全零）、uint64伤害事件、uint32操作数，以及每步uint32种类＋三个float32参数，共 `76 + 16 × N` 字节，1–32步。参数为GoldSrc单位/秒，种类0为增量，种类1为原版变换；非有限数、未知种类、非正强度、越界数量/参数或错误长度拒绝。计算先留在局部变量，全部有效才写回。

边界：旧宿主、同一代理递归重入或超过32步的特殊攻击保留原有合并增量路径；任意Mod完全替换计算的部分也只保留观察到的增量。这些路径不声称已经获得连续速度重基准能力。固定版本普通调用的连续命中、Mixin实际加载和完整双服/多人仍待合批验证。

本批仅进行Java生产及既有握手夹具的类型检查、三原生生产单元与既有冲量夹具的Clang x86 C++20 `/Zs`，并静态核对开发/正式命名的两个调用位置；未执行夹具、FML、游戏或专服，未生成或部署新JAR/DLL。证据 `build/native-knockback-order-20261019`。按用户最新安排继续积累更新后集中测试。

## 原因与行为

固定 Minecraft 1.21.1 / NeoForge 21.1.256 的爆炸路径在曝光量、抗击退属性和 `ExplosionKnockbackEvent` 处理后，直接调用 `Entity.setVelocity`。原生玩家的 MC hitbox 只用于代理碰撞与效果，改它的速度不能驱动 CS 玩家；`takeKnockback` 也不是爆炸的入口。旧 Core 的实际蓄风对照已经算出非零向量，但没有发出原生位移消息。

`HostExplosionMixin` 在这一次原版速度写入处提取增量，保留原来的 MC 写入，再交给独立的 `NativeImpulse`。因此蓄风不造成伤害也能推动玩家，普通 MC 实体继续走原版行为。Mod 修改为零、取消爆炸、移出爆炸目标列表，以及原版爆炸抗击退属性均保留。

## 权威与兼容

新增可选能力 `33554432` 和消息 `101`，协议版本仍为 30。只允许已认证的 MC 专服向 ReHLDS 专服发送；图形客户端不具备该能力。老宿主拒绝新能力时按既有能力链降级，不更换身份凭据。

消息固定 64 字节：world/event/snapshotTick 三个 uint64；slot/serial/spawn/life 四个 uint32；权威快照身体中心和速度增量六个 float32。MC blocks/tick 转换为 GoldSrc units/second：`(x*640, -z*640, y*640)`。

MC 端核对当前世界、维度、连接、身体、出生、生命、阵营和原生形态。ReHLDS 再核对当前身份/生命、存活、非观战、原生步行、事件去重和已实际导出的身体快照：快照不超过一秒，提交中心须匹配记录，当前中心移动不得超过 64 单位。NaN、无穷、越界和错误包长均拒绝。连接或世界更新会重置事件序列，旧生命不能领取冲量。

有效冲量累加到真实 `pev.velocity`，正向上冲量清除 `FL_ONGROUND`；之后由原生引擎处理移动、碰撞、摩擦、重力和最大速度。不会改变坐标所有权或强制切换形态。
