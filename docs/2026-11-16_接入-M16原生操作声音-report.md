M16 的空仓、抽枪袖口、武器拾取和弹药拾取已接实际原生声音消费者，并装入地图 runtime。射击声仍需原合作消息接线，玩家推搡声属于独立生命任务；当前未开放 M16 购买、未部署或操作用户 B。

F-01（high / original and SDK validated）：类型化 M16 sender 使用自身资源表。只处理四个原生事件，不把 M16 FireSound 放到普通 CHAN_WEAPON，也不从当前武器借用玩家延迟推搡的生命周期。

F-02（high / host adaptation）：从已有P345 sender逐字节逻辑抽出编译期共用实现，P345与M16各自保持事件、样本枚举/资源数组；TMP/MP5的自动循环/尾声实现保持。此选择与初始私证中的候选复用范围差异记在m16-native-sound-scope.json；不宣称原版源码就是模板结构。

F-03（high / source implemented）：地图 runtime 内部消费四类原生声音，并在实际后端声明相应能力；真实external回调仍需提供其余效果。声音缺资源/引擎或回调换代时返回精确状态，只有存活的成功空仓发声才清点击标志，不注销整个玩家生命或武器。

P-01：M16 class原事件 → runtime同实体/生命租约 → 真实owner quiet快照/地图pickup抑制 → 编译期样本选择 → SDK EmitSound → 存活后原字段后处理。冷预缓存ID复用，热路径不读盘、不查模型、不分配；这属于静态成本边界，不代替游戏CPU采样。
