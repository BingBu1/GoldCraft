# 永夜提灯照亮人物

旧版提灯优先使用 CoF 的地图表面光。在永夜《穷途末路》，地砖和墙面已经受光，两名队友的模型、第一人称手套和灯体仍然接近黑色。客户端现将装备光提交给 GoldSrc 原生动态光，Renderer 可以用同一盏灯照亮人物、手中装备和地图。提灯保持中性白光，基准半径 440。照明弹保持原色，落地半径 220。

## 原版与宿主的依据

修改前分别核对了 CoF x86 原版 client.dll 的 SHA-256 `d2a04641b301804f6f449aa68265042b13adc360925b80033d417ec9f38c9c00` 和 hl.dll 的 SHA-256 `0036b91c01e92ed205513f52563053a55a66a32d257efb5f476b8f1f3dde0e63`。客户端 VA 0x100B1148 从手持模型两处附件追踪灯位，VA 0x10060470 从世界模型坐标上移 6 单位。两段分别复核 190 和 180 字节。原提灯三个通道均为 0.4，半径基准 220，逐帧波动 −5 至 +5。项目按用户先前的要求扩大提灯半径。照明弹的原版通道计算和火焰伤害分别见[地面照明记录](2026-11-20_修复-CoF照明弹地面材质照明-report.md)和[火伤记录](2026-11-19_实现-CoF照明弹火焰伤害-report.md)。

原版客户端 VA 0x1005B300 处理地图表面。移植的 `PointLightRenderer` 遍历世界 BSP 和刷子模型。对应人物在宿主由 Studio 绘制，私有灯池没有进入它的照明。修改位置是 `native/csol/client/weapons/guest_cof_light_equipment.cpp`。原生灯使用独立实体键。落地照明弹继续申请 256 阴影。原生灯不可用时保留已有地图光后备路径。

第一版只切换了后端。12 张画面已能辨认队友，但原 CoF 灯的 10 毫秒有效期比当时实机 24.0 毫秒的帧间隔中位数还短。连续抽查的 50 帧里，49 帧在当前视角提交后看到了引擎灯键，Renderer 帧首转换出来的点光为 0 帧。宿主先在 `GL_BeginRendering` 收集引擎动态光，此后当前视角才提交手持附件。最终版沿用已实际验证的宿主 120 毫秒刷新窗口，并按可见帧和实体键主动回收。原 CoF 私有后备灯仍使用原 10 毫秒。装备端只记录已提交的灯，共用宿主 32 槽上限。普通灯、落地阴影和地图重置通过同一套所有权检查回收。该时间窗口属于宿主适配。

## 同机位人物实测

测试使用一个 B 客户端和同一间隔离 ReHLDS 的两名 CT 测试角色。两人的自带手电均关闭。B 在买区通过真实购买处理扣款，提灯 600，照明弹 150，然后到测试位置。各版将观察者固定于（−1824，1256，36.0312），视角俯仰 8°、偏航 194.595°。服务器核对了两名角色的坐标、朝向和持枪模型。最终版第一组持灯帧发生视角与位置变化，原样留在 moving-observer。复拍沿用同一生命与库存。测量覆盖旧版与最终版各 5 张持刀、12 张提灯、5 张收灯画面，逐帧核实位置和角度。表内为固定人物区域的 8 位加权显示亮度，先求每帧区域平均，再取多帧中位数。

| 取样区域 | 旧版提灯 | 最终版持刀 | 最终版提灯 | 最终版收灯 |
| --- | ---: | ---: | ---: | ---: |
| 正面队友的头脸 | 0.7 | 0.7 | 111.2 | 0.7 |
| 正面队友的背心 | 0.3 | 0.4 | 119.3 | 0.4 |
| 侧向队友的头部 | 0.1 | 1.6 | 52.5 | 1.8 |
| 侧向队友的上衣 | 0.2 | 0.1 | 99.3 | 0.1 |

第一人称手套在旧版与新版均举起同一盏提灯时，从 0.0 升至 17.3，灯身金属面从 0.1 升至 58.1。实机读取 37/37 帧识别为 Renderer 点光，RGB 均为 102、102、102，采到半径 435 至 445。收灯后抽查的 32 帧均无有效装备灯键。修复前后的原始帧、取样区域、面积与逐帧数值保存在本地验证目录。

## 照明弹复验

同一机位通过第 4 栏选择、点燃和投出一枚照明弹。夹具在它自然落地后固定弹体位置。服务端首次记录燃烧落地在 346.7 秒，观察到同一实体自然熄灭在 449.2 秒。服务端确认了落地点，两名人物均在取景范围内。

| 状态 | 正面头脸 | 正面背心 |
| --- | ---: | ---: |
| 点燃前 | 0.7 | 0.3 |
| 手持燃烧 | 13.0 | 12.5 |
| 落地燃烧 | 35.0 | 37.7 |
| 自然熄灭 | 0.7 | 0.4 |

手持照明弹采到的半径为 205 至 235，落地每帧为 220。落地样本的红绿蓝通道范围分别为 168–255、39–64、14–38。原武器的颜色会随燃烧变化。自然熄灭后抽查的 47 帧均无有效灯键。服务端仍使用原已部署的每秒 5 点、半径 96 火伤逻辑。

## 队友手电与投影的独立观察

此前在相同 Renderer 上由一个 CT 测试角色持 USP 并使用游戏的手电开关。另一名 CT 横穿光束。单 B 侧面观察时，墙上预计躯干投影区的平均亮度中位数由关灯 1.41 升至开灯 69.31，穿越时为 73.78，角色离开后为 67.63，关灯后为 1.41。可确认队友手电能照到墙，这组读数尚未验证穿越者在墙上的投影。手电聚光和提灯人物照明的测试数据各自保存在本地独立回执中。

## 构建与部署

x86 CSOLSupport 使用 C++20、Clang O3、ThinLTO、AVX2 和精确浮点，核对装备翻译单元的 448 个依赖、164 个链接对象及静态库。并行构建更新了公共缓存中的四个对象。通过既有编译输入 SHA-256 恢复其源字节，仅在编译器临时覆盖层重编，四个产物逐一匹配已通过的基线对象。AMXX 角色夹具用项目匹配的 1.9.0.5303 编译，并在此轮冷服加载。第一次在取景位置购买照明弹被正常买区规则拒绝，最终轮在出生买区买齐两件再固定相机。

隔离服通过 326 项 HUD 预检和 292 项客串资源实际 HTTP 核同，B 挂载 v4 全部 3519 项并绘制永夜 HUD。最终版实采 234 个相邻 Renderer 帧间隔，中位数 32.0 毫秒，P95 为 47.7 毫秒。此值反映单 B 同场景整机表现。常用沙盒专服通过 327 项 HUD 预检，实际受测的 DLL 和 PDB 已安装到常用 B，客户端 SHA-256 为 `ee456bc898ca36f197aa79062ce8177142030df9ecca6fd326cda64261ee5d58`。双真人同屏、多人多灯开销和正式客户端分发仍待验。
