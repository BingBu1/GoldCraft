# MC 控制就绪与输入时效

CS 渲染暂停超过 500ms 时，旧实现把输入超时加入 MC 的未就绪判定。MC 客户端随后上报 `ready=false`，MC 服务端挂起玩家并发布禁用姿态，ReHLDS 因 `authority_not_ready` 释放控制。这条路径会把短暂卡顿扩大成重新取得控制的过程。

现在输入时效只决定旧按键能否继续执行。MC 客户端仍在线、宿主几何和玩家有效、双方世界与生命代次匹配时，缺少新 CS 输入不会自行撤回就绪。`INPUT_AGE` 仍保留在诊断原因中，供现场区分输入暂停和生命周期失败。

输入与控制的边界如下：

| 条件 | 行为 |
| --- | --- |
| CS 输入满 250ms 未更新 | 停止旧移动、攻击、使用等按键，丢弃本 tick 的视角增量 |
| CS 输入满 500ms 未更新 | 诊断记录 `INPUT_AGE`，仍允许有效 MC 客户端续租就绪 |
| 控制授权缺失或玩家身份刚变化 | 不执行 MC 控制；仍可请求重新授权 |
| 断链、几何未就绪、玩家死亡、世界／形态／生命无效 | 上报未就绪并停止控制 |

没有修改服务器对当前配对、生命、姿态、效果租约及碰撞的校验。未变化的就绪状态仍每 400ms 续租；MC 服务端 1 秒就绪超时、ReHLDS 1 秒姿态超时、350ms 效果证明时限、客户端 350ms 姿态／500ms HUD／250ms 相机时效均保持。真正失联仍按既有路径处理。

服务端权威姿态序号由 MC 服务端独立递增，不依赖 CS 输入帧序号。CS 接收客户端姿态允许同一输入序号的更新，因此停止输入帧不要求伪造新输入或放松序号校验。
