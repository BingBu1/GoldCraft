## Findings与Path

F-001，`status=validated`、`severity=n/a_re`、`confidence=high`，E-001/E-002：原预测命令函数`3784E590`在`3784EB53..3784EB64`按位复制输入状态`+30C`至PM`+220`。`3784EC90..3784EC9B`调用客户端移动出口后，`3784EF07..3784EF18`将该PM字段写回输出状态`+30C`。此处没有浮点转换、钳制或默认值；264种位型包含NaN、无穷和有符号零，逐位及邻接内存检查通过。此结论只命名原始偏移，不借此补猜网络生产者。

P-001，`path_type=callflow`，E-001/E-002：原预测状态输入 → 引擎填充PM → `37831790`以server标志0调用实际客户端移动表项 → client `HUD_PlayerMove 02A2D460` → 前置可写回调 → PM → 引擎写回预测状态。原客户端回调接收的是两个参数的地址；它能改变随后传给PM的指针和标志。三组提供方分别保留参数、换PM指针／标志0、换回指针／标志1，原调用顺序、栈平衡和EBP保存通过。回调与内层PM是明确的ABI测试提供方，不声称已执行原运行插件或完整移动。

F-002，`status=validated`、`severity=n/a_re`、`confidence=high`，E-001/E-003：原导出F `02A2D130`从引擎描述符`+8`取得前置回调表。原引擎初始表`382FEF70`的移动`+18`和清键`+34`均指向3字节空回调；`378B43D0`将该表交给已加载模块的注册入口和上下文入口。`378B4790`的退役路径才用空回调重新覆盖此表。因此不能根据静态初值在生产代码中加入no-op，或宣布原运行回调没有副作用。

## 源码、失败与验证边界

仅新增 `tests/csol-standalone-prediction/original_transfer.py`及说明。回放复用已有PE读取器，先固定原样本SHA和完整IDA指令边界，再运行未修改原指令；构建输出只写简短回执，不复制生产源树。没有新增游戏热路径、分配、读盘或服务器灯实体。

本轮IDA概览首次超时，后在同一worker确认缓存就绪继续，没有杀死共享服务。打开第五个worker时遇到四槽限制，只保存并以技能脚本设置本任务已不用的原MP／hw会话空闲退出，其他任务会话保留。首次脚本入口还因Git Bash环境中工具路径缺失失败，改为显式已核对安装路径后复用现有服务，没有重新安装IDA或修改Codex配置。
