# 蝗虫图复活与跨图模型错配修复

蝗虫图 `zs_evacuate1` 的旧服务端在安装首轮触发规则时失败，玩家一直留在观察状态。跨图另有一个客户端共用缺陷。原生模型表满时，旧实现可能把旧 Studio 缓存挂到新模型名下，或者回收已经绑定到本图网络索引的延迟加载槽。

## 证据与改动

| 证据 | 实现 |
| --- | --- |
| 隔离专服的匹配 PDB 捕获到 `unsupported scenario trigger command`。CSOL MP 的 `0x1139D870` 先结束列出的波次，随后在 `0x1139D956` 调用 `0x11380630` 清理怪物。 | 支持该地图的 `k` 事件，按顺序结束波次、调用既有普通怪死亡处理。回合初始化失败时报告具体错误，避免卡在观察状态。[触发程序](../native/csol/scenario/core/trigger_program.cpp) · [波次服务](../native/csol/server/scenario/core/scenario_wave_services.cpp) · [回合规则](../native/csol/server/scenario/core/game_rules_gate.cpp) |
| CSOL MP 的 `0x113813AF → 0x1138B240 → 0x1138B353` 进入失败处理。`0x113820DA–0x113820E1` 将 7 秒交给结算函数 `0x114B3210`。 | 将团灭接到 GoldCraft 的现有结算策略。同图重玩配置在结算后原地开新局。队友仍存活时沿用当前回合的免费复活。[回合规则](../native/csol/server/scenario/core/game_rules_gate.cpp) |
| CSOL HW 的 `0x3787D1E2–0x3787D240` 根据模型名哈希定位身份，`0x3787D242–0x3787D2E4` 为新名称分配记录并初始化 CRC。宿主 10210 的 `0x1023E64E–0x1023E709` 在表满时可能复用旧 Studio 槽，预缓存调用位于 `0x101A4653`、`0x101A4662`，索引消费者位于 `0x101A2FA0`。 | 让有效模型名继续指向原记录。缺少安全可回收的原生槽时使用已有扩展表。两条延迟登记路径都在向本图网络表交付模型指针前保留槽位，实际模型仍由引擎在首次使用时加载。[客户端预缓存](../native/client/precache_client.cpp) |

原版使用现有 IDA 数据库。PE32 MP 基址为 `0x10000000`，SHA-256 为 `39f962f34816411e615f01e5279d914204f7fd07c5a5112b0b303acafe0308b2`。PE32 HW 基址为 `0x37100000`，SHA-256 为 `c7bddfda93c2e0877ea126a15a318b83cce74c59bb95e38a7301b08033ac7783`。宿主 PE32 HW 10210 的 SHA-256 为 `9ba9a2db5e07598fd59afa35507a98c86162e4e15b3835177b78c11842cd2295`。表中均为对应映像的 VA。现有数据库指令、关键字节和模块表回执位于本地 `analysis/csol-evacuate-respawn-20261121/ida-review.json`。[原版模型身份路径](2026-11-07_取证-CSOL专服代理模型与换图负载-report.md) · [原版 CRC 路径](2026-11-07_取证-CSOL引擎CRC32与宿主模型校验边界-report.md)

宿主修复保留已有模型名索引、缓存命中和按需加载。新增检查在登记模型时执行，无逐帧扫描或同步文件读取。地图清怪复用现有怪物池和死亡处理，发生在触发事件时。

## 验证

使用当前工作区完整构建 x86 `mp.dll` 与 `GoldCraft.dll`，DLL 与 PDB 配对核验通过。服务端通过 23 项失败结算、196 项触发程序、139 项波次检查。客户端模型表满回归旧版失败 4 项，覆盖 Studio 缓存错配和延迟槽被回收。新版预缓存组累计 199 项及清单顺序 15 项全部通过。

`zs_evacuate1`、`zs_evacuate2`、`zs_evacuate3` 使用各自独立的 ReHLDS 启动，逐图检查 326 项 HUD 下载资源。原生死亡路径下，同一回合内首次观测复活分别发生在 2.90、3.42 和 3.41 秒。两名测试角色团灭后，三次都在满足 7 秒结算并额外经过一次采样后进入同图新局。这里使用测试专用玩家槽。

另在 `zs_evacuate1` 启动真实图形客户端与一名测试队友。两次均完成 3,396 项资源校验及挂载。走原生死亡流程后，客户端分别在约 3.95、4.09 秒被观测到在原回合复活。第二次抓取的实际提交帧显示“复活剩余时间（1 秒）”，复活后恢复第一人称武器 HUD。两次客户端及专服退出码均为 0，隔离文件已恢复。画面与复活日志位于本地 `build/csol-evacuate-respawn-20261121/client-countdown-06`。

图形客户端先后运行旧版和新版，分别走完穷途末路 → 失落之城 → 致命陷阱 → 最初线索 → 黑暗之门 → 穷途末路，实际核验资源挂载和 HUD。两版各核对 1,497 个已加载 Studio 模型头，模型名与缓存身份一致，当前网络模型槽均可正确解析。原生记录峰值同为 957，低于 1,024 槽上限。模型表满时的错配在定向回归中复现，玩家在正常对局中看到的偶发错模仍待对应画面或现场模型索引核实。此次对照记录换图过程，未测量纯模型修复对帧率的影响。

两次客户端及专服均正常退出，隔离文件已恢复。模型对照汇总在本地 `build/csol-evacuate-respawn-20261121/model-capacity-ab.json`。

蝗虫一图的默认投票策略另行通过 17 项隔离检查。投票选回当前图 `zs_evacuate1`，从团灭到地图重新载入约 33.31 秒，包含结算与投票。

构建、原生服务器及图形客户端回执位于本地 `build/csol-evacuate-respawn-20261121`。正式客户端和正式服待配套更新。
