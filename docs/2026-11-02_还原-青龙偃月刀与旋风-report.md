# 青龙偃月刀与旋风 SKULL-9：原版合同与实现检查点

两把武器已经落实独立 C++ 实体、延迟伤害、JSON 伤害配置、SDK 扇区命中、客户端预测和青龙刀光。实体注册、预缓存、预测打包与客户端公共分派已接线；实际客户端专项119项、刀槽发放真实方法专项179项通过，完整客户端和服务端 DLL 已编译链接并核对 x86/PDB。原包缺失的青龙重击音效经用户明确同意后精确省略，资源闭包已通过。原价核实、购买目录接入、部署和实机尚未完成，不能记为两把武器已可购买游玩。吸血按用户最新要求留在插件系统，低优先级，不内建到刀的基础伤害逻辑。

## 身份和证据

集中资源目录的中文词条确认青龙偃月刀为 `dragonsword`，旋风 SKULL-9 为 `skullaxe`。原 MP SHA-256 为 `39f962f34816411e615f01e5279d914204f7fd07c5a5112b0b303acafe0308b2`，x86 image base `0x10000000`。

原实现是 `CKnifeHelperDragonSword` 与 `CKnifeHelperSkullAxe`。`16`、`10` 是原 `CKnife` 的类型编号，不能当作两把独立武器的网络 ID。本项目分配桥接 registry ID **1022/1023**，分别对应原物品目录 **483/363**、原 InGameID **4016/4010**；原生刀的武器ID仍为29。这些命名空间保持分离。

原 common `resource/item.csv` 两行直接验证 Equipment/category11/InGameID4016与4010。`CSOL_MeleeItemIdentity` 必须同时匹配真实动态类型、bridge ID和classname才返回物品编号；灾变 `SetItemIdentity` 再核目录的精确类别和InGameID。没有放宽仅接受4000的默认刀选装规则。发放事务在新实例Spawn后、Touch前调用`CSOL_ScenarioSetMeleeIdentity`；失败即拒绝发放。

独立 MP 副本研究库位于 `analysis/csol-model-20261017/melee-20261102/ida-copy-mp`，未复制或打开已停用原 IDB。原生 IDA 定义并读取两属性构造、四攻击入口、四延迟命中函数及 CKnife 延迟分派；164 段共 24,760 字节与原 PE 逐字节一致，原/副本 PE 内容和 file-ID 保持。证据是该目录的 `ida-verification-01.json`。

Hex-Rays 返回的 positive-SP 伪码只保留为诊断，不作为实现依据。第一次大批 `get_bytes` 的结果被工具截断，未采用；第二次按 160 字节分页完整核对。两属性构造的反汇编同样按 160 指令分页保存，未将被裁剪的初次响应视为完整函数。

原青龙完成函数只在左键 seq1 发送消息 type84/subtype0，右键发送 subtype2；seq2 不发此消息。原客户端 `02563390`、`02563560`及消息分支已通过原生IDA和629字节直接PE核对：效果为`ef_dragonsword.mdl`，时长0.35、additive/alpha128、fadeSpeed3、frameMax256；序列为subtype加左手偏移1，回调每帧跟随当前视点和视角，不是枪口附件。移植层独立`CSOMelee`消息还携带完成序号和动画结果，并在切枪/死亡/会话重置时退役旧刀光。

源码配置位于 `native/csol/config/dragonsword_damage.json` 与 `skullaxe_damage.json`，包含原 `PriFullDmg`、`PriFastDmg`、`SndDmg` 和原模式集合的倍率。JSON 解析有严格字段、版本、数值范围检查，解析全部成功后才替换旧配置。

## 命中几何

`native/csol/server/melee_trace.cpp` 依据原 `0x10CBE320..0x10CBE6AA` 实现：

- BSP 目标首先要求 human hull 的正前方直接命中；普通目标先走 point hull。
- 普通目标的前向碰撞不成立时，调用目标的原 BodyTarget 语义，再做水平夹角判断。
- 可跳过最多五次非 BSP 遮挡，每次从命中点沿攻击前方向前5单位继续追踪；不会直接穿越 BSP。
- 目标 BodyTarget 由匹配目标类型的 provider 提供，未以 `Center()` 近似。原玩家 BodyTarget 有随机视点偏移，怪物与可破坏物的实现还须逐类型匹配。
- 普通背刺朝向判定使用水平位移与目标完整 forward XY 点积大于0.8，伤害倍率3。原玩家被动概率强制背刺分支尚未接入。

补充函数由 `ida-supplementary-02/result.json` 的42次窄查询、49段3951字节另行核对原PE，全部一致；与首轮24,760字节分开记录。该轮核对了BodyTarget、伤害属性调用、原刀空击杀回调与近战冲量关闭入口。没有依赖positive-SP伪码。

## 预测、切枪和回调生命周期

原生`weapon_data_t`协议不传输`iuser2/iuser3`，`iuser1`为signed16/scale128，不能直接装无限递增攻击序号。现以实际传输的`m_iWeaponState`保存动画及交替奇偶，以`fuser2/8`保存16位序号，`fuser1`保存延迟计时；没有修改引擎结构或delta ABI。实际delta字段量化专项遍历全部65,536个序号，验证客户端重放仍能读回状态。

Holster清除未完成Think和刀光，保留攻击冷却；Deploy不重置两个攻击计时。每位玩家、每种刀的完成序号跨同刀实体替换延续，避免重新购买后序号归零而被客户端视为旧消息；地图预缓存与userid变化分别清理。服务端逐目标TraceAttack/ApplyMultiDamage后验证当前SDK、回合、实体与怪物池租约，防止死亡回调销毁/复用对象后继续访问旧目标。受控库存重入与发放事务结果见下文，真实实体回调和多人实机仍待验证。

人物动作优先使用实际`dragonsword`/`skullaxe`动画族；缺少所需人物序列时退回原生knife动作。首人称预测保留人物手部body，不每帧重启动画；权威完成消息可纠正本地视线未发现的侧面扇区命中。项目刀实体仍为服务器权威伤害，客户端仅预测表现。
