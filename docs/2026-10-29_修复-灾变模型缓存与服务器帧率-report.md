# 灾变模型缓存与服务器帧率

2026-10-29。测试地图为穷途末路。当前发现来自旧运行版本与原 CSOL 引擎静态分析；独立缓存修改尚未通过真实战斗验收，不将编译或空场 FPS 当作修复完成。

## 证据与结论

| 证据 | 观察 | 结论 |
| --- | --- | --- |
| E1：匹配 PDB 与运行模块的只读缓存快照 | 堆 41,943,040 字节，低端已用 27,410,944 字节，缓存预算 14,532,096 字节；快照只保留两种僵尸和一个人物模型 | 地图与模型共用旧 ReHLDS 40 MiB 堆，剩余预算不足以同时保留常用模型。 |
| E2：用户连续 SEQ 日志与实际 Mod_LoadModel / Cache_Alloc 调用路径 | 模型缓存未命中才重新解码、合并 SEQ；容量不足按 LRU 淘汰 | 日志是重复加载的结果；单纯隐藏日志不能消除转换开销。 |
| E3：8 次只读专服采样 | 38 个 solid 非零怪物、45 个池实体；FPS 从 39.18 到 500.60；玩家死亡、terminating=1 | 存在间歇性重卡，不能描述为稳定 40 FPS，也不能称为正常战斗基准。 |
| E4：原 CSOL hw 静态代码 | 固定 64 MiB 普通堆与另一块独立缓存；缓存有 14 MiB 下限、80/256 MiB 上限分支；仍有 LRU 淘汰 | 原版并非由 MP 阻止重复调用，而是引擎使常用模型保留在独立缓存。 |

E1/E3 保存于本地 `build/csol-cache-thrash-20261029/before.json` 和 `live-before-01.json`。这些是一次性进程快照，复现需要同一版本和有效运行实例，不能套用旧进程 ID 或地址。E4 保存于同目录 `cso-memory-init-b.asm`、`cso-memory-layout.asm`、`cso-host-memory-call.asm`、`cso-cache-alloc.asm`。原模块 SHA-256 为 `c7bddfda93c2e0877ea126a15a318b83cce74c59bb95e38a7301b08033ac7783`；原字节仅本地研究，不随仓库分发。

原初始化函数 `0x37941D50` 分别分配普通堆和缓存，宿主初始化 `0x378A01AC` 将两个地址和容量传给 `0x3798C5A0`。缓存基址/末尾单独保存在 `0x39424290` / `0x3942428C`，`0x3798AE70` 在缓存满时仍走 LRU。分支标记的 getter 与引擎 IsDedicatedServer 接口邻域交叉吻合；这不代表已测试官方远程专服的实际内存占用。

调用路径是：怪物逻辑查询模型 → 引擎查缓存 → 未命中时读取与合并 SEQ → 缓存分配 → 容量不足淘汰其它模型 → 下一种怪物再次查询。新实现让模型缓存与地图高低端 hunk 分配互不侵占。

## 实现范围

- 使用独立普通堆与缓存，保持原缓存命中、LRU 顺序和 cache_user 指针更新合同。先前只把共享堆提高到 128 MiB 的候选已放弃，未部署。
- 保留原双参数 Memory_Init 入口的共享堆行为；新宿主使用四参数独立分配，不修改公开 quakeparms 结构或 GameDLL ABI。
- 固定普通堆 64 MiB；按原版 dedicated 分支缓存上限 80 MiB，非 dedicated 分支上限 256 MiB。`-heapsize` 使用 KiB，控制独立缓存；`-minmemory` 把缓存限制为 14 MiB。
- `gc_cache_stats` 报普通堆、独立缓存预算、条目、分配和容量淘汰数；淘汰计数不包括主动 flush。
- `csol_scenario_perf begin|reset|report|end` 默认关闭，启用后分别记录真实 StartFrame 间隔、引擎 frametime、有效阶段、怪物数量和 AI/导航耗时。嵌套计时不可相加，Rejected/空场高 FPS 不作为验收。
- RCON 诊断器按匹配引擎九字节 split header 重组大包，缺片明确失败；不同独立 UDP 消息仍不保证全局顺序。

原无路径隔次重建已在 MP 指令中证实，与行为层 0.6 秒 FindPath 门独立。本批保留调度，不通过降低刷怪数量、关闭 AI 或减少攻击来制造高 FPS。

## 验证与下一步

源代码与离线检查、完整构建、部署、实服各自记录。独立缓存直接包含实际 zone.cpp 的 53 项回归通过；实际 Sys_InitMemory/Shutdown 函数体的 92 项边界检查通过，涵盖容量选择、两次分配失败与清理顺序。宿主平台接口由桩提供，仍不等真实进程生命周期。性能诊断 34 项边界与 9 TU 编译、RCON 7 项传输测试通过。统一候选六个 x86 原生模块与两个生产 Pawn 已构建，两个外部源码补丁均已验证可应用至固定上游并重现当前源码。

用户授权后，`build/csol-fps-candidate-20261029-03` 的 150 项计划已应用，65 项实际更新。独立复核所有目标的长度与 SHA-256 一致，两个新购买图片的 HTTP GET 200、全内容 SHA 和 Range 206 通过。专服和 B 已重启，RCON 确认穷途末路、32 槽和一名 B 玩家。运行引擎确认 heap=67108864、budget=83886080、separate=1，即 64 MiB 普通堆与独立 80 MiB 缓存。

本轮界面工具在首次窗口枚举时再次报告实体 Escape 停止操作，因此未发送选人、移动或攻击输入。随后仅后台采集 30 秒诊断：9145 个有效规则阶段帧、实际 StartFrame 平均间隔 3.310 ms（约 302 Hz）、p95 桶上界 16 ms；31 次人口采样均为零怪物，不能作为刷怪性能改善证据。预载后缓存已有604次淘汰，不能声称没有淘汰；本段无战斗，也不能证明常用模型不再反复淘汰。击杀、破墙、复活、菜单视觉及换图释放继续待验。

证据位于 `build/csol-fps-live-20261029/`：`deployment-audit.json`、`passive-performance/commands.jsonl` 和 `protected-comparison.json`。客户端启动前后原安装19608项文件元数据、7项核心 SHA 及根 Git index 一致；该基线是在专服启动后、客户端启动前采集，不扩张为部署前后全安装哈希证明。

更新后在同等怪物数量和观察位置采集正常刷怪/攻击/击杀：比较帧间隔分布、低帧尖峰、模型淘汰增量，并核实击杀不再拒绝整图；再检查换图、重启和普通 CS/ZP。整体大灾变验收保持开放。
