# 大灾变永久模型血迹

近距离枪击每次命中能出血的灾变僵尸，手臂与实际开火的枪各叠加一层随机溅点。首发是清晰的溅点簇，后续每发在同一表面续加溅点。同一发的多弹丸与穿透共用一次溅射。每个表面能够累积 63 层，达到上限后保留最终覆盖。僵尸自己的受击血迹也逐步累积，并在实体可见期间保留。

手臂血迹随玩家在本图存续，重生与同图重玩后仍显示。同一把枪在手持、落地及换人拾取时始终带着自己的血迹。地图卸载、玩家离开和实体销毁是状态回收边界。僵尸池回收再借出时，新僵尸从干净状态开始。关闭模型血迹会隐藏已有血迹，重新开启后按原样显示。

## 管理设置

统一 `gameplay.json` 中的 `features.blood.enabled` 控制模型血迹，默认关闭。M 菜单的「管理员菜单 → 模型血迹」可即时开关并保存。溅射距离 `blood_splash_radius` 默认 128 GoldSrc 单位，设为 0 时只保留僵尸受击血迹。旧版 JSON 中的血迹寿命与上限字段仍能读取，在下次保存时自动移除。

## 运行路径

服务端通过真实弹道和伤害聚合确认命中与开火枪械。血迹状态按实体槽及序列号保存，僵尸逻辑复用命中后的出血分类。玩家和普通实体快照在 `fuser4` 的 28 位自定义增量中携带两组种子与击中次数。原生客户端会覆写本地玩家快照的 `iuser3`，改用通过实机核对的 `fuser4`。服务端与客户端同时更新才会显示新版血迹。

渲染端用六张游戏自带的 WAD 血花生成两组共 126 层的累积贴图。每个 GL 上下文准备一次，由两套 Studio 绘制路径共享显存，单个材质仍只采样一次。保留旧点并叠加新点，斑点有颗粒和深浅。原生 Renderer 对沾血的部分降低高光，手臂使用材质名识别并保持同一贴图的溅点位置。关闭效果时停用渲染查询。

## 逐发累积验证

- x86 隔离专服加载 ReHLDS 49b79a2f、ReGameDLL bce9f514，单个图形客户端加载 CSOLSupport fced8ac6、Renderer ddaa8dd6 及配套 Studio 着色器。完整 HUD 资源闭包和 v4 实际挂载通过，原生生命及护甲 HUD 正常。
- 穷途末路隔离实测 40 项通过。每次 88 单位内的真实枪击使手臂和 AK 各增加一次，原生视角的渲染快照逐发从 1 层累加到 8 层。196 单位外的命中只给僵尸留血。切到干净 USP 后只看到手臂原有血迹，换回 AK 后恢复枪身原有血迹。即时隐藏与恢复、第三人称及实际僵尸快照通过。两端正常退出，已恢复隔离配置并复核受保护安装的五个核心文件。
- 同机位 RGB 差分阈值为 12。手臂取样区相对于干净画面的变化像素从首发 6,818 增至第八发 9,217，枪身从 9,591 增至 10,083。关闭时两处差分归零，恢复与切回枪的像素和第八发一致。该受控机位的两段 500 帧间隔 p95 分别为关闭 13.56 毫秒、开启 13.63 毫秒。采样在隔离桌面，正式多人性能与首次准备成本仍待测。
- 封存的 x86 服务端对象通过专项 SDK 回归 30 项行为和 1,219 项底层检查。真实霰弹路径确认多弹丸只累计一层，验证 63 层封顶保留原种子。原命中、排除与重入三组也通过。回执为 `progressive-sdk-02/receipt.json`。
- 27 项原生增量回放包含旧字段丢失的反例。RTX 4090 离屏对照分别覆盖两套 Studio 路径、手臂和枪身材质及不同累积层。实机回执与同机位对照在本地测试目录下的 `scenario-live-stains-progressive-07/`。
