# 冰桑启动器完整配套修复交付

11 月 7 日服务器包虽然包含完整 19 个客户端核心 DLL，但沿用了旧启动器的静态资源合同。
旧 EXE 在线更新两份 DLL 后仍使用旧符号目录，造成 `CSOL_CRC32_ProcessBuffer` 等缺失。
此前只验证磁盘发布、安装及回滚，遗漏了真实旧启动器资源与新 DLL 的组合，这是本次修复的发布缺口。
根因及发布器防回归见 [目录遗漏报告](2026-11-08_修复-启动器符号目录配套遗漏-report.md)。

## 成套交付

- 单文件冰桑启动器 2026.11.08.1，内置完整 374 项安装文件和原图标。
  新 bundleId：`ac689085e776441828892db90bd22f09c9ee21c80e0318630ac3ea096c796406`。
  最终 EXE：75,324,277 字节，SHA-256
  `ce3c1add11b52da4816531fc044523dabe93564f20d159b2d555d5097dc1bf79`。
- 服务器配套包 `server-packages/launcher-20261108/BingSang-Launcher-Server-20261108.zip`：
  26 成员、10,364,466 字节，SHA-256
  `a4b9c77f82c6c7e107dc0dfa610aab6ce386ff584bcba5c0f4eab36f67ee91b6`。
  包含签名序号 `2026110801` 和完整 19 个 DLL，不依赖旧下载目录中的 blob。
  清单 SHA `f41fd468156fca0f3b67bf4e351b488024cabfa1f4ae3b52c1a624721e7484df`。

配套包适用于已更新 11 月 7 日服务器累计包的环境，只改 `cs/launcher-public` 和自身备份。
先运行 Update-Launcher.cmd，再给玩家新 EXE；玩家退出 CS、选择原游戏目录并点击“安装 MetaHook”修复，
之后正常启动。普通 cstrike_downloads 资源无需重下。服务器端每次请求重新读取 manifest，
由 `native/engine/launcher_http.cpp::LauncherFiles::request` 确认，因此本次在线发布不需重启服务。
未知或更新的签名清单拒绝覆盖；配置、端口和管理员保持。

## 修改范围与身份

`refresh_bundle.py` 使用实际旧 EXE 提取的 payload/bundle 为完整库存，校验旧 ZIP 全 SHA、
运行资源、全部 207 符号目录和索引、基础游戏身份、核心发布和插件顺序，拒绝未审新资源。
旧新只变化四个目录/索引与两份核心 DLL；原公钥、网络配置和其他静态资源保持。
未修改符号地址或实现新游戏行为。

固定 CSOLSupport：`d585de84ff94d5e1b9ea561ef3586c801c83f6a0e1b7d0a2b6e635525691fe6c`；
GoldCraft：`daaf84f876fd57382e54f4eb09f2e4d6982dd43ed8e9b9e3e6d709bb618df16a`。
本轮没有重新编译 native，没有修改运行沙盒或原 Steam 安装。
Build.ps1 使用独立 obj/bin 路径和明确版本；构建输入身份记录在
`build/launcher-static-hotfix-20261108/build-inputs-final.json`，保留构建前 Git revision 和逐文件 SHA。

真实升级首次在 Windows File.Replace 返回 1175 时失败，事务自动回滚，失败现场保留于 upgrade-test01。
这暴露原安装器缺少短暂共享锁重试；SafeFiles 现在仅对 32/33/1175 有界重试，
每次重试前核验源和目标字节，仍使用原子替换。等待期间外部修改目标时停止并保留其改动。
没有删除目标再移动等非原子回退。
