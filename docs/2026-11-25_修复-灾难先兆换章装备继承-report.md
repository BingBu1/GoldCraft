# 灾难先兆换章装备继承

## R4 复现

用 R4 专服和一个真实图形客户端触碰第一章通往第二章的 BSP 机关。换章前装备 CoF M16、Glock 与近战武器，主副枪备弹为 171 与 151。第二章保持相同 userid、83 生命、28,900 金钱及 CoF 协议能力，三个武器槽及当前武器均为空，服务端也没有第一人称武器模型。客户端已挂载第二章全部 3,687 项资源。R4 实机回执见 `build/leon-character/live-carry-r4-03/receipt.json`。

## 原版依据

原版 x86 MP 基址为 0x10000000，SHA-256 为 39f962f34816411e615f01e5279d914204f7fd07c5a5112b0b303acafe0308b2。108285E0 调用 10824EE0，在换章前保存装备。114EF060 在 Spawn 尾部调用 10826140，后者经 114D9BD0 清除默认装备并按编号逐件发放，再恢复备弹。114D9BD0 的参数 a3 为 0，武器使用新建时的默认弹匣。原版存取和调用点保存在工作区的 2026-11-16 灾难先兆取证记录 §4.7。

## 修复

- 把快照恢复移到 CBasePlayer::Spawn 的装备尾部。复刻的 CoF 武器需要该位置之前的角色初始化，才能在原生 Touch 中完成持有者绑定。 [出生尾部](../native/csol/server/scenario/core/game_rules_gate.cpp)
- 按新地图已登记的武器编号走 Spawn 和 Touch。保留扩展协议、CoF 持有者能力和特种武器登记检查，备弹在装备发放后恢复。购买阶段检查继续由商店承担。R4 的发放入口在开章重生期间读取购买状态，因而清空默认装备后无法发回快照武器。 [武器发放](../native/csol/server/weapons/weapon_service.cpp) · [章节快照](../native/csol/server/scenario/core/scenario_chapter_carry.cpp)
- 恢复只在出生时处理该玩家的快照。装备尚未完成或实体生命周期切换时核验当前地图及玩家身份。失败的武器编号记入专服警告，备弹和 HUD 在装备发放后同步。
