# CSOL 选人与购买菜单修复

本轮按用户提供的原版截图修正选人和购买菜单，并修复主、副武器弹药只购买一包的问题。源码、专项验证和完整构建已完成，已部署专服及 B；尚未将这一批称为实机画面通过。

## 行为与资源

- 灾变玩家保持 CT 合作队伍，T／CT 页签切换的是角色库。选择、出生模型、手臂身份和技能类别共同使用选中的角色，不再按角色所属阵营拒绝 T 角色。普通 CS 的人物阵营限制保留。
- 原版选人样式每页九个角色，0 自动选择；鼠标、数字键、分页和初始定位使用同一页容量。采用用户 common 中的原字体、列表背景、键帽及头像，按截图重排标题、页签、头像、介绍和 Max Level 五属性。
- 五属性读取当前服务器同源的默认角色档案，不能冒充用户原版账号的角色改造。截图角色的 26／30／24／24／19 与本机默认档的 22／27／27／20／19 有实际差异；实时账号改造同步尚未实现。
- 购买菜单按九个分类排列，6／7 分别购买主／副武器弹药，0 退出或返回分类。装备分类包含已经实现的 CSOL 特殊主武器；尚未移植的武器不生成虚假商品。
- 右侧八个收藏位使用 S／D／F／G／Z／X／C／V。列表右键添加或取消收藏，收藏位右键移除；两个阵营分别保存在客户端归档配置中。购买仍须服务端报价与资格检查。
- 搜索使用已有匹配 SDK 的原生 VGUI TextEntry，支持文本编辑；实际中文输入法与游戏焦点仍待实测。初次打开不会主动夺取数字键，点击搜索框后才启用输入。
- 重新购买记录服务端成功回执，串行申请新交易，先武器、后装备、最后弹药。超时清空重买队列，避免前一笔回执丢失后错误消费下一笔。它不冒充原版账号仓库或全局装备系统。
- 灾变原生武器购买允许目录内的两队武器，仍保持玩家真实 CT 身份和原有购买生命周期；其他模式继续原 SDK 规则。

资源导出不再将 ver3 和 ver7 的控件静默合并。现代购买布局中原 RES 未声明的列表、八收藏位置按用户截图测量；这属于移植布局，尚未宣称与原版运行时代码逐像素一致。选人解析器兼容旧版本；新增贴图及新版 JSON 由服务器资源清单与 HTTP 分发。

## 一次买满

服务端循环调用原生 BuyAmmo，直到弹药满、钱不足、规则或玩家身份失效、原调用停止，或弹药没有进展。首轮保留余额闪烁提示；后续不重复闪烁。快照包括实际备弹和主、副武器弹匣，因此涵盖黑龙炮 clip-only 弹药以及盾牌重定向副武器。普通 buyammo1／buyammo2 的单包语义没有改动。

原生调用在同槽后续枪停止时可能返回 false，但已经补入的弹药仍算成功。钩子虚报成功而没有弹药变化时终止循环，避免卡死；重复交易号不重复扣款。
