# 全资源加载瓶颈与换图复核

原版的资源总量不能直接换算为一次换图的读取、解析、解码和纹理上传量。原 CSOL 已证实模型名称登记与专服实际模型分离、武器共用代理、模型缓存快路以及声音有效缓存复用。当前移植仍有独立的文件打开和主线程模型／SPR／纹理成本。本轮整理已完成的真实采样和隔离专服对照，没有修改生产加载策略；完整换图性能仍未通过。

F01（validated，E01／E02）：资源库很大不要求每次换图重做全部资源工作。对应路径是“登记名称 → 选择实际模型／声音记录 → 检查有效缓存或按条件加载 → 实际消费者”。这解释已确认的架构差异，不是原版与移植的完整性能归因；原版现场建服／换图的严格对照仍缺。

## 真实客户端：武器、SPR 与文件打开均有成本

E04：`build/resource-native-late-20261117-01/late-lostcity-observations.json` 和 `late-lostcity-client.json`。同一现行客户端从 deadend 到 lostcity，清单出现后才启动 35 秒主线程采样；实际首样本在换图命令后 37.525 秒。共 11,976 栈、零失败，包含校验、原生恢复和入服后的画面阶段。符号化文件 SHA-256 为 `cbc1dcd37f26ff51e09f60330bda2858b20744599e62cbeb062be6d9d82261fe`。

| 当前实际区间／工作 | 结果 |
| --- | --- |
| 新 world 且 viewReady 的首个观察 | 55.018 秒；21 个 hung 观察点，整体仍不合格 |
| 资源校验 | 3,401 项；8.551 秒；本轮 hashedBytes=0，复用已有结果，仍执行 VFS 验证 |
| openReader | 6,802 次、5.374 秒；该次数含两个验证阶段，不能等同于 6,802 个唯一文件 |
| 原生恢复 | 6.728 秒 |
| Studio 模型加载 | 274 次、2.501 秒；最慢为武器 `models/v_m249ex.mdl`，单次 53.039 毫秒 |
| SPR 模型加载 | 286 次、1.010 秒；最慢为 `sprites/ef_buffcalss24s4_skill.spr`，单次 83.488 毫秒 |
| BSP 模型路径 | 150 次、0.199 秒；含缓存访问，不能写成 150 张地图读取 |

原始主线程栈对应 `Checks → resource_overlay::Open → filesystem_stdio`、`timed_load_model`、`CSOLSupport::LoadStudio`、`Renderer::GL_LoadTexture2 / GL_UploadTexture` 和 `CSOLSupport::LoadSprite`。NtCreateFile 叶样本 2,456；模型加载包含样本 1,251，GL_LoadTexture2 包含 633，GL_UploadTexture 包含 482。包含样本可嵌套，不可相加为独立耗时或当作 GPU 时间；主线程挂起取栈也不是 ETW。35 秒进程 CPU 增量 30.172 秒、ReadTransferCount 增量 256,609,747 字节，均不等于物理磁盘读取量。

F02（validated，E04）：继续只优化人物不能覆盖当前加载热点。文件访问在校验和原生消费中都有成本，武器 Studio 与 SPR 的实际恢复／纹理路径同样需要处理。对应生产路径是 `native/client/resource_overlay.cpp`、`resource_update.cpp`、`precache_client.cpp`、CSOLSupport 资源加载和 Renderer 模型／纹理消费者。本轮没有改这些路径，也没有把等待移到首次攻击。

本轮没有部署新的 RLE／文件系统候选。55.018 秒与此前另一地图的 73.750 秒受地图、缓存预热和共享主机负载影响，不能归因于未部署的代码，也不构成同条件 A/B。
