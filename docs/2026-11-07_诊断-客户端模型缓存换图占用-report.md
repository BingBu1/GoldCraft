## 身份及读取契约

宿主 `hw.dll` SHA-256 为 `9ba9a2db5e07598fd59afa35507a98c86162e4e15b3835177b78c11842cd2295`。工具核沙盒路径、磁盘 SHA、运行 RSDS，实际地址使用枚举到的模块基址加 RVA。依据是该精确 PE 的原字节、LLVM 反汇编与已有匹配 PDB/宿主符号目录，**不是新增原版 CSOL IDA 取证**。这里只读诊断，不以此改变 CSOL 还原行为。

私有窄证据为 `analysis/map-transition-active-20261107/client-cache/hw-cache-layout-pe-evidence.json`，SHA `456cfaca1c08800357ace380a546960e1d06ff8fdaf850cca71a63c7b1fbba75`。父代理重新从目标 PE 校验其中六个函数的全部字节与范围 SHA，无差异。

| 项目 | RVA 或节点内偏移 |
|---|---|
| cache_head | RVA `0xf6adc0` |
| hunk high / low / size / base | RVA `0xf6ae20 / 0xf6ae24 / 0xf6ae28 / 0xf6ae2c` |
| 节点头大小 | `0x58` 字节 |
| 块大小 / owner / 名称 | `+0 / +4 / +8`，名称最多64字节 |
| 普通链 prev / next | `+0x48 / +0x4c` |
| LRU 链 prev / next | `+0x50 / +0x54` |

`Cache_Alloc`（RVA `0x237d60`）以 `(requested + 0x67) & ~0xf` 分配，节点大小包含头和对齐。`*owner == node + 0x58`，不能把节点地址当模型数据地址。可用容量是 `hunkSize - low - high`；占用必须遍历分配链求和。

工具检查范围、节点上限、普通链顺序和互链、LRU成员和互链、owner反向指针，并再次读取全部头和全局。任何不一致都保留为拒收样本；不修补数据，不暂停游戏。双读仍不能排除ABA变化，不能声称原子快照，也不能把节点消失直接标为LRU淘汰。

运行 `Cache_Alloc` 已跳转到 CSOLSupport 的 owner 包装器。匹配 PE/PDB 与 trampoline 核实它最终返回宿主分配器，包装器没有另一套缓存预算。窄证据 `csol-cachealloc-wrapper-evidence.json` 位于同目录，SHA `eb7fbd9e8bceea29b7d2a265144dadfbdbd6986e2ff003f78f147705b5644629`。宿主分配失败分支依次选 LRU 尾、释放其 owner、重试分配；这说明存在容量淘汰路径，不证明本次每一次释放都走它。

## 单 B 实际换图

PID37384 保持同 DLL，专服保持 5f869363 引擎。后台只读采样45秒、间隔250毫秒，同时执行 `zs_2gate → zs_trap`。原生 HUD 后续回调恢复为 **24.484秒**，最大状态报告间隙7.917秒。采样期间没有编译；后台采样本身仍有开销，不能将本轮与无采样结果作为严格提速对照，也未完成前台画面验收。

- `build/map-transition/cache-transition.json`：180样本，124一致、56拒收。SHA `c40bcb0c893d92efc91a68b85132c18c15838fc8506c03ae229fe7192f53021b`。
- 拒收原因：40次LRU互链变化、10次节点双读变化、4次全局/链头变化、2次尾变化；全部保留。
- 单次读取最长25.457毫秒；这是采样程序墙钟耗时，不能当作游戏被暂停的时长。
- `build/map-transition/cache-client.json` 保留实际重连、epoch、清单及原生HUD窗口证据。

实际 hunk 为256 MiB；换图期间一致样本中的模型/声音缓存占用常在约224–242 MiB。末段97节点占用238.20 MiB，剩余12.23 MiB；最大的数个角色模型块约7–8 MiB。不要套用专服80 MiB缓存的结构或计数器。

采样器 `startedMonotonicSeconds=18524.8204638`，换图观察器为 `18535.7108554`，相差10.8903916秒。以下时间均按 `cache sample.seconds + cache.startedMonotonicSeconds - map.startedMonotonicSeconds` 对齐到换图观察器起点，不是缓存JSON中原始的 `seconds`。

同一个 `models/player/csol89/csol89.mdl` owner 在9.152秒样本缺席、10.656秒重新出现，17.170秒缺席、20.427秒重现，21.678秒缺席、22.179秒重现，重现时数据块地址变化。K3也出现相同owner消失和重建。以上时间是**采样时间**，不是捕获的释放调用时刻；样本之间可能漏掉更短生命周期。

这组证据闭合了“相同名称可能属于不同模型对象”的一个疑点：至少这些例子是**同一 owner 的数据块多次变化**。容量压力与重复重建值得优先处理；尚未捕获释放调用栈，仍须区分正常换图清理、hunk搬迁和LRU淘汰。
