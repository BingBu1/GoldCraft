## 实际接线

实际运行源码从 `client/scenario/bosses/teddy_sparks.cpp/.hpp` 移到
`client/scenario/core/particle_effects.cpp/.hpp`；保留原位源码与 Git 历史，不复制源树。
`TemporaryPool` 的一个实例承载两类 emitter，`OrdinaryPool` 的一个实例承载两类 particle，
不再各自享有 128/1200 配额。已有严格 decoder 和纯 Spawn/Tick/Corners 继续使用。

发射仍由实际 UpdateClientData 回调调度，更新/退役/距离排序绘制在透明阶段。
黑洞保持 mode4、RGB150/alpha40、36 环记录、5 次发射与原碰撞路径；火花保持 additive。
溢出时继续消耗剩余环形 RNG，但不加载被拒绝记录的资源；工厂失败先消费当前次数，
随后结束整个发射 pass。资源查询仅在 Add，通过引擎原资源缓存处理。

精确数学接口在冷初始化解析原版指定的两个系统 CRT 导出；常规消息不查导出表，
逐帧不加载库。宿主插件退出时释放自己持有的引用；地图/场景清理不卸载 CRT。
这是宿主 DLL 生命周期适配，不宣称复刻原游戏全局析构结构。

摄像机不再混用普通池缓存：当前原生客户端的观察状态、render 和 chase 向量通过
三项 SHA/CRC 匹配符号获取。地址只进入已校验目录生成器，运行代码不硬编码偏移。
`tools/Build-ClientGameData.py` 已检查三观察字段的真实写入及两组视角向量的引用字节。
普通 CSOL VXL 剧情摄像机和原模式 53 的特殊 provider 尚未接到原生宿主，明确保留为
完整目标缺口；本轮普通游戏/观察分支证据不延伸到这些 provider。

实际数学库由 32 位进程打开模块文件句柄，再取最终路径，避免 64 位 Python 把
`System32` 重定向路径误读成 x64 文件。当前实际加载的 x86 ucrtbase 身份及导出 RVA
已记入原环回执，未把本机 CRT 版本说成原游戏安装的相同版本。
math 行协议输出 uint64 位模式，解析器必须保留整数精度。

精确暂存的 plugin/scene 另经 stdin 编译通过，5 项已测核心暂存 blob 与实际 SDK 输入
核同；精确暂存的目录生成器也从 stdin 执行，输出 50 项 / 3 新别名。工作区 52 项
还包含另一个领域未发布的 2 项 CoF 定义，本次未混入；没有复制最小源树冒充完整 HEAD 链接。

初版将 per-particle camera 误接普通池缓存，完整构建 `166ce300…` 在发布和部署前明确作废；
没有用其 SDK 通过替代原 getter 证据。新绑定完成后最终回执为 full02，DLL 完整 SHA-256
`d9d2dd58b584ddb397381cc1a99c101becf791b0d4cf2c272fe646c052eb367a`。
完整编译来自当前混合工作区，不表示拆分公开 HEAD 已具备其他域完整发布闭包。
其他保留失败包括直接初始化测试 Particle 漏设 Spawn 朝向、WOW64 文件身份误读、
夹具的 SDK 状态枚举拼写错误和原指令白名单长度错误；详见私有 `failed-checks.md`。
没有为通过这些失败删除生产碰撞、绘制或消息门。
