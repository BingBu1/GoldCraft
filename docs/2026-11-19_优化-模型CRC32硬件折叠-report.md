# 模型 CRC32 硬件折叠

同源 ReHLDS 隔离专服在 `zs_deadend` 切到 `zs_lostcity` 时，520 次完整模型 CRC 的平均耗时由 0.647 秒降到 0.117 秒。四轮整段换图结果的范围重叠。此次验收覆盖 CRC 计算和隔离专服准入、换图及 HTTP。

## 原版接口与代码

原版 CSOL `hw.dll` 样本为 x86，基址 `0x37100000`，SHA-256 `c7bddfda93c2e0877ea126a15a318b83cce74c59bb95e38a7301b08033ac7783`。编写前核验其 9 个 IDA 区段共 3,694 字节，包括 Init `0x37867ED0`、ProcessBuffer `0x37867EF0`、Final `0x378680C0`、表 `0x3809F170` 及模型调用链。它使用反射 IEEE `0xEDB88320` 并支持未取反状态的分段累积。Steam HL10210 的客户端接口另按已经核验的宿主调用符号和样本 `9ba9a2db5e07598fd59afa35507a98c86162e4e15b3835177b78c11842cd2295` 比对。[原版接口取证](2026-11-07_取证-CSOL引擎CRC32与宿主模型校验边界-report.md) · [客户端适配证据](2026-11-07_优化-客户端完整CRC等价计算-report.md)

`native/engine/crc32_ieee.h` 用 PCLMULQDQ 折叠完整缓冲区并做 Barrett 约简，常量由 IEEE 多项式在编译期推导。CPU 支持时对至少 64 字节的输入使用硬件路径，其余输入及末尾不足 16 字节的数据使用八表算法。模型加载仍对全部字节计算同一未取反状态，再由原调用者终结 CRC。ReHLDS 和现有 CSOLSupport `ProcessHostCrc` 适配共用这个头文件，Steam 宿主的负长度请求仍委托原回调。

## 构建与回归

- ReHLDS 基线与候选均完成 x86 全量构建。3,199 项输入中仅 CRC 头文件有差异，111 个引擎链接对象中仅 `crc.obj` 有差异，静态库一致。两版实载引擎与 PDB SHA 前缀分别为 `2b8928460360` / `07fb9e3c97fc` 和 `c7f2fec72098` / `7704df9c6c96`。
- 服务端 445,613 项通过，覆盖原回调、八表算法、硬件分派、zlib、分段、输出别名、保护页，以及 150 个模型和字节变更。已读入内存的 150 个模型每轮耗时约 0.54 秒降到 0.09 秒。
- 客户端共享计算通过原指令与生产适配 75,615 项检查。单独编译的实际 `model_crc.cpp` 通过启用与禁用两组 SDK 编译和运行。此阶段客户端验证到组件与接线层。

准入复核先遇到隔离基线 RCON 认证失败，改为专用控制台。随后采集器等待缓冲日志和使用预填 HTTP 端口分别失败，改为解析实时控制台并核对实际 TCP 监听进程后完成四轮。失败记录、正常退出及回滚留在 `build/crc-pclmul-20261119`，有效对照为 `transition-04-baseline` 至 `transition-07-baseline`。四轮退出后均校验恢复隔离文件，主测试服二进制前后一致。六份原始采样压缩前后的文件大小由约 1,069 MB 降至 114 MB，解压数据的 SHA-256 逐份核对，归档回执为 `raw-archives.json`。
