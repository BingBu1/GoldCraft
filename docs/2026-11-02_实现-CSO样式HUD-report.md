## 已有证据

- 原 CSO client.dll 的 SHA-256 为 `f4145136edbd229c219ea793bb3a6dcacea0b406ccc1e610138abbb8063bcbfd`。IDA 只打开工作区独立副本，原 DLL/原 IDB 前后哈希保持；工具关闭时保存只作用于研究副本。
- `0x2AA2BE0` 加载人物与武器底图；`0x2A9C130` 直接调用面板绘制方法 `0x2A9F6D0`。30 段共 3,134 字节的 IDA 读取与原 PE 一致。反编译存在 positive-SP 警告，因此参数和分支以汇编为依据。
- 人物底板使用 `(0,H-93,288,85)`，武器底板使用 `(W-288,H-84,288,76)`，共同留 8 单位底边；头像为 `(0,H-156,99,116)`，方形头像另有 UV 裁剪。面板颜色设置为白色、alpha 225。这些是原版逻辑坐标，整体屏幕缩放仍需继续核对。
- 原版数字、生命/护甲和武器图标来自 SPR，不能全部按普通透明 TGA 绘制。候选将其拆分为 HL25 additive 绘制，底图与头像保持普通 alpha。资源转换的 285,088 像素数学校验误差不超过 1 字节；这不是 GPU 验收。
- 当前资源方案包含 34 把武器和 149 个原版 HUD 头像，共 230 文件。角色 39/40 没有对应原版头像，明确保留缺失。普通武器的 common 表与图集有版本错配，已使用 B 客户端实际成对表/图集，名称仍取 CSO 本地化；不宣称这部分轮廓均来自 CSO。

## 源码改动

`native/csol/hud_style.*` 定义资源目录、宽生命/护甲状态和布局；`native/csol/client/hud_style.*` 负责预加载、字体、图像、生命观察消息及 VGUI 绘制。资源未就绪、无可用根 panel 或不支持 additive 的引擎保留旧 HUD。十个数字纹理在准备阶段生成，绘制路径不解码资源。

武器状态来自实际活动编号以及相匹配的预测快照。飞刀显示总数，普通枪和御天绝影保留其真实弹夹/备弹语义，不把截图中的百分比套给所有武器。切至普通武器后，陈旧的充能枪快照不能继续绘制瞄准框。

原版生命数字抑制按图标起点、数字格位、真实值和绘制顺序消费，避免宽生命越过半屏时残留，或误吞同图集的时钟/钱数。服务端读取同一目录计算预缓存闭包；可选 HUD 目录缺失不新增拒绝入服条件。
