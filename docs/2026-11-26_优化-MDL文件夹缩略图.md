# Windows 文件夹中的 GoldSrc MDL 缩略图

资源管理器使用 crskycode 的 GoldSrc Model Thumbnail Provider。已装 x64 DLL 与上游 v1.0.0 发行文件的完整 SHA-256 均为 `e42bf275201dfef62289d64f390b947cd9a8d3f039df631f976d3ad87e37a209`。上游源码固定在 `3b615efb8b4d93370f69ea434d827510ab959015`。 [原项目](https://github.com/crskycode/GoldSrcModelThumbnailProvider)

在该版本上应用 [性能补丁](../patches/goldsrc-model-thumbnail-performance.patch)，即可打开原来的 `GoldSrcModelThumbnailProvider.sln`，也可以使用补丁内的 CMake 工程构建 x64 版本。当前 Windows 主机使用 Visual Studio 2026 和 Windows SDK。

```sh
cmake -S . -B out -A x64
cmake --build out --config Release
```

## 大目录耗时

取一个实际包含 83 个 MDL 的文件夹，以 256 像素调用 Windows 默认的 `IThumbnailCache`，强制逐个生成缩略图并读取返回的位图。测试不向系统缩略图缓存写入结果。表内计时覆盖这批缩略图提取及像素读取，文件夹枚举和窗口排版在计时范围之外。

| 同目录、同机、同尺寸 | 共 83 张 | 单张中位数 |
| --- | ---: | ---: |
| 已安装的 v1.0.0 | 16.626 秒 | 184.1 毫秒 |
| 更新并安装后，第 1 次 | 1.923 秒 | 11.4 毫秒 |
| 第 2 次 | 1.833 秒 | 10.6 毫秒 |
| 第 3 次 | 1.821 秒 | 10.4 毫秒 |

旧版真实渲染的阶段计时显示，每张平均花 153.71 毫秒初始化 D3D，19.40 毫秒销毁，20.53 毫秒加载模型。加计时的旧版与已安装发行版的 83 张图逐像素一致。

新版在同一宿主进程内复用一套 D3D11 设备、着色器、管线状态和当前尺寸的绘制与回读纹理。多个 COM 单元可同时解析模型，立即上下文的绘制按序执行。顶点按与旧版相同的几何属性建立哈希索引，保留首次顶点的骨骼选择和图元顺序。单个模型的 GPU 绑定在画完后释放。活动的预览对象持有模块引用，COM 查询可卸载时回收空闲设备。

## 画面和安装验证

83 张武器缩略图在三次 Windows 默认宿主测试中与旧版逐张核同。另用四个 COM 单元交错请求三种尺寸，共 36 张人物和碎块图，再测混合目录的 121 项。共计 240 个文件与尺寸组合，其中 237 项的尺寸、像素及直连返回的透明度类型一致，3 个原版不支持的版本返回相同的失败结果。还验证了三轮卸载后重建，以及请求不存在的文件后继续显示正确图像。 [Windows 对照工具](../tests/mdl-thumbnail/verify.py)

本机在原注册路径替换了 x64 DLL。第一轮 DLL 的 SHA-256 为 `35d9cf87c69c03370caedde8efc80e8d31832aea97dc18c526932cf0857dc7ce`。原件在同目录的 `GoldSrcModelThumbnailProvider64.dll.v1.0.0.bak`。安装后由 COM 激活确认模块路径和文件哈希。逐文件结果和安装记录位于工作区 `build/mdl-thumbnail`。

## 包含大量子文件夹的模型下载目录

第二轮使用资源管理器实际显示的尺寸。下载目录顶层有 1,027 项，其中包括 343 个子文件夹和 643 个 MDL。96 像素缓存初查命中 262 张文件夹封面，另外 81 张在一次正常 Shell 请求中合计用了 35.306 秒。同期 632 个独立的 v10 模型已有预览，另外 8 个是独立序列文件，3 个是提供程序尚不支持的 v20/v21。两类文件的返回结果均已逐个核对。

Windows 为一个小文件夹封面通常会挑两个子模型。用相同模型的独立副本追踪时，Shell 对这两个文件发出 2560 像素的普通缩略图请求，与主动索取大图时的尺寸和上下文相同。六个全新目录的实验中，如果子模型已经有 256 像素缓存，Shell 可以复用小图合成封面。

提供程序将模型和遮罩纹理绘制到固定背景上，最终位图每个像素的 alpha 都是 255。第二轮按这一实际格式返回 `WTSAT_RGB`，让 Windows 可以使用不透明图的缓存路径。单独请求 2560 像素仍返回完整尺寸。

| 同一批 6 个全新子目录，在 Windows 默认宿主提取 96 像素封面 | 第一次 | 换全新目录重复 |
| --- | ---: | ---: |
| 第一轮插件 | 3.181 秒 | 3.149 秒 |
| 第二轮插件 | 1.302 秒 | 1.257 秒 |

每批六个目录的 42 个 MDL 均从工作区样本独立复制，首轮开始前逐个查询并确认系统缓存未命中。新版的六张 96 像素缓存封面与旧版逐像素相同。顶层 643 项在两版默认宿主强制提取时，632 张位图逐像素相同，11 项返回相同错误。另测四个模型的 256 和 2560 像素原始输出，八张位图全部一致。Windows 将大图写入系统缓存后，三张 2560 像素缓存图存在轻微编码差异，抽样每色道平均绝对误差为 0.40～1.30（0～255）。

已通过普通系统接口补齐本机两个目录的封面。新进程按同样尺寸再次读取时，顶层 343 张封面合计 0.284 秒，643 个 MDL 请求合计 0.493 秒。`player` 的 423 张封面全部命中 256 像素缓存，重复读取合计 0.509 秒。独立的 Windows 文件夹视图以相同图标尺寸三次打开实际路径，顶层列齐 1,027 项用了 0.273～0.431 秒，`player` 列齐 424 项用了 0.315～0.352 秒。视图计时截至可取到最后一项。用户窗口的最终绘制时间未采集。

目录缓存对照工具默认只统计已有缓存，`--fill` 通过 Windows 默认接口生成缺图。 [目录缓存对照工具](../tests/mdl-thumbnail/folder_cache.py)

第二轮 x64 安装件的 SHA-256 为 `0f295183b4ebf40d4493918c831b893a9f1fc624bf8357b63780ec9852986be1`。已从实际 COM 对象核对加载路径和哈希。上一版留在同目录的 `GoldSrcModelThumbnailProvider64.dll.35d9cf87.bak`。
