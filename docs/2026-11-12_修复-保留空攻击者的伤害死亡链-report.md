# 保留空攻击者的伤害与死亡链

宿主现在能将空攻击者保留为NULL，完成真实玩家伤害、死亡和胜负处理，
不把它改成世界/礼盒/替代玩家，也不为不存在的攻击者修改分数或发奖励。
正常玩家与真实world实体的原非NULL行为保持，并有实际执行对照。

这是明确的宿主安全适配：原CSOL的NULL+Gift路径会读空地址，
不能把本修复称为原版定义了world回退。原MP SHA-256为
`39f962f34816411e615f01e5279d914204f7fd07c5a5112b0b303acafe0308b2`，x86/base10000000。
原玩家TakeDamage `114F42B0` 在 `114F45A9` 读NULL+1C8；原Killed `114DDBF0`
在 `114DDDEC` 再读NULL+238；base lethal没有把NULL改成world。
2169条新增IDA/raw及复用4389条完整玩家体，7个有界原指令案例核对；不声称执行过完整原游戏进程。

| 真实源码 | 修改与理由 |
|---|---|
| ReGameDLL `player.cpp` | nullable Instance/ENT/GetClassPtr只在存在时调用；NULL不创建新edict，不进入玩家攻击者专属逻辑；保留victim真实伤害/死亡 |
| ReGameDLL `multiplay_gamerules.cpp` | NULL不写killer.frags，死亡提示/日志/director/观察目标使用明确空值；原非NULL分支保留 |
| `native/server/native_armor_commit.inc` | 两处career攻击者解析使用同样空值规则，保持护甲提交行为 |
| ReAPI `hook_callback.cpp` | TakeDamage、Killed、FPlayerCanTakeDamage、PlayerKilled、DeathNotice五wrapper使用已有AMX_NULLENT=-1转换，插件-1仍返回NULL |

ReAPI现有PEV/getPrivate(-1)、成员getter/setter和活动Ham转换已经安全，未凭猜测修改。
DeathMsg协议killer byte0与hook里的NULL/-1是不同层，不借协议0伪造一个world攻击者。
上游版本由现有sources.lock固定，原始第三方树不随本修复发布；变化通过source-only补丁交付。
