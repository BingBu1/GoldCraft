# 僵尸炸弹怪绿色：原版客户端颜色调制链已定位（尚未实施修复）

本报告更正 [早期绿色调查](2026-11-06_分析-僵尸炸弹怪绿色着色-report.md) 的推断，保留旧稿作为调查历史。原版确实存在 **普通工作室模型读取 rendercolor，并通过 SharedDataMgr 将 RGB/255 乘入绘制照明** 的路径；不需要给技能 6 怪物强制 renderfx，也不是更换绿色皮肤。

本批仅分析复制的原模块、读取原资源及当前源码、执行有界原指令 oracle。没有修改生产代码、共享四文档、运行配置或 Git，没有编译、部署、启动游戏或干预现有游戏进程。新增文件位于本报告及 `analysis/csol-model-20261017/scenario/skill6-green-20261106/`，后者不在源码发布范围。

## 已定位的颜色路径

### 1. 原服务器只需发送已有颜色

MP `11399E40`（RVA `1399E40`）从怪物实例 `+12EC` 的类型记录取 `+20/+24/+28`，写 pev `+168/+16C/+170`；`+64/+68/+6C` 分别写 mode、fx、amount。失落之城技能 6 的 `80,228,91` 继续沿原工厂路径发送，不能额外赋一个“让绿色生效”的 fx。

`1140B740` 中 ESI 是 edict，entvars 位于 `edict+84`。因此 `1140BE5C–1140BE7A` 的 `[esi+1EC/+1F0/+1F4]` 对应 pev `+168/+16C/+170`，经 CVTTSS2SI 再取低字节写 state `+5C/+5D/+5E`。旧稿直接把 ESI 偏移称作 pev 偏移不准确。mode/fx/amount 也是同一 edict 基址换算。

`1140BB6D–1140BBB2` 识别 `monster_entity` 后设 state.entity_type=3，但下面颜色提交分支没有要求 entity_type=3；这一类型标签不能代替颜色消费证据。

### 2. 客户端每次绘制提交 RGB/255

`02A45570` 调用 `02ACA500`（RVA `11CA500`，函数内含原 `StudioModelRenderer.cpp` 源路径字面量）。`02ACA597` 获取当前实体并保存到 renderer+30；`02ACA5A0` 获取视图模型，另调用实体分类回调 `3AE90C0`，二者合成分流条件。

在非视图模型/该分类回调为假的通路，`02ACA637–02ACA6BC`：

1. 读当前实体 `+330/+331/+332`，即 curstate `+2D4` 加 state.color `+5C`。
2. RGB 全零时跳过本次 setter；不是把模型染黑。
3. 否则以单精度各除 `02FB2EBC = 255.0f`，调用接口 `vtable+1A8`，参数为 `(r/255,g/255,b/255,false,false)`。
4. 这段没有 rendermode 或 renderfx 判断。mode49/51 的前置分流也会把非视图模型送回该提交点；当前 mode15 同样走该分支。

正常绘制尾 `02ACB9BC–02ACB9E8` 调同一接口复位 `(1,1,1,false,false)`；其他已见提前返回处 `02ACAA1F–02ACAA47`、`02ACB024–02ACB050` 也复位。没有宣称全函数所有早退都复位：例如 LOD 距离分支 `02ACAC7D/80 → 02ACB9E8` 可绕过该尾。当前报告验证的是可见普通模型的提交、消费者及正常复位，不能用它伪造完整异常/LOD 生命周期验收。

视图模型进入 `02ACA8EF` 的不同分支，读取另外的 fx/颜色状态；本批不把世界怪物的调制规则扩大为修改所有第一人称武器。

### 3. SharedDataMgr 到实际照明乘法

client 初始化 `02A2D703–02A2D708` 将引擎表拷到 `03AE8DA8`。其 `+26C = 03AE9014` 对应 HW 表 `382FEBC0+26C` 的 `37A6A930`，返回单例 `39413D28`；构造 `37A21CE0` 在 `37A21DB1` 写最终虚表 `380E5238`。该表 `+1A8` 的原指针为 `37A5E580`（RVA `95E580`）。

setter 写：

- RGB 浮点 → `3830778C / 38307790 / 38307794`；
- 第四、第五个布尔参数 → `39257970 / 39257974`。

这不是仅存档不用的状态。原 HW `378E5070` 中，在 `39257970==0` 时，`378E55A1–378E55E5` 逐通道执行：

```text
vertexColor[c] = scalarLighting × lightColor[c] × modelTint[c]
```

其中 scalarLighting 已由前面的 `378EA080` 产生，lightColor 在 `39A57C10/+4/+8`；最后系数即 setter 的三个全局。第四参数非零的另一分支直接使用 tint。client 绿色路径明确传 false。

硬件参数路径 `37ACBEF0`（RVA `9CBEF0`）在普通模式/无特殊覆盖时，`37ACC299–37ACC2D9` 同样生成 `lightColor[c] × modelTint[c]`。前面的 fx22/23、特殊材质、mode5 等有各自分流，不能把特殊路径的白色默认当作整台渲染器最终不读颜色。

技能6绿色的单精度系数是 `0.3137255013,0.8941176534,0.3568627536`。这证明了普通模式颜色乘法，但不单独证明本工程 GLSL 与原版完整 gamma/PBR/渲染目标处理等价。原指令是在已有照明求值后乘系数；接入当前 shader 时需明确所在色域，不能凭本报告把 tint 随意放到 `pow(lightColor*lv, exponent)` 内或外。

## 对旧候选和皮肤假说的排除

`11397E50`（RVA `1397E50`）确实写 pev+174，但唯一已知 direct call `1138AAE4` 位于 `1138A980`：先创建 `zsht_item_box`，用引擎 edict→index 的返回值作参数，并设对象+ C8=now+30。其上游 `1138A520 → 1138A980` 还存在 mode28 与条目字段>=1000 门。这不是普通技能6僵尸着色链，不能因字段名相同就调用它。

旧候选 `113E15F0` 是真实函数 `113E15E0`（RVA `13E15E0`）内部。两个 callsite `113E0066` 和 `113E295C` 分别位于 `113DF1D0`、`113E24C0`。两处实际参数完全相同：`(mode0,255,255,255,unused0,fx0)`，不是绿色。六参中的第五参在该函数没有被消费，不能自行补写 renderamt。

普通技能6分派为 `113F0970 → case6@113F0F06 → 113F1460 → 114ADA10`，随后写 active/cooldown 时钟。已检查该分派分支和完整800字节 throw helper，无上述两个 setter 的调用，也无该 helper 直接写 mode/color/fx；这一结论限于已跟踪分支，非全库绝无其他修改的证明。

## 撤回、验证级别及接入边界

明确撤回旧稿的这些断言：

- “原版必然在普通模式乘色”曾只是推断；现在由以上 IDA setter→消费者证据重新建立，不能沿用旧推断作为依据。
- “普通mode0/fx0为白，故绿色不来自rendercolor”不成立：旧扫描遗漏了 client→SharedDataMgr→HW 全局乘数这一间接通路。
- curstate+2EC、color+348 的布局已错；本链使用 +2D4、+330。
- `113E15F0` 不是独立函数入口；`11397E50` 不能当普通怪 setter。
- “继续找绿色skin或更改默认renderfx”不是当前正确修复方向。

源代码映射：`native/csol/server/scenario_monster_factory.cpp` 已发送类型颜色；缺口在 `native/csol/client/scene.cpp` 的 `DrawAsset` 和当前 shader/各绘制阶段的颜色传递。现 `DrawAsset` 只提交 `state.lightColor` 与 `EvaluateMaterial` 颜色，没有上述普通实体调制。接线应以实体已有颜色作每次绘制输入，确保 opaque prepass/post-scene 均获得本实体系数，黑色三零默认保持白、换实体/换图不串色；不要改 server 默认 fx，不要把 skill6 本身写成固定绿色的特例。

验证分开记录：

- 原版静态 IDA：已定位 setter、调用者、两条真实消费者、正常尾复位；原字节与样本匹配。
- 原指令自动验证：`python analysis/csol-model-20261017/scenario/skill6-green-20261106/original_tint_oracle.py`，24窗口逐字节核验，20组合全通过，覆盖绿色、全零、白色、单通道及另一表色，两种lightColor和两种scalarLighting，mode0/fx0。
- 生产修复/编译/GPU测试/实服画面：本批均未做。没有把20例原指令执行说成20例游戏或GPU验收。
- 尚未闭合：原完整着色/色域与当前GLSL的逐阶段对应、shader特殊材质和viewmodel规则全覆盖、可见怪物实际输出及与同场普通白色怪物的对比。
