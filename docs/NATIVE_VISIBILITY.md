# 隐身药水同步

隐身由 MC 服务端实际效果表决定。CS 身体代理为避免重复绘制而永久隐藏，这个标志不能作为药水状态。独立 `NativeVisibility` 模块读取当前效果所有者，并把药水状态单独同步给 CS 和 MC 客户端。

原生服务端在 `AddToFullPack` 生成玩家显示状态后，将隐身身体设为透明，清除该身体的发光渲染效果；模型、碰撞、移动和伤害实体仍保留。它不修改实体原始渲染配置，药水取消或状态失效后，下一份快照自然恢复当时的游戏/插件显示设置。MC 形态的真实 MC 模型、装备和持物继续由原版渲染处理。

通道使用协议30的可选能力8192、消息89。固定36字节携带世界、修订、槽位、连接、出生、生命和隐身标记，只接受已认证的服务端角色。状态租约350ms；重复包不续期，重生、换连接、换世界、死亡及断链失效。每次更新也发送非隐身状态，避免等待租约才恢复。旧原生服务端可逐级降级握手，图形客户端不能申请该能力。

MC 的原生玩家代理独立同步药水隐身字段，Epic 的目标获取和保留使用它；原版生物看到的逻辑玩家从当前效果所有者读取隐身。视觉隐藏不取消攻击命中，也不把全部生物的目标强行清空。

验证：生产 Clang x86 客户端/ReGameDLL 和 NeoForge JAR 构建成功；304项JUnit、6组原生回归通过。隐身部分包括57项生产原生消费者/租约检查、76项生产Java发布器检查及真实TCP能力协商/降级/重连。原生消费者执行真实函数，检查真实 `AddToFullPack` 接线；引擎身份/数据与Java世界使用观察适配器，不能当作真人画面或生物AI实测。ReGameDLL补丁从固定上游回放16文件一致。

已加入本地联合部署。仍需真人验证双形态隐身/到期、装备显示、Epic锁定和生物感知、重生/重连以及其他插件叠加。夜视、失明、黑暗等剩余效果见[完整审计](STATUS_EFFECT_COVERAGE.md)，本项不代表39种效果全部完成。
