## 消费者及适配边界

`round_settings.cpp::ReadRoundSettings` 与 `monster_attributes.cpp::ReadRoundMonsterDeltas` 只校验 `headerRecord==6`、`recordIndex==index+7`，随后按原始固定列读取，不依赖表头名。它们适用于本次服务模式 15 的 Chaos 数据；原服务模式 48 的 metadata 处理不同，不能因为行布局相同就宣称完整模式已支持。其他服务模式起始行 6 可由新读取器保存，但现有设置消费者仍会明确拒绝，未适配部分不绕过。

`RoundRow.round` 在 native 实际消费者中仅用于 `FindMissingReferences` 的诊断，不是物理房间索引。新 API 不解析原版忽略的列 0：该成员保持值初始化的 0，并明确不代表有效编号；真实标签须从 `source.records[recordIndex].fields[0]` 读取。非数字、重复、乱序列 0 不新增拒绝门。现有命名列 API 仍保留原诊断编号语义。

`FindMissingReferences` 检查普通 round→wave；Chaos 列 1 是 trigger group ID，不能直接据此函数拒绝 Chaos。路线/TRG/WAVE 的验证由路线层承担，本阶段只验证诊断溯源边界，不猜写新引用逻辑。

安全适配：不足起始物理行、整表没有列 1、损坏 CSV、超限文件/字段以及原数字扫描失败均保留上一次完整输出。起始行后的空记录不删除。无记录的合法表仍输出空 rows，后续需要房间的路线入口已有独立数量门。
