# 修复：奥伯恩音效重复与死亡后持续播放死亡音效

用户报告（2026-11-04）：奥伯恩 BOSS 音效会重复触发，死亡后一直播放死亡音效。原始候选及二进制证据由 Claude 领域会话交接；GPT 已审计并补齐实际 studio 上下文与清理边界，完整构建、部署与实机继续核收。原 `scene.cpp` 的 `csol_studio_sound_diagnostics` 诊断保留，新增 `suppressedEvents` 计数。

## 原因（原生二进制证据，只读 PE + capstone，未打开任何 IDB）

1. 奥伯恩模型 `models/monster/zbs_bossL_big02.mdl`：`death`（序列20）**不循环**、301帧/30fps，第1帧有事件 5005 `300zombi/oberon/death.wav`；攻击序列同样不循环，第1帧带 5005 音效（如 `zbs_attack3` 1/66 帧、`zbs_attack_bomb` 44/88/133 帧）。解析脚本 `build/oberon-sound-20261104/mdl_events.py`。
2. 引擎客户端事件分派（沙盒 hw `101F1258..101F12F6`；原版 CSO hw `378DF066..378DF092` 完全同构）：`end`=估计帧，`start`=end−本帧推进量；**若 `latched.sequencetime == curstate.animtime` 且序列不循环，`start` 被重置为 −0.01**，随后所有 ≥5000 且 `start < frame ≤ end` 的事件都分派给客户端。
3. 序列切换时引擎把 `latched.sequencetime` 设为当时的 `animtime`（沙盒 hw `101F6146`、`101FA0BE`）。因此只要服务端不再推进 `animtime`，非循环序列里已经过的事件会**每个渲染帧重放**。
4. 死亡后本项目按原 MP（`1137D095..1137D1AC`）安装截止时刻的 `FreeThink`，奥伯恩外观死亡时长 60 秒，期间不再 Think、`animtime` 冻结 → 客户端 5005 每帧重放 `death.wav`（模型复现：60 秒约 5800 次）。存活时新攻击序列开始到下一次 `animtime` 更新之间也会重放第1帧音效。
5. 原版 client `HUD_StudioEvent` 开头调用 `02A40050`：按（实体号、事件号、事件记录指针）去重，窗口 1/30 秒（常量 `03199940`）。该窗口只能消除一次服务端 Think 间隔内的重放，**不能**阻止 60 秒冻结期间每 1/30 秒再放一次，故不照搬为唯一方案。

## 实机攻击反例与后续修正

主代理部署第一版后，单 B 记录到同实体、同 `sequence=6` 的第 1 帧 `attack1.wav` 在网络帧从 3 推进到 9 时再次播放：`animtime` 与 `sequencetime` 同时从 250.63 改为 250.69，音频调用进出均已执行（`phase=3`）。冻结记录 `build/oberon-sound-20261104/replay-observed-01/client-diagnostic.json` 的 SHA 为 `7a0680e4f5628af66939713f96696e9790a29eeeacffc3a3fb93c9a78dff7ce0`。因此第一版“animtime 改变就是新的动作”假设不足，旧 46 项通过不能作为最终验收。

后续修正使用 `STUDIO_EVENTS` 绘制时的网络帧观察：同模型/序列的帧向前推进不清记录；较新网络姿态出现帧回退时才开始新的一次动作。无音效的中间绘制帧也被观察，以保留连续两次同序列攻击。viewmodel 的网络帧通常保持 0，故仍以其动画起始时间辨别新一轮开火，避免影响原版枪械。循环动作退掉旧状态，反向播放不使用正播守卫；普通窗口发出的首个事件也登记，以防随后网络重置窗口再次投递。

- `context-live-02`：真实 SDK 与生产观察/守卫入口 35 项、0 失败，包括上述实机的帧 3→9 时间重写、后续帧 121、同序列重播、同 animtime 的新包帧回退、正常首发后进入重置窗口、viewmodel 连射、循环间隔和纯绘制 pass。
- `guard-live-07`：引擎窗口 20 项、0 失败，死亡冻结、多事件攻击与循环脚步模型仍通过。
- `plugin-observe-02`：修改后的实际 plugin TU 编译通过；完整 DLL 与新版本实机仍待，构建代理已收到 `guard-live-handoff-02.json` 的稳定源码身份。
- 本次主代理死亡样本只收到一次客户端事件，但 `sequencetime != animtime`，不能用它证明冻结等时分支已经通过实机；原版声与最终听感仍需继续采样。
