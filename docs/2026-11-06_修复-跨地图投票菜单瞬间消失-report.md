# 跨地图投票菜单瞬间消失

客户端投票倒计时已统一改用 `GetTickCount64` 单调宿主时钟。相同夹具中，已部署旧逻辑为 **422 项、42 失败**，修复候选和根目录公开测试均为 **422 项、0 失败**。本报告记录源码及自动回归；具体客户端包时间/帧时间回拨尚未在用户实机中采样，不能把受控复现写成实机捕获。

## 根因与改动

已部署 `session.cpp` 明确区分用户消息所见的包时间和 `HUD_Frame` 所见的插值时间，且不再用渲染时钟回拨判定连接更换。但投票控制器仍把两处 `engine.GetClientTime()` 混作同一倒计时采样域：`Receive` 经 `Countdown::Observe` 保存包时间后，下一帧 `Remaining` 遇到更早的插值时间返回0。`ScenarioMapVoteFrame` 随即清掉 `pendingOpen` 并关闭菜单，后续同 generation 包不会执行新投票的打开流程；`Observe` 自身也会把同类回拨标记为取消。

本次仅改 `native/csol/client/scenario_map_vote.cpp`：接收快照与读取剩余秒数均调用统一的 `VoteClock()`，投影到单调宿主时间。服务器仍控制 generation、revision、phase 和剩余秒数；同 generation 沿用现有 `min(deadline, projected)`，延迟包不能延长已建立的本地截止点。没有更改共享 `Countdown`、服务端消息协议、菜单每帧打开规则或会话重置逻辑。

现有按需诊断增加 revision、phase、remaining、pending、restoreMouse、gameUiVisible 及 clock 名称；不逐帧写日志。源码只需重编一个客户端翻译单元，不涉及公共头文件布局或服务端 ABI。

该持续投票规则属于用户要求的 GoldCraft 自定义行为；本修复不新增原版 CSOL 还原假设。
