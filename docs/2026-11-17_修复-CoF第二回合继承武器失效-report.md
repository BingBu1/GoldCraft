# CoF 第二回合继承武器失效修复

用户澄清的触发条件是同一地图内回合结束后进入第二回合。不是换图。

## 根因与修改

实际 ReGameDLL 的 RestartRound 调用 RoundRespawn，Spawn 开始退休旧客串玩家后端，再增加 m_iNumSpawns。存活玩家的 m_bNotKilled 路径保留原库存和弹药。CoF 的 PreparePlayer 在出生完成后建立新生命的后端，再遍历保留库存恢复绑定。

VP70、TMP、MP5、M16、G43、870 的恢复路径额外要求旧 backends_.ownerLife 等于新后端代次。这与原生保留库存的生命周期冲突。任一武器重绑失败，实际 Host 会将整名玩家的 row.prepared 清掉，连带购买、切换和使用失效。Glock、P345、左轮没有这个额外相等条件，但会受到同一玩家就绪门的连带影响。初始私有分析误把左轮也列为直接失败类，本轮核源码后纠正。

删除上述六类武器中的额外旧后端代次比较；TMP/MP5 共用同一模板，因此实际修改五个生产文件。恢复仍从冷 Host 获取当前权威后端并执行完整 Bind。附带的 modelRebind 延迟任务继续严格核对生命、出生次数、玩家/武器序号、地图及当前选择；库存事务快照也继续拒绝跨生命回放。没有强制成功、重发武器或重置弹药。

这属于 ReGameDLL 库存生命周期适配，不作为原 CSOL/CoF 内部结构的复刻声明。原武器射击、装填、音效、伤害和 CSOL 怪物 AI 均没有本次行为修改。

## 修改前证据

复用原 CoF PE32/x86 MP 样本，基址 0x10000000，SHA-256 为 0036b91c01e92ed205513f52563053a55a66a32d257efb5f476b8f1f3dde0e63。本轮实际样本全文哈希已复核。原 VP70 Primary/Shoot 的 VA 0x10084880/0x10084CE0、派生 Post/aim/Holster 的 VA 0x10083FC0/0x10083CD0/0x10083A00/0x100839C0，以及共享库存/装备入口的已有 IDA 窗口，由原指令 oracle 在实际 SDK 回归中再次执行。M16/G43/870 使用各自修改前冻结证明，并由测试校验原模块区域。

私有证据保存于 analysis/cof-weapons-20261111/round-retained-inventory-20261117/。PREEDIT-host-inventory-lifecycle.json 在生产修改前记录 SDK 接点和文件哈希；PREEDIT-binding-renewal.json 保存旧版负例、原样本和原指令对照身份、修正范围。旧 SDK 用同一把 VP70、同一原生玩家和新出生/生命代次，实得 native-survivor-rebind=0 并在新回归处失败。

本轮 IDA 新会话接入失败（环境未设 IDADIR，旧 worker 未被 supervisor 接管），没有把失败调用写成新增逆向成果。本次使用已存并核身份的原证，新增结论来自实际 SDK 库存消费者。未据猜测新增原版规则。

- TMP/MP5：build/cof-round-retained-auto-20261117-01，真实两个模板实例及 TMP4489项/其中MP51270项检查通过；TMP 的新回合继承用例覆盖共享重绑代码。MP5 的独立原射击/切换回归也通过。
- M16：build/cof-round-retained-m16-20261117-01，2178项 SDK 检查通过。
- G43：build/cof-round-retained-g43-20261117-01，1953项 SDK 检查通过。

三把长枪的新增用例在同一地图和原库存实体上退休旧玩家任务槽，再按新生命建立真实任务槽和武器后端，验证原弹药保留、旧快照拒绝及下一轮射击。现有同生命换模型和旧延迟任务取消用例继续执行。控制的引擎/目标伤害/音频/网络边界保留，不将这些数量当作真人游戏或 FPS 验收。

## 构建、部署与剩余项

修复为冷库存重绑路径少一次整数比较，无新增分配、缓存、逐帧工作、磁盘或网络读取。此处没有声称实机 FPS 收益；真实多人、长期回合与性能仍需验收。

完整服务端构建正在 build/cof-round-retained-whole-20261117-01 执行。修改直接在项目源码；build 只含编译输出和回执。早先 870 整服构建在本次源码修复后因输入变化被拒绝，不部署该旧候选。

本地专服完整 HUD 预检320项通过、当前为无人窗口。新候选完成封存后再核完整资源/实际模块配对，正常停服并原子更新服务端 DLL/PDB，再用原启动脚本恢复。没有更新正式远端；本次不需客户端资源更新，也不接管 B 键鼠。
