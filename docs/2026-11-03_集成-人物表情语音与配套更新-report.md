# 人物表情语音与配套更新

用户要求审查 Claude 的人物语音和 J 键动作，并与当前更新一起部署。已核工作区源码和实际候选，不能把早期服务端 DLL 直接覆盖到新武器版本：本次以已验 SKULL2 双端为基线，合入表情动作与语音。地狱围栏准入保持独立验收。

## 审查修正

- MP 菜单入口对所有槽位执行 `1..count` 检查；技能 action5 的特殊入口不表示四项 J 菜单可以调用第 5 项。宿主已区分无技能 owner 的菜单动作。
- HW `37541120` 在声线向量为空时，通过 `3753FBC0` 的明确映射回退到通用声线。已按原指令恢复映射，保持非空专属向量优先；一次选句只有一个候选也消耗一次 CRT `rand()`。
- 客户端清理场景时重置句子表，避免同地图重连继续使用上个会话的表或缺件缓存。原资源中缺少的旧句子保持无可播内容，不补造语音。
- HTTP 原规则拒绝 `sound/sentences.json`，导致 WAV 即使下载仍没有句子索引。只增加该精确路径，其他 sound JSON 与未广告资源继续拒绝。
- 服务端菜单正文 `resource/csol/cso_titles.txt` 原样来自 common 的 `titles.txt`；资源收集器记录此路径映射，供补丁闭包使用。

语音限本次已确认的表情事件 5050。电台按发送者声线的行为仍未证明，不纳入此次实现。J 动作当前接在灾变运行会话，其他游戏模式另验。

## 顺带发现的真实购买生命周期问题

独立购买夹具在原生 AddPlayerItem 的 post hook 中释放新武器，复现了“已插入库存、尚未 AttachToPlayer”的窗口。此时 `m_pPlayer` 已设置而 `pev->owner` 为空，原 OnFreeEntPrivateData 没找到玩家，留下库存悬空指针。

已在原清理路径中通过实际客户端实体查找匹配的 `m_pPlayer`，不直接解引用未经核对的指针。DefaultTouch 的 CanHave/Add/Attach/音效回调后增加实体与生命校验，避免对已释放对象继续 Attach 或调用目标。真实 SDK 购买夹具 80 组、734 项行为和 15160 项边界检查通过；旧 DefaultTouch 负例准确触发释放后的目标查询。该结果仍不代替真实多人购买。
