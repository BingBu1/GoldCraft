# 近战准星与初始小刀选装

用户报告近战武器没有准星，并且装备扩展近战后无法买回初始小刀。本阶段分别核对原版准星消费者和刀具选装链；构建、部署与游戏验证分别记录。

## 准星原证与修改

样本为 x86 工作区副本：hw.dll 基址 `0x37100000`，SHA-256 `c7bddfda93c2e0877ea126a15a318b83cce74c59bb95e38a7301b08033ac7783`；client.dll 基址 `0x01900000`，SHA-256 `f4145136edbd229c219ea793bb3a6dcacea0b406ccc1e610138abbb8063bcbfd`。以下均为 VA，RVA 在核验清单中记录。新建独立 IDB，不修改共享样本数据库。

原 HW `0x37A8EE4A–0x37A8EEEC` 注册 `weapon_knife=29`，经 `0x37A77A50–0x37A77B26` 构造武器记录。原指令回放确认 `+3C/+40/+5C/+60` 为 `{7,3,0,0}`，准星资格标志 `+64=0`。原 client `0x02A2269A–0x02A228A6` 查询该记录，以 `+64 & 4` 排除不画动态准星的武器；`0x02A23CB0–0x02A23F0B` 消费实际间距和动态参数。四段共 423 条 IDA 指令的地址及原字节已逐项核同。

青龙偃月刀和旋风在原版仍是武器 29 的不同刀具选装；宿主分别使用 1022/1023 是桥接适配。旧公共 `weapons.cpp::DrawCrosshair` 只允许 Total/Magazine 弹药显示种类，误排除了 `AmmoKind::None` 的两刀；其模块参数也未填写。修复使公共入口按已注册模块和有效武器定义判断，`melee.cpp` 填入原版小刀参数。普通 CS 武器继续由原客户端画准星，避免重复；狙击枪显式禁用准星和隐藏、死亡、观战、FOV、过场条件保留。

修改前合同及原证：`build/melee-restore-20261106/crosshair-evidence-01/contract.md`、`verified.json`。独立候选以实际诊断 05 的有效源码为基底，保存于 `crosshair-client-01`；根目录无关 WIP 保留。

## 当前验证

- 原指令：刀记录构造回放得到 ID 29、间距 7、变化量 3、速度与动态标志 0；此为受控指令验证，不是原游戏画面。
- 实际生产入口及模块描述：46 项通过；旧部署源码在同夹具中出现 12 项失败，准确检出两刀参数与准星缺失。使用实际 SDK 类型与真实准星绘制助手，控制引擎绘制和武器查询边界。
- 完整双端构建、更新和真实画面尚待本轮合批。
- 初始小刀独立 SDK 的 16 组库存与切换场景已通过：388 项行为断言、18,983 项 SDK 检查。菜单校验随后补入默认刀图标必需项，217 项菜单检查通过；不把此前库存结果说成后续菜单修改的验证。

测试入口为 `tests/csol-melee/run_crosshair.py`，结果在 `build/melee-restore-20261106/crosshair-test-02/result.json`。首轮测试夹具误用了 const 返回类型，与实际 SDK 的 `char*` 声明不符，编译失败已保留；修正测试声明后通过，未修改生产 ABI。

## 初始小刀原证与宿主适配

原 MP 为 x86，映像基址 `0x10000000`，SHA-256 `39f962f34816411e615f01e5279d914204f7fd07c5a5112b0b303acafe0308b2`。原 HW 使用上文同一份样本。修改前合同在 `build/melee-restore-20261106/knife-purchase-01/BEFORE-IMPLEMENTATION.md`；父独立核验两个模块身份、映像基址及七段 577 条指令对应原字节，见 `parent-evidence-check.json`。

HW `0x379EB870` 从 `0x380D4738` 建立刀具选装目录；索引 0 对应 InGameID 4000、目录项 161，查询消费者为 `0x379EA550` 和 `0x379E96C0`。MP `0x11414F48–0x11414FF8` 经 `0x1140D370` 调用 `0x114D8650`；灾变模式 15 不进入模式 59 的货币分支。同刀选择不重建实体，但共同尾 `0x1140D44F` 仍刷新选装属性。更换携带的刀只在原刀当前手持时切换，不打断手中的枪。

购买目录新增“海豹短刀”，价格为 0，使用普通 `weapon_knife`。服务端明确处理原生 `CKnife` 与现有两种扩展近战，保留购买准入、重复选择的共同尾、槽位唯一性、失败回滚和原有切枪策略。宿主原生 `SelectItem`、`SwitchWeapon` 丢弃 `Deploy` 返回值，因此增加仅在选装事务中生效的观察回调，验证新小刀实际部署成功；不改变普通小刀返回值、对象布局或攻击逻辑。

菜单资源修订为 v10，仅新增 `models/csol/buymenu_v10.json` 与 `gfx/csol/buy/w29.tga`，已有 63 项资源字节保持。本轮服务端受控 SDK 和原版证据不等于真实菜单点击、准星画面或多人验收；完整 DLL 与部署结果将在合批完成后补记。

最终选装交接为 `knife-purchase-01/handoff.json`。父核对 63 条产物身份引用、62 个唯一文件，以及实际 16 组结果和菜单结果，均通过；记录在 `parent-incoming-check.json`。SDK 中受控 `game_rules_gate.cpp` 对象禁止复用到正式 DLL，最终合批使用实际运行基线上的窄修改。
