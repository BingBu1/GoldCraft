# 自定义玩法配置纯数据层

本阶段完成严格 JSON 编解码、可逆类型化编辑和不可变配置快照；尚未接入永久写盘、管理员菜单或实际玩法消费者。这是用户授权的 GoldCraft 自定义配置，不宣称原 CSOL 行为。

## 接口与配置

源码为 [settings.hpp](../native/csol/scenario/custom/settings.hpp) 与 [settings.cpp](../native/csol/scenario/custom/settings.cpp)。`Features()` 提供 11 个功能描述，`Settings()` 提供 37 个数值描述，包括稳定枚举、键、类型、范围、CVAR 元数据、默认值、生效范围和中文说明。`csol_custom_` CVAR 名称仅是元数据，纯层不注册或执行控制台命令。

根对象必须恰好包含 `version`、`features`、`values`、`comments`，版本必须为整数 1。`comments` 必须包含 `features` 与 `values` 两个对象。功能、数值及说明子项可省略，取明确默认或保留未定数值为空。支持 `//` 和块注释；持久说明存放于 `comments` 对象，序列化保留这些字符串，不保留源文件注释排版。

`Parse(json, output, error)` 只在完整验证成功后替换 `SnapshotPtr`。`Draft(snapshot)` 克隆冷态草稿，`Set` 编辑，`Finish` 验证功能必需参数及跨字段关系后发布 `shared_ptr<const Snapshot>`。数值编辑的 `nullopt` 恢复声明默认，没有默认则移除；JSON 不接受 `null` 代替数值。关闭功能保留它的数值，之后可再次开启。

默认 `kick=true`，其他新功能暂为 false，表示配套消费者尚未完成时不自动激活，不表示最终请求范围缩小。用户指定正午 180 秒、黄昏 120 秒，之后永夜；熟练度阈值 100/200/300。本阶段明确采用的自定义平衡默认包括盲盒 3000/6000/9000 CS 金钱、各档独立换弹/伤害/射速、黄昏/永夜增益和每玩家每怪返现上限 1000；对应中文说明均注明“GoldCraft 自定义默认，非 CSOL 原值”。CoF 基础体力等未定参数不补猜测值；启用相关功能缺必需参数时明确拒绝。

时相、黄昏增益、永夜增益、怪物数量和随机尸潮独立开关。仅开启时相无需填写战斗增益。盲盒三价严格递增，熟练度三阈值严格递增。熟练度一档换弹、二档换弹与伤害、三档射速与伤害分别描述，未使用每档一个总倍率的简化。返现上限按用户明确的每 player-victim 组合定义，不提供虚构 scope 选择；怪物租约与玩家身份由未来权威消费者维护。

数值范围是宿主配置和溢出保护边界，不是原版参数。血迹数量最多 4096、寿命最多 600 秒；实际资源容量仍由消费者检查。纯层不根据 `enabled` 假定 BGM、奖励、移动或血迹渲染已经可用。

## 验证证据

E1：本阶段用户/主协调者授权的自定义范围和参数，以及修改前独立 scope 记录；未以 JSON 设计冒充 CSOL 原证。

E2：实际源码、[纯测试](../tests/csol-custom-settings/main.cpp) 和 [CMake 入口](../tests/csol-custom-settings/CMakeLists.txt)。验证重复/未知字段、UTF8/NUL、类型、整数范围、非有限数值、缺参、中文说明往返、可逆编辑、失败保留旧快照、每个描述范围边界及最大说明序列化体积。

E3：本地 `build/csol-custom-settings-20261113-03/receipt.json`：两个实际 TU 和独立 EXE 编链成功，x86/C++20/O3/ThinLTO/AVX2/precise；**504 检查、0 失败**。295 个实际编译头文件均在预先记录的 4812 个输入中，记录输入前后稳定。首次 302 项与扩展 504 项收据分别保留于 `-01`、`-02`；最终 `-03` 补齐编译器内建头输入核验。没有源码复制、整服构建、部署或实机验收。

E4：[示例工具](../tools/Generate-CSOLCustomSettings.py) 从编译出的纯 codec `--example` 获取唯一默认表，已生成本地 `build/csol-custom-settings-20261113-03/gameplay.example.json`。重复目标被独占创建拒绝，原文件 SHA 不变；Python AST 通过。工具是离线生成器，不能替代运行时原子持久提交服务。

F1（E2/E3）：无效配置不能部分修改已发布快照；草稿失败保持旧指针。F2（E2/E3）：未知基础体力等不能被缺省值静默启用，关闭和重新开启保留已填参数。F3（E2/E3）：固定数组热读取在 100000 次受控循环中零分配；这是分配边界检查，不是实际 CPU/帧时间通过。

P1，callflow：冷启动或显式重载 JSON（E2）→严格完整解析与 `Draft::Finish`（F1/F2）→发布不可变快照→逐帧消费者只读枚举 getter（F3）。权限、保存和消费者准入在纯层之外，必须先验再发布，不允许客户端直接设置 `enabled` 或任意 CVAR。
