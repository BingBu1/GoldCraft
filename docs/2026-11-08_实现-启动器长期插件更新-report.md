# 冰桑启动器长期插件更新

用户要求以后发布新 DLL 时，不再更换冰桑启动器 EXE。2026.11.08.2 引入签名更新协议2：
保留一个稳定的离线安装基线，在线签名合同同时管理 DLL、符号目录、shader 和插件加载顺序。
玩家本次换用该 EXE 后，后续在这个范围内的插件更新只需点击“启动游戏”。
这取代上一个2026.11.08.1版本“静态目录改变必须重制 EXE”的发布方式。

## 实现与限制

- `ReleasePolicy.cs` 验证 RSA 签名、基本引擎/客户端身份、路径/大小、解压长度和每文件 SHA。
  稳定 bundleId 为 `ac689085e776441828892db90bd22f09c9ee21c80e0318630ac3ea096c796406`。
  启动校验以安装记录中保存并重新验签的在线合同为准，不再要求在线符号目录符合旧内嵌 SHA。
- `Updates.cs` 在同一个事务内更新 DLL、符号目录、shader、插件顺序及签名记录。
  必须保留19项基础核心；新增插件/依赖可通过签名清单加入，不再将数量固定为19。
  已受管理的新插件和资源可以撤销，删除前验证旧文件身份，外部修改时拒绝覆盖。
  仍保留用户按键、账号、无关插件和其他游戏配置。
- `Bundle.cs` 保留完整离线安装；修复已在线更新的安装不降低序号或覆回内置旧 DLL。
  UI 的修复流程接续在线校验。已安装2026.11.08.1组件与稳定基线相同，可直接启动升级。
- 小型配套资源压缩后直接包含在签名 manifest 中，复用原 HTTP 端口、路由及1MiB限制。
  DLL 仍使用现有按 SHA 命名的 blob 路由。当前19个 DLL、264个目录/shader，清单690489字节。
  超限会拒绝发布；没有扩大服务器开放路径，也没有把资源伪装成 DLL。
- 配套文件范围为 metahook/gamedata 的 JSON、metahook/shaders 和 renderer/shader 的
  glsl/fsh/vsh/h。地图、模型、字体、大纹理及 MetaHook.exe/SDL 等引导组件、基础游戏 ABI
  不在此范围；启动器程序功能或基础游戏兼容范围改变仍可能需要新 EXE。

`Publish-Update.ps1` 默认协议2，调用 `managed_release.py` 和 `Publish-ManagedUpdate.ps1`：
按实际插件顺序/依赖目录生成完整 DLL 集合，校验所有符号索引的 SHA/长度与实际快照一致，
检查不可管理的引导文件保持原身份，发布前后输入核SHA。旧协议1仅显式选择并继续拒绝静态差异。
shader的`.frag.glsl`正常支持，运行生成的`*_cache.txt`排除；首次两项拒绝日志保留。

`managed_package.py` 带齐所有 blob，配套通用 `Update-Server.ps1` 默认使用既有服务器根目录。
签名、文件哈希、顺序号检查后先放blob、后原子替换manifest；支持预检、幂等、恢复和中断重跑。
在线发布无需重启服务器。恢复旧清单不会让已升级客户端接受回退，修复应使用更高序号。
