F1，已验证，高置信度，`n/a_re`：青龙的文件名不能代表声音发生条件。左键完成函数按当前斩击序号选择 hit1/hit2 或 slash1/slash2；右键命中取 hit1，空挥取 stab_hit。声音在目标扇区处理完成后播放一次，早于后续计时和跟随动画。源码对应 `PlayAttackSound` 和 `DelayedAttack` 扇区扫描后的调用；依据 E1。

F2，已验证，高置信度，`n/a_re`：旋风每个接受的目标在 `TraceAttack` 前播一次命中声；空挥从三个样本选择，且声道/音调不同。单样本的命中和墙声也执行 `RANDOM_LONG(0,0)`。源码对应 `PlayAttackSound` 和每目标伤害前的调用；依据 E1。

F3，已验证，高置信度，`n/a_re`：起手模型事件与完成结果音是不同路径。缺失 `dragonsword_stab.wav` 已按用户明确决定省略，继续保留 `studio_sound.hpp` 中模型、事件和样本三条件过滤，不能用 stab_hit 替补；依据 E2 及此前用户授权偏差记录。没有重新生成或修改模型。

F4，受控 SDK 验证，高置信度，宿主适配：新增声音/RNG调用后必须确认当前攻击拥有者与实体仍有效。旋风伤害前另复验目标 EHANDLE 与怪物池 lease，避免音效回调释放目标后继续伤害；这是 ReGameDLL 回调安全适配，不宣称原 CSOL 使用同样的 C++ 结构。依据 E3。

P1，`callflow`：原 helper 延迟完成函数 → 扇区目标检测 → 旋风逐目标播声、然后伤害 / 青龙扇区结束后一次播声 → 完成计时与动画。E1支撑原顺序，E3验证移植后的函数路径。声音与 RNG 作为宿主引擎边界，返回后验证所有者；失效即停止该次后续处理。
