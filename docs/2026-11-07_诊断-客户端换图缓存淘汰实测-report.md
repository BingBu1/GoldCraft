## Findings

F-01（validated，n/a_re，high，E-02/E-03）：正常换图存在容量淘汰。1536次释放中1134次返回宿主 RVA 0x237DD6。csol89 在事件71/724、K3在109/742各从同一 owner 被淘汰两次，data 地址已经改变。位置为宿主 Cache_Alloc 分配失败分支；不能再把这些具体事件解释为单纯搬迁。

F-02（validated，n/a_re，high，E-02/E-03）：不是所有释放都代表丢弃模型。RVA 0x238378 的199次和0x2385FE的153次，在释放前已复制数据，之后把新指针写回 owner，分别属于 low/high hunk 扩张时的成功搬迁；0x238610的49次属于 high hunk 扩张时搬迁分配失败后的释放。剩余0x1BF664一次暂不分类。

F-03（validated observation，n/a_re，high，E-01/E-02）：已部署 CSOLSupport::CacheAlloc 调宿主分配器，LoadStudio 调用链在淘汰栈中。当前相关源是 `native/csol/client/sequence_guard.cpp` 与 `native/csol/client/resources.cpp`。这证明消费路径和容量冲突，不单独证明应扩大缓存或跨图永久保留。

## Path 与下一步

P-01（callflow）：LoadStudio → 下游宿主/Renderer 模型加载 → CSOLSupport::CacheAlloc → 宿主 Cache_Alloc → 申请空间失败 → LRU Cache_Free（E-02/E-03、F-01）。重复出现相同 owner 的两次容量淘汰，说明只优化 CRC 计算不足以消除重复准备。

继续对照原版 IDA 的非像素前缀、SEQ整理、独立缓存与清理消费者，确认当前每角色约7–8MB保留块的来源，以及哪些数据和生命周期可按原版优化。没有足够证据前不改容量、绕过校验或永不释放。
