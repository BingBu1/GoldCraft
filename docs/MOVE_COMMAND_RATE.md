# 移动指令突发误封

2026-10-17 候选修正，尚未部署。用户报告正常游玩收到 `Banned for move commands flooding (burst)`，随后因 IP 禁止名单被拒绝五分钟。该文案来自 ReHLDS 的移动指令限流器，与 Steam 认证掉线不同。

## 计数缺陷与修正

`Netchan_Process` 将接收序号缺口写入 `net_drop`，`SV_ParseMove` 再扣除本包包含的新指令。恢复循环只在 `net_drop < 24` 时补执行丢失指令；较大缺口直接丢弃。旧限流入口却把所有正的 `net_drop` 加入执行次数，造成从未执行的历史包被算作当前突发。

候选只在 `0 < net_drop < 24` 时计入补执行次数，与真实 `SV_RunCmd` 循环一致。新指令、实际重放、包长度/CRC、平均/突发限流和用户指令时间校验均保留；阈值、处罚和普通客户端设置未更改。

例如当前源码默认突发阈值为 5500，最短统计窗口为 0.2 秒。一个含 1 条新指令、校正后缺口为 1199 的包实际只运行 1 条指令，旧计数却为 1200，得到 6000 次/秒并封禁。修正后该包计数为 1。真实 1200 条新指令仍触发同一保护。

本次公网事件没有服务器接收序号采样，不能据此断言它的唯一原因已经被现场证明。只读 RCON 已确认公网当前突发阈值 5500、平均阈值 1800、封禁五分钟。当前本地 B 保存的 `cl_cmdrate=60`、`cl_cmdbackup=2`，诊断中的 `fps_max=99.5`，也不足以支持“正常持续高 FPS 超限”的判断。
