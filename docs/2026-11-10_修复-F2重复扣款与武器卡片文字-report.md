# F2 已持武器与卡片文字

用户报告：F2 会重复购买已经持有的扩展枪械，卡片名称遮住武器图。
按两个独立入口修正；0.1 秒输入门保持用户要求的已删除状态。

## F2 修改前证据

原 MP 为工作区副本 `analysis/csol-model-20261017/samples/mp.dll`，x86，
SHA-256 `39f962f34816411e615f01e5279d914204f7fd07c5a5112b0b303acafe0308b2`，
映像基址 `0x10000000`，以下地址均为 VA。现有 IDA 证据重新对原 PE
核验了 350 窗，新增读取同一身份的已有 IDA 会话，不使用不同版本偏移。
私有证据在 `analysis/csol-rebuy-owned-20261110/source-evidence.json`
及 `fresh-ida.json`；核验脚本同目录 `inspect.py`，依赖本地原版样本。

E1：原重购 `0x114E51DB..0x114E523E`、`0x114E571C..0x114E5781`
仍发送正常主副武器购买命令；不能在客户端凭持枪状态整段取消 F2。

E2：原购买 `0x1140D83D..0x1140D8B0` 在服务 `+0x98` 返回假的分支，
遍历实际武器链，跳过原刀槽 3，在 `0x1140D883` 比较实际武器 ID。
相同 ID 跳 `0x1140D916`，两个子分支都回到 `0x1140D8EF` 失败返回，
发生在 `0x1140D993` 余额检查和 `0x1140DE39` 扣款之前。
`0x1140D93B..0x1140D959` 受打印标志控制显示
`#Cstrike_Already_Own_Weapon`；特殊武器的 `+0x25C` 分支仅改变另一个
标志，并不交付或扣款。服务 `+0x98` 的其他模式语义仍未命名，
不扩展到未支持的多库存模式。

F1（E1、E2）：宿主原生枪械购买已有同枪检查，但扩展枪械在
`native/csol/server/buy_menu.cpp::Purchase` 直接扣款并调用交付服务，
后者允许替换实体，因此 F2 会走同枪付费重建。应在该购买入口为已支持
的扩展枪械补齐实际库存同 ID 检查，刀具保留已证的选装元数据尾。

P1：`cl_rebuy/rebuy_in` → 服务端固定顺序 Replay → Purchase →
同枪失败且不交付/扣款 → 继续弹药和装备。普通购买也使用相同资格门。
宿主实体归属、存活标记和回调后失效检查属于适配，不声称原版 ABI。

## F2 源码与适用范围

F2 源码已在 `native/csol/server/buy_menu.cpp` 补齐检查：扫描非刀槽实际
库存链，验证实体归属和删除标记；比较实际武器编号，不把 SKULL-3 的
双持实体当作另一件可重复付费购买的枪。已支持灾变模式内的普通菜单购买
与 F2 共用此门，后续弹药、装备回放继续。检查只在购买请求时遍历现有
库存，不分配内存、不进入逐帧路径。刀具保留原独立选装尾，不加入同枪门。

宿主 `Eligible` 目前要求 `CSOL_ScenarioCanBuy`，作用域为
`CCSOLScenarioRules` / mode2 / StandardVer2。此修复不声称普通模式、
ZP 或原版所有多库存模式均采用相同策略。

独立审计纠正服务身份：`+0x98` 属于引擎服务对象，不能命名为
`g_pGameRules`。匹配原 HW 为 x86，基址 `0x37100000`，SHA-256
`c7bddfda93c2e0877ea126a15a318b83cce74c59bb95e38a7301b08033ac7783`。
原 MP `0x114B22B0..0x114B22CF` 复制引擎表至 `0x122785A0`；
`0x12278860` 对应 HW 表 `0x383099F0+0x2C0`，getter `0x37A94800`
返回对象。构造 `0x37A77F6D` 的虚表 `0x380EB3FC`，槽 `+0x98` 指向
`0x37A91880`，仅已证有符号全局值 `0x383729B0 >= 2`。
该值的生产者、模式含义与真分支仍未知；未虚构模式判断。审计保存于
`analysis/csol-rebuy-sdk-owned-20261110/parent-audit.md` 与
`parent-mode-ida.json`。
