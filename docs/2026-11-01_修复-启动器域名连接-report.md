# 启动器域名连接修正

用户报告启动器自动连接失败，但服务器列表的数值 IP 能进入。只读核对发现，在线签名清单、运行中 MetaHook 的 `+connect` 参数与内置域名一致，系统 DNS 返回的 IPv4 与用户成功连接的列表地址相同，游戏查询也返回同一灾变服。因此没有证据把问题归因于配置端口写错；旧引擎启动参数或名称解析内部的具体失效点尚未动态定位。

`GameLaunch` 在每次启动前解析签名清单中的域名，选择 IPv4 并保留原游戏端口。CS 只接收数值 IP，避免依赖其启动阶段的域名处理；后续启动重新解析，隧道 IP 变化时无需改版。解析限时八秒，取消或解析失败停止启动，不回退到 HTTP 地址或状态接口。启动参数通过 `ArgumentList` 传递，拒绝未解析域名和换行尾缀。

交付版本 **2026.11.01.6**，单 EXE 75,141,481 字节，SHA-256 `60afd6c2e604eb7ef0175831a8eab884a4a0688d18b9080fc1b6a7116825f4c6`。沿用此前图标与静态安装资源，未更改签名发布、核心 DLL 或生产游戏安装。

验证：.NET 构建零警告/错误，56 项检查通过，涵盖含连字符域名、动态 DNS、IPv4 选择、保留端口、实际进程参数构造、取消/失败，以及既有完整安装、更新签名、范围下载与回滚。真实在线签名版本 2026110104 验证通过，系统解析及最终启动参数与用户提供的可用 IP 相同。没有启动真实游戏，仍需玩家确认自动连接成功。

首轮完整安装夹具错误使用了比内嵌资源更新的在线清单，因本地 HTTP 夹具没有该新增 blob 返回 404；保留失败日志，改用与嵌入包对应的历史签名清单完成安装回归。新增签名解析诊断入口首次编译存在变量重名，修正后构建及真实解析通过；交付程序不受该测试入口改动影响。

本地证据：`build/client-launcher-connect-20261101/delivery-final.json`、`tests-02.log`、`public-signed-launch.json`、`publish.log`。主 goal 仍暂停，服务端 BGM 资源遗漏单独修复。
