## 已定位并修复的代码路径

| 证据 | 结论 | 调用路径与处理 |
|---|---|---|

| E02：服务器 `gc_zp_locale` 对购买标题返回中文，对 `ZOMBIENAME Classic Zombie` 和武器名返回 `ML_NOTFOUND`；匹配 AMXX 源码在键的首个空格处截断 | F02：原翻译文本已在文件中，但运行时注册键与查询键不同 | P02：`CLang → CTextParsers::ParseFile_INI → GetLangTransKey/%L`。生成无空格别名，同时修正职业、HUD、道具、模式和购买菜单的查询 |

| E04：隔离执行匹配引擎的真实 x86 光标状态函数，16 个旧/新光标及 rawinput 组合中有 3 个遗漏 SDL 状态更新 | F04：光标不变时切换 rawinput，或关闭 rawinput 同时打开菜单，会留下错误 relative-mode/光标状态 | P04：原生 `CL_CreateMove` 之前，通过公开 SDL2 光标及 relative-mode 接口对齐状态；不读取鼠标增量，不修改绑定或 rawinput 设置 |
| E05：`ShadowIdx` 虽然使用 `WRITE_LONG`，ReGameDLL 的 `g_iShadowSprite` 仍是 `unsigned short`；实际编号 65676 会先截成 140 | F05：字段在发送前已丢失高位，客户端会取到无关贴图 | P05：阴影及 Bot beam 的预缓存句柄存储改为 `int`。真实高编号客户端解析到 `sprites/shadow_circle.spr`；匹配符号还校验了实际 CS 阴影字段 |
| E06：同一 CS 客户端的公开 `StudioDrawPlayer` 调用虚表槽 25；用户八月原版插件正确识别 25，十月更新的符号集成却选中了基类槽 3 | F06：更新后的 Renderer/BulletPhysics 挂接遗漏实际玩家路径，物理裁剪盒曾偏离玩家 2408.97 单位；不能归咎于用户的原版 MetaHook | P06：从公开 studio 接口包装实际玩家绘制，恢复各 pass 步态输入、更新物理骨骼上下文、限制重复事件并约束第一人称自身模型。实际多回合数值验证通过，完整视觉验收仍保留 |
| E07：ReGameDLL 的 `Brass` 模型参数和实际 CS 对应读取都仍是 short | F07：高编号弹壳会被截断或按错误长度解析 | P07：只扩展已核对的模型字段，保留其他参数；实际 AMXX／ReAPI 修改、扩缩、reset 及客户端 65535／65536 读取通过 |
| E08：安装客户端即改媒体读取与资源表，会影响普通服务器 | F08：扩展能力必须以当前连接的协议协商为准 | P08：安装时验证并保存原字节，匹配 manifest 后启用；原生连接调用原资源解析器，清理后恢复表、读取指令及一致性返回格式。真实单进程两轮往返通过 |
| E09：开启延迟光照的真实录像中，每帧约 1117 次骨骼保存仅有约 53 个不同姿态；旧代码每次保存都取新槽再覆盖同键映射，原版 Renderer 在当前沙箱也重复报溢出 | F09：多个点光源的阴影 pass 耗尽 1024 槽，丢失后续缓存收益并反复输出警告；此外，旧哈希把负浮点坐标转成无符号整数，违反 C++ 转换规则 | P09：`R_RenderShadowmapForDynamicLights → StudioSaveBones_Template → R_StudioSaveBoneCache` 按键复用槽位并更新矩阵，使用合法哈希与精确相等，每帧清理。真实独立姿态满时保留原生计算并限制重复警告 |
| E10：启用此前遗漏的 CS VGUI hook 后，真实入服崩溃落在地图说明文字路径；匹配客户端实际接收 4 个参数并清理 16 字节栈 | F10：目录声明的单参数包装与真实调用约定不符；符号能找到不代表 ABI 正确 | P10：匹配二进制身份的四参数适配保留参数和返回值，独立 x86 负对照触发旧错误，修复后连续 3 次实机重连通过 18 项检查 |
| E11：狙击镜外圈和四段黑线存在，但中心为空；匹配引擎实际 `crosshair=0` | F11：中心 sprite 的引擎绘制入口由此 cvar 关闭，四段 VGUI 线本来就为中心留空 | P11：用户恢复 `crosshair 1` 后确认正常；无需修改 Renderer。写入 0 的来源尚未查明，ZP 的 Crosshair 用户消息不写这个 cvar |

E01 的硬件行为可能因驱动而异，因为未声明的片元输出没有规定值。回归同时使用实际 TriAPI shader 和显式污染其他附件的测试 shader；生产隔离代码在两种情况下都必须保留地面光照、法线、材质和深度。该测试使用隐藏 OpenGL 窗口，不控制游戏窗口。

阴影修复通过公开的 `engine_studio_api_t` 函数指针安装，不新增硬编码地址或扫描规则。精确引擎分析和运行日志仅保存在本地，仓库发布源码补丁与复现测试。

## 实际运行检查

### 客户端可见实体 512 → 4096

模型、声音的预缓存已动态增长，本次保持不变。独立可见实体组件替换引擎的 7 处表指针、5 处 512 比较，并让 Renderer/BulletPhysics 绑定同一张 4096 表。保留原生计数和逐帧重置，通过引擎原分配器保证透明排序容量至少 4096；不替换其释放路径。所有写入前验证精确引擎身份、符号和旧操作数，不支持的版本拒绝安装。

实际 x86 入队函数通过 8 项检查：原版接收 512／拒绝 513，修改后保留 4096 个不同指针并拒绝 4097，数组两侧保护字、旧数组及下一帧重置正常。单 B 的真实观察者录像测试中，原场景占 91 项，新增 4005 个独立精灵补满 4096；主画面 `glDrawElements` 后的逐实体计数确认全部测试精灵提交，第 513／4096 个均绘制。另一次请求 4097 时准确拒绝 1 个，OpenGL 错误为 0。截图已人工检查：蓝色点阵清晰分离，红色标记代表槽 513，绿色代表槽 4096。测试自动超时和活动状态下重连都清除精灵，容量及消费者绑定保留。

扩容后无测试精灵的相同观察者场景采样有 2001 个前台帧，平均 100.005 FPS，p95 12 ms、最大 15.2 ms，超过 50 ms 的间隔为 0；保持原 100 FPS 上限、延迟光照、阴影、裁剪和 24 Bot。首次采样超时，保留失败记录；上述结果来自后续完整前台采样。后续仅调整诊断精灵的加载方式，不改普通渲染或扩容代码。该证据不能用于宣称 4096 个复杂模型也达到 100 FPS，或服务器能同步 4096 个网络实体。

延迟光照性能使用人类选定的观察者位置和朝向录制 40 秒原生 demo，逐帧验证 993 个网络帧的相机不动、文件目录完整。比较时校验真实播放状态、相同画面坐标、前台焦点和渲染配置，不能用重进服默认视角或后台帧率代替。示例命令只适用于已录制并验证该本地录像的沙箱：

```powershell
python tools/Exercise-RendererReference.py sample --seconds 20 --developer 0 --culling 1 --renderer-profile --label verified-observer
python tools/Exercise-StudioLifecycle.py --rounds 3 --seconds 20 --label model-lifecycle
```

## 尚未确认的问题

可见实体扩容不扩大服务器 edict／网络编号，也不等于模型或声音资源数量。未知引擎需要独立验证；4096 个复杂模型的性能、所有视角／地图及完整多人玩法仍需另测。

- 原始鼠标：确定的 SDL 状态切换缺陷已修复，用户反馈恢复；后来“只能左右看”另行确认是 `in_mlook` 被释放，`+mlook` 可恢复。录像工具会还原它的原状态，释放来源和全部菜单／焦点组合仍待追踪。没有关闭 rawinput 或改变绑定。
- 其他人物随视角消失：实际错误物理裁剪盒与遗漏调用入口已有证据及多回合修复验证，仍需覆盖完整角度、观战切换及移动过程。未关闭主视图裁剪。
- 死亡尸体、步态和完整自身模型：公开玩家入口与 BulletPhysics 的状态恢复、尸体身份及模型重建已通过生产路径回归，完整尸体／动画视觉验收仍未完成。
- 主副武器：已扩大遗漏的 `clientdata.viewmodel` 位宽，用户截图验证双枪显示；主武器及来回切换仍需验证。
- 室内亮度、漏光及动态阴影：需要 CS 真实场景对比，独立 MRT 测试不能替代。
- Minecraft 图形端：NightFall 专服配置访问已有定向防护；YSM/Epic Fight 自定义人物渲染器防护及 HUD 独立矩阵栈已构建，27 项 JUnit 通过，实际组合渲染尚未验收。
