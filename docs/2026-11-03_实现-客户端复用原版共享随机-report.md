# 客户端复用原版共享随机

五个武器客户端原先各自复制了同一张 256 项随机表和散布算法。现已删除这些副本，统一调用宿主 CS 客户端已有的 `UTIL_SharedRandomFloat`。这里只声明函数的 C++ 调用接口，不再自行实现算法或保存随机表。

范围由用户本次纠正确定：复用原客户端能力，并按 CSOL 的原始行为与 CS 的代码约定实现新武器，使用 C++20。只分析工作区内的独立模块副本；不改原客户端二进制、不写受保护安装、不启动游戏。

## 原始依据

| 项目 | 已核结果 |
|---|---|
| 宿主模块 SHA-256 | `b434b1c09b10b011be6c42e4154955da0c3ca46e95746988ebea1aa316a2a9f2` |
| 函数 RVA / 大小 | `0x47c40` / `0xba` |

| 随机表 RVA | `0x105f38`，256 项 |

| IDA 原字节复核 | 函数、转换子函数、表及两个常量区域共 5 段 / 1343 字节一致 |

E-01：本机 `analysis/csol-model-20261017/shared-random-native-20261103/ida-evidence.json`、`ida-bytes.json` 和 `verification.json` 保存 IDA 反汇编、交叉引用与原 PE 对比。函数内容 SHA-256 为 `6fbe71c4bb28f9c383d6fb65559e68827072f32a45be1357304ed85b5b01a698`。原 DLL 不随源代码发布；复核需要自备匹配模块。

F-01（逆向结论，已验证，置信度高，依据 E-01）：原函数每次用显式种子和浮点上下限的位模式重新播种，保留原版的整数范围截断。普通引擎 `pfnRandomFloat` 没有预测种子参数，不能替代它。宿主的两个共享随机函数均自行播种，随机状态的交叉引用也已核对。

P-01（调用路径）：MetaHook `LoadClient` → 按模块身份解析 `UTIL_SharedRandomFloat` → 扩展武器预测调用公共入口 → 原客户端函数计算结果。退出时清除函数指针；缺少匹配符号会在初始化时报错，不静默产生错误散布。

## 源码与维护约定

公共接口在 `native/csol/client/shared_random.hpp`，解析及调用在同目录 `shared_random.cpp`。K3、SKULL-7、龙炎、SKULL-1、SKULL-5 都使用该入口；后四者的其他功能仍按各自阶段独立验收。

`native/client/shared_random_10210.json` 记录模块与代码、数据身份。`tools/Build-ClientGameData.py` 校验后生成配套目录，DLL 与目录必须一起部署。生成时仍支持检查既有匹配目录，避免重复符号。

客户端后续实现遵守以下约定：

- 以匹配 CSOL 的 MP/client 证据确定状态机、时序、动画、弹道和效果；差异不能用通用模板猜测。
- 沿用 CS 的武器预测、事件回调及初始化/切枪/退出生命周期；预测重放不能重复播放效果。
- 先复用宿主已有能力，再提取经过核实的公共组件；保留武器之间有证据的差异。
- 使用 C++20 的类型、容器和资源管理能力；不改变原 ABI、随机调用顺序、浮点计算和动画时机。初始化时解析与准备资源，避免在逐帧绘制中重复搜索、分配和加载。

## 验证边界

源码重构与配套目录生成完成。独立 x86 原函数及 SDK 适配器验证 20,750 项全部通过；K3 经原函数的预测/事件回归 133 项通过；SKULL-5 独立实际 SDK 回归 1,104 项通过。公开测试入口又独立构建并通过全部 20,750 项，输入保持。完整客户端的 5 个编译单元及链接已通过，195 个对象来源和 866 个实际头文件核实，13,105 项输入保持，x86 DLL 与 PDB 匹配；配套 35 符号补充目录也独立生成并逐字节核同。尚未部署或实机验证。

原函数验证覆盖全部 256 个低八位种子、5 组高位及无符号边界、12 类范围、cdecl 栈平衡与初始化/失败/重初始化/退出。只验证原转换辅助函数的 SSE 分支（CPU level 0/1/5），不宣称 AVX512 分支通过。首轮额外范围出现 368 项差异，经反汇编确认参考计算被编译器合并为 FMA；仅在测试 oracle 禁用融合乘加后逐位复核通过，生产代码始终直接调用原函数。

公开复现入口：`tests/csol-shared-random/build.py`，参数和依赖见该目录 README。测试专用表从校验过身份的原 PE 提取，不加入生产 DLL。

时间记录：先核宿主原函数与调用者；随后删除五份重复表并接入目录；最后冻结增量交独立验证。原字节比较首轮因测试解码器错误拼接非补零十六进制 token 失败，改为逐 token 解析后全部一致，未修改原字节或生产源码规避失败。
