## 2. 行为树框架（原版内建，不读外部文件）

- **管理器**：`BehaviorTreeMgr`，单例 `10777B40`。
  - vt8(name) 取缓存的树；为空时由调用方用 TreeBuilder 在代码里构建。
  - vt16("Basic") 返回一个 "Basic" 上下文（黑板）。
- **节点语义**（直接读自原函数）：

  | 节点 | 函数 | 语义 |
  | --- | --- | --- |
  | Sequence | 10625040 | 子节点依次 Tick，任何一个返回 0 则整体返回 0；全部为 1 才返回 1；没有子节点时返回 1 |
  | Selector | 10625090 | 依次 Tick，遇到第一个返回 1 就返回 1；没有子节点时返回 0 |
  | Parallel | 10624F80 | 全部 Tick，返回 1 |
  | If | 10625130 | 黑板 int[name] != 0 |
  | If_Int | 10625170 | 黑板 int[name] == value |

  - Tick 的签名是 `(owner, ctx)`，`ctx+4` 是黑板。
  - 黑板 API 由用法推断：vt40 GetInt、vt44 GetFloat、vt48 GetString、vt76 SetInt、vt80 SetFloat。

**更正（2026-11-08 写服务端时按 `ctor-full.asm` 重读）**：Idle 是根 Selector 的第三个子节点，不在 FindTarget/FindPath 的 Sequence 里。依据：

- 10984932..10984945 添加 Idle 时，`ecx = ebx`；
- ebx 来自 109848F7..109848FC：`[[FindPath 叶 builder + 0x14] + 0x14]`，也就是 Sequence 的父节点（根）。

所以只有“没有目标”或“寻路失败”时才会 Stop；有目标时，寻路之后不会立刻 Stop。此前的图把 Idle 画在 Sequence 内，是错误的。

**ZombieBoss_* 叶节点**：先用 RTTI 把 `owner+4756` 转成 CBaseZombieBossImprov，再调用 vt[113..117]。

**SkillSelector (10A212D0)**：

- 读黑板的 `next_skill` 和 `cur_skill`，经 FNV 哈希表（10A20F90）找到对应的技能叶节点。
- 如果有 `next_skill`：
  1. 对旧技能调用 vt24（End）；
  2. 设 `cur_skill = next`、`next_skill = −1`；
  3. 调用 vt16（Bind）和 vt20（Start）。
- 每次 Tick 调用 vt28（Update）：
  - 返回 0 时调用 vt8（返回值为 1）；
  - 返回非 0 时调用 vt24（End），并设 `cur_skill = −1`。

### 3.6 跳跃与重定位（第二轮）

- **109858F0 落点**：

- **10A29160 跳跃中每帧**（第 2 节已读）：
  - dir = normalize(落点 − 中心)；
  - velocity = (t·dir.x, t·dir.y, t·dir.z + (1−t)) × kickSide；

- **109859A0 BombJump 重定位点**：
  1. 取目标点：handle 有效时用目标，否则用 BOSS 自己；再用 vt108 修正 z。
  2. 求距离 d：
     - 跳跃中：BOSS 到当前落点的水平距离；
     - 否则：`max(1000, 到目标的水平距离)`（常量 11EF6A98 = 1000）。即 `1000 > d` 时用 1000，否则（包括无序比较）用 d。

  4. 用 `11348AB0(目标点, 120)` 查导航区域（即 GetNavArea）。若落点不在该区域的三维范围内（包含边界，含 z；无序比较视为在范围外），改为：落点 xy = 目标 xy + FastNormalize(区域中心 − BOSS 原点).xy × d，z 仍取目标 z。
