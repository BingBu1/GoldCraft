# 喷漆尺寸与攻击伤害数字

用户要求喷漆恢复此前的墙面尺寸上限，并修复攻击玩家、灾变怪物和可受玩家伤害的灾变墙体时没有伤害数字的问题。本次修复已构建并部署到隔离 B 和专服。用户已分别确认攻击怪物的伤害数字“能看到，显示正常”、喷漆“大小合适”。普通玩家与可伤墙体已通过真实 SDK 回归，尚未补齐对应实机画面；多人验收未完成。

本次范围是工作区中的 MetaHook/ReGameDLL 适配；保持 GIF、HTTP 共端口和 10 MiB 上传限制。喷漆长边恢复 48 世界单位并保持比例，这是用户要求的自定义回退，不称为原版 CSOL 标准。生产安装始终只读。主协调持有共享文档和发布索引；用户已明确“允许更新并恢复实测”，主协调交付独占 B／专服／UI 窗口；此前 UI 暂停已由该直接授权解除。

## 生命周期与测试边界

通知持有地图/runtime/session/round、EHANDLE 与玩家出生序号，并在引擎和虚函数回调后重新检查。墙体还验证 rules generation、私有对象生命和操作 serial；致死待移除墙体允许发送最后一击，但实际换图、释放、重置后的旧调用会取消。怪物保留 pool lease、behavior 及 ordinary 的既有 SpawnState，避免同一 lease 内 ResetForSpawn 后把旧伤害发给新状态。friend 声明不增加字段或虚函数；所有实际头消费者仍按依赖重编。

`sdk-04` 用真实完整 Session/工厂/伤害/墙规则执行：怪物 3673/0、玩家 3003/0、墙体 3265/0。同 lease 的真实 ResetForSpawn 在扣血后的 OFFSET 回调发生，旧 guard 出现唯一预期失败（3211 项中 1 项），证明仅检查 pool/behavior 身份不够。

墙体夹具保留原黑暗之门 hmdmgratio=0 的负例。该地图的奖励 threshold=0 与不可受玩家伤害的墙配套；直接改夹具墙比例会触发生产非正奖励阈值保护。可伤墙采用明确受控的 hmdmgratio=1、threshold=125 输入，调用真实 Spawn、Difficulty、Session Players、WallRewards 和 CBreakable；未修改生产地图比例、奖励保护或伤害规则来让测试通过。

玩家测试进入真实共享护甲后提交函数，分别覆盖正常和爆炸尾、截断及爆头；它不执行前置完整玩家 TakeDamage/护甲计算。怪物测试执行真实 TraceAttack、多弹丸累积和 ApplyMultiDamage，再验证一次通知。SDK 的引擎世界、消息和文件边界受控；这些计数不是鼠标弹道或游戏画面的实机证据。

正式 `sdk-05` 基于墙机/字体双端03的已核输入，重编 81 个实际服务端消费者，增加 runtime 退休、墙 Restart、同 lease ResetForSpawn、消息回调与重入检查。最终 SDK06 六组全部通过：怪物3673/0、墙3265/0、玩家3096/0、同lease重置3199/0、runtime退休3198/0、墙Restart3161/0，共19592项零失败。冻结夹具有 96 项普通文件和 2 项按匹配 eiface.h 生成的 include；原 plan 的 sources 保留生成前记录，生成后身份正确记在 inputs/known/observed。原 plan 不重写，另用 `generated-source-reconciliation.json` 核可复现内容及实际 include 消费。
