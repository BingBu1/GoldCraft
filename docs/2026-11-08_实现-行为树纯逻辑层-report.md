**SkillSelector 的调用顺序**（按汇编，纠正了先前对反编译的读法）：

1. 找到 `next_skill` 对应的状态时：
   - 若有旧状态，先 End(旧)；
   - 设 `cur_skill = next`、`next_skill = −1`；
   - 依次调用 Bind(owner)、Start(ctx)。
2. 只有当前状态、没有新状态时：**每一跳都会先调用 Bind(owner)**（10A21361..6C），不调用 Start。
3. 然后调用 Update(ctx)：
   - 返回 0：返回 Tick(owner, ctx) 的结果；
   - 返回非 0：End(ctx)，设 `cur_skill = −1`，返回 0。
4. 两者都找不到时：若 `cur_skill` 的完整 int 值不等于 −1，且 owner 通过两次 RTTI 检查，就调用 10A27670 结束技能；返回 0。

### 未读到原版的部分，按以下方式处理，不猜

- **黑板存储**（引擎接口 12278844 vt1076 创建的对象）：原版每个键只按一种类型使用。混用类型时返回 fallback，并让 `Consistent()` 变为 false，由宿主拒绝。没有实现原版可能存在的跨类型转换。
- **SkillSelector 插入**（10A20B30）：没读，不知道重复键是先到者还是后到者生效。所以 `Add` 直接拒绝重复键和 −1；31500 的树里没有重复键。
- **默认 Start 没有当前行时**：原版 10A20F10 不检查空指针，会直接读空行。这里改为调用 `Fail` 并返回，作为宿主契约违例上报。**这是宿主保护，不是原版行为**；上层的 UseSkill（10A29600）在没有行时返回 0，正常流程走不到这里。
- **节点返回值**：用 bool 表示。原版 Sequence 判断非 0、Selector 判断 `== 1`，两者只在叶节点返回 0/1 以外的字节时才有区别。已读的叶节点只返回 0 或 1（`sete`、`mov al,1`），宿主叶节点也必须这样。
