## Path 与源码对应

P-001，`path_type=callflow`：原始输入分发先检查锁（F-001／E-001），脚本 `StopPlayerControl` 写锁并按条件清键（F-002／E-002），引擎清键最后通知 `IN_ClearStates`（F-003／E-002）。宿主中哪些脚本/控件应发同等锁、如何恢复，以及拦截表 `+34h` 的完整副作用仍待证；本阶段没有据此写一个菜单锁替代品。

P-002，`path_type=callflow`：真实 stamina frame owner → 原生 `ResetMaxSpeed` → 原生 `UpdateClientData` → 真实链接的 `PM_CheckParameters`（F-004／E-003）。新增 `tests/csol-standalone-prediction/sdk.cpp` 执行该链；`tests/csol-standalone-frame/sdk.cpp` 仅增加入口保护宏以共享既有夹具。生产 `client.cpp`、`pm_shared.cpp` 没有修改，逐SHA核对与完整封存输入一致。

## 验证层级与时间线

1. 先复核原始客户端、CSO引擎及477条指令。批量 IDA 指令查询解决旧文本搜索遗漏；19次并发查询曾有传输失败，失败文件保留，不计作证据通过。
2. 新夹具首轮因重复 `main` 编译失败，已通过命名保护宏修正；第二轮严格整服封存检查正确拒绝后来改动的共享 `game_rules_gate.h`，该失败保留在 `build/standalone-native-prediction-sdk-20261116-02`。
3. 第三轮明确作为组件构建：重编当前控制器、action_stamina、stamina与夹具，复用逐SHA封存支持对象。4组153行为／5721 SDK检查通过，352个记录输入在该构建期间稳定。它不是当前整服验证，不能覆盖第二轮拒绝。
4. 离线汇总脚本再次核样本、PE架构/基址、1667B、477条IDA边界、字符串/函数表，以及原生 `client.cpp`／`pm_shared.cpp` 和两支持对象的实际封存来源。

覆盖武器派生步行 `.5`、疾跑 `1`、蹲 `.8`，命令不自行推进帧，真实快照速度，服务器/预测标记下的对角限速，回合冻结／FL_FROZEN优先级、sv_maxspeed、80单位位移扣8体力，以及预测查询不重复扣费/恢复。没有新生产热路径或运行时成本；测试耗时不代表游戏性能。
