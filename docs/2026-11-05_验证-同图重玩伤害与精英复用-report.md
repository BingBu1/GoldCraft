# 同图重玩伤害与精英复用独立验证

本记录验证“重玩此地图之后怪物不扣血”，与后来提高难度触发的技能 11 未实现拒绝分开。生产修改由主任务持有；本验证只修改夹具、执行冻结源码/对象，不操作游戏实例或发布。

## 原证、实现与边界

原 MP SHA-256 为 `39f962f34816411e615f01e5279d914204f7fd07c5a5112b0b303acafe0308b2`，x86、基址 `0x10000000`。原命中阶段 `11386B9A..11386C08` 调用 `10823570` 获取当前难度；精英虚表 `11803454 + 114` 指向 `106129F0`，原字节 `B0 01 C3` 返回 true，工厂 `11385644..1138566F` 据此重建行为。主任务在生产修改前重新核对身份与字节，证据为 `build/replay-fix-20261105/evidence-before-edit.json`、`elite-before-edit.json`。

生产四源固定在 `build/replay-fix-20261105/selected-01/manifest.json`：伤害头/实现、怪物服务实现、精英行为头。奖励对象按当前 Session 每次命中取得属于宿主生命周期适配，不声称原版使用相同 C++ 所有权结构；精英重建标志按原 v114 还原。

## 真实 SDK 负例

`tests/csol-scenario-2gate/replay_damage.cpp` 包含已冻结的完整 Session 夹具，链接实际服务端 351 个对象。保留真实规则、地图、池、工厂、伤害、Replay 和奖励；仅引擎世界/Studio/网络边界受控。命中直接执行真实 `TraceAttack` → `ApplyMultiDamage`，不能据此宣称实机弹道几何或视觉通过。

原部署基线是 `build/season1-integration-20261105/server-full-02`，DLL SHA-256 `ab8825a4b5ebbc10e4a2bb6efc4c032921adea986a0c3ea16ffc477f7085f977`。其对象混有 2492/2504 字节玩家布局。原夹具链接选择了 2492 字节模板并损坏 guard，但部署 DLL 自己的 `GetClassPtr` 最终选择 2504 字节；不能将夹具分配错误冒称已证明生产 DLL 在此少分配。独立证据在 `build/player-abi-audit-20261105/fixture-linked-allocation.json`、`linked-allocation.json`。

为排除此干扰，旧逻辑负例仅把 `CSPlayer`、`gamerules`、`ggrenade`、`triggers`、`weapontype`、`pm_shared`、`cbase` 七个旧 ABI 对象换成全量重编的同有效源码对象。七项源码 SHA 完全一致；编译返回 0、未知输入 0。清单为 `build/2gate-damage-audit-20261105/abi-replacements.json`。拼装后的 351 对象由 `Check-ServerPlayerABI.py` 检查：175 份类型记录、10 个分配模板、0 失败，记录为 `old-logic-abi-gate.json`。

第一组 `replay-old-consistent-01`：首次命中 27→12，第一次 Replay 分配新槽仍 27→12；第二次 Replay 复用旧槽变成 40→40，错误为空、未拒图。4102 检查只有“不扣血”1 项失败，无 allocation guard 破坏。精英组在创建前被夹具选中的出生点 0 跳过，不能算生产失败；第二组诊断确认返回 Skipped、错误为空。夹具随后改为选择真实已注册且正编号的出生点，不改变生产条件。

第三组 `replay-old-consistent-03` 在真实点 1 成功创建精英，实际 Replay 后在槽位复用时拒绝：`ordinary behavior requires a valid propensity0 spawn`。5083 检查、2 次失败报告对应同一次帧断言/异常。与主任务实服观察到的拒绝一致。

最终冻结夹具追加旧奖励回调取消检查：旧 owner 配新 SpawnCall、新 owner 配旧 SpawnCall 都必须返回 Cancelled，资金、血量及 owner 错误保持原值。第四组 `replay-old-consistent-04` 的伤害部分 4114 检查中仍只有 40→40 这一失败；精英部分保持同一拒绝，12 个新增 owner/回调检查通过。所有输入前后无变化。这份夹具将原样用于修复后正例。
