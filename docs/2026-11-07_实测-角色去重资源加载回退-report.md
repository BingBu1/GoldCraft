内置 HTTP 依据地图资源表记录文件大小，所以重启专服重建登记，而非只运行 `mc_http_refresh`。真实 HTTP 完整读取149资源，各项状态200、长度和 SHA 均与新产物一致。新单 B 成功入服，原生扩展资源清单3429/3429完成、receiving=0、viewReady=true。B 是受控更新现有缓存；当前 v4 自动 SHA 更新未启用，不能称玩家自动更新已验收。

## 已证代码差异与下一步

旧部署角色没有 SequenceSafety footer，新生成角色有完整元数据。源码显示客户端 `LoadStudio` 先 `ReadSequenceSafety`，`SequenceLoadScope` 再通过 `PreparedSequenceModel::Read` 进行第二遍完整 RLE 验证；普通服务端实际加载的 decode/prepare/storage 为三遍，任意可变 hookchain 可能另增一遍。旧文件在 footer 不存在时提前返回，因此这些旧模型的既有微基准不能证明 tagged 校验便宜。

owner 每帧检查并不重新全扫 RLE，已复用本次加载证明。另有 tagged 采样期间关闭 Renderer 骨缓存的行为，必须与加载校验开销分别测量，不能直接撤掉保护。

最窄后续方向是在**同一不可变加载事务**中传递首次完整验证的所有权证明，保留分配/复制/代次/实际采样检查。当前 PreparedSequenceModel 仅含元数据，没有独占输入字节，不能直接与任意另一 buffer 配对；新加载、变换或可修改 hook 后均须重验。该方向尚未实现，不按文件名或 owner 地址长期缓存成功结果。
