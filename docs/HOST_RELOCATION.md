# MC 服务端传送与骑乘

原版末影珍珠等服务端传送会调用 `ServerPlayNetworkHandler.requestTeleport`。原版 `ServerPlayerEntity.startRiding` 在成功上船后也会调用它，将玩家对齐到座位。旧桥接逻辑无条件撤销控制绑定，随后重新向 CS 申请控制并对齐旧 CS 坐标，因此传送和上船都可能被拉回。

现在，同一世界、同一玩家生命与连接下，已经收到原生服务端 `UPDATE` 确认的有效控制绑定可以保留。目的地必须满足实际 GoldSrc 玩家 clip hull、动态实体、MC 方块／实体和世界边界，并且不能移动被冻结的坐标轴。初次 `OPEN` 仍需对齐原生位置；过期、换世界、重生、换连接、身份不匹配等情形仍撤销并重新申请。

原版传送包和确认流程保持：传送请求不被取消；确认前不发布带授权证明的位置；只有匹配的原版确认解除屏障。连续请求、相对传送标志、确认重发都不延长授权期限。MC 1.21.1 的请求参数是绝对坐标，相对标志只影响发送给客户端的包。

骑乘位置本来就由 MC 服务端读取实际玩家位置发布，不依赖普通步行包的观察记录。本次修复上船对齐触发的绑定撤销，不修改原版船的速度、碰撞或乘客控制规则。
