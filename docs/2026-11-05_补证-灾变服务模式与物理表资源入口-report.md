# 灾变服务模式与物理表资源入口

本阶段仅增加显式模式的加密 round 资源入口。没有从 `SubType==4`、文件名或 `room` 表头猜出 mode 15；`MapResources` 尚未选择此入口。保留既有函数、类布局、普通地图事务及调用者 ABI。

## 当前宿主与准确缺口

实际 `native/csol/server/game_mode.cpp::GameModeService` 只锁定宿主模式 `0/1/2`，当前 `native/csol/scenario/map_catalog.hpp/.cpp` 只提供 subtype、numeric map ID 与难度来源。`MapResources::BeginMapFromCatalog` 没有原服务 mode 字段；`BeginMap` 接收的 `scenarioType` 明确是 manager subtype。这些宿主字段不能替代原服务 mode 15/48。

原 HW `37AA2230` 的上层选择者仍需从 vslot `3C4` 的调用链闭合。另一个成对 setter `37AA8230` 的直接 caller `378347EF..37834800` 从保存的两个全局字段取参；`37835A40..37835A6D` 把这两个字段地址交给 `37AA7DD0` 导出当前服务状态，不能将这条保存/恢复候选误写成目录选择。这些候选只作后续检索线索，不作为新游戏模式的准入依据。

因此本阶段不修改 MapResources 或 Session。父任务后续须先确定明确的原模式生产契约，再决定在哪个真实规则入口传入 mode；不能设置隐含默认、按文件名分支或拿 subtype 4 当 15。模式 48 的其他 metadata 消费差异同样未完成。

## 改动与验证边界

新增 `ReadPositionalRoundResource(encoded, originalServiceMode, output, error)`，复用已有私有副本解码、只裁尾 NUL 的校验，再调用上一阶段已证的 positional parser。错误不改原加密输入或旧输出。原 `ReadRoundResource` 保持命名列 API，既有调用者行为不变。

`round-resource-01` 与精确发布候选 `round-resource-02` 均通过：新加密入口 **187/0**、原命名资源测试 **128/0**、原地图资源事务 **321/0**。实际六原表在显式 mode 15/48/0/4/59 下和独立原 HW 明文解析结果全字段/偏移一致；无假设把 subtype 4 自动改成 mode 15。损坏长度、过大输入、嵌入 NUL、后续行数字扫描失败、缺列表列、坏引号、不完整 metadata 均保留原密文与旧表；尾部 NUL 裁剪和物理空行保留正常。

原 HW `37AA22B0` getter另有 **1024 个原指令组合、0差异**，覆盖全 256 mode 字节与四种显式 session type。mode 15/48 无隐式改写；特殊 session type 1 的原重映射仅为 0→6、32→35。外部 session-type vcall为已声明替身，不替换 getter 指令或将原表推断用于生成期望。

16 个真实 TU 以固定 Clang x86/C++20/O3/ThinLTO/AVX2/precise FP 编译、三个 EXE 链接和执行通过；编译顺序执行，链接最多两个 worker。431 份输入/实际 include 前后未变。首轮使用工作树当前已有 MAP_TRG 候选，但这不归本任务；为排除夹带，第二轮 `round-resource-source-02` 固定 main `8fadf2562910a1e9b566aaef991b9e68b734ffd3`，仅加入本次显式 wrapper 与独立测试，再次完整通过上述组件检查。既有候选在工作树保留，本次未修改 `map_resources.hpp/.cpp`。

源码冻结交付必须选择 `round-resource-source-02` 中的两份资源源文件，不直接整文件发布含既有 MAP_TRG 候选的工作树版本。报告与测试入口来自本次独立路径。未进行完整 DLL、部署或实机测试；上层 mode 生产者缺口仍如上，MapResources/Session没有接入该新入口。
