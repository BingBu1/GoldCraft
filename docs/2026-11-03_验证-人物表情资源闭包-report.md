`deploy-01/receipt.json` 记录最终 527 文件部署：B 的 CSOLSupport DLL/PDB 和新 J 绑定配置共 3 项，专服 524 项。6 个旧文件独立备份、521 个新增，全部独立临时文件校验后原子替换；未预填客户端资源，其他配置、旧配套和保护安装保持。客户端产物为 `e65c7ed8`，GameDLL 为 `99d46a3a`，引擎为 `e98e69dd`，均核对完整 SHA 和匹配 PDB。

首轮 `server-live-01` 实际发现 SKULL-2 与 SKULL-5 的伤害 JSON 未进入初始资源部署集合。按完整 DLL 对象出处核查十份实际配置路径，只补两个缺件，保留八份已有配置；`deploy-configs-02/receipt.json` 记录补充事务。首次补充检查器误把 beamgun 配置定位到统一 config 目录，尚未改运行文件便停止；该失败脚本保留于 `deploy-configs-01/runner.py`，后改用真实 server/config 来源。

补参数后 `server-live-02` 启动超时。独立 x86 CDB 全线程栈与 `/ma /u` 转储确认它是隐藏的 `Sys_Error` 模态框：`CSkull5::Precache → PF_precache_model_I_internal → Mod_LoadModel`，正文为 `Mod_LoadModel: models/v_skull5.mdl not found`，并非技能 AV 或 AI 死锁。完整现场保存在 `server-precache-debug-01`，完成栈和错误文本审阅后手动结束该自有诊断进程。

随后用已验证收集器核查十二把实际激活武器，共 340 项资源，发现 13 个缺件；`deploy-weapons-01/receipt.json` 已只补这些文件，327 项已有资源保持。两项与 common 不同的已有内容 `models/v_beamgun.mdl`、`sprites/csol/640hud6.spr` 未覆盖，差异记录于 `weapon-closure-01/plan.json`。累计本批 542 项写入（B 3、专服 539），不修改此前 527 项原始回执。

`server-live-03` 已正常加载穷途末路并给出完整四张资源表：generic 2078、model 518、sound 413、event 39；五个实际模块 SHA 与部署配套一致。移除旧技能计划中过时的 `hud_v3.json`、`buymenu_v5.json` 下载预期，并加入本轮缺件后，B 共 704 项待实际下载。然而其中五项没有广告：`gfx/tattoo/MaleShort.tga` 和四个 `sound/weapons/skull5_{boltpull,clipin,clipout,draw}.wav`。这次验证在广告检查处明确失败，492 文件 HTTP 检查尚未执行，B 尚未启动。
