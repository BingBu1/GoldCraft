# CoF 库存恢复隔离与切枪重试

本次优先落实用户要求的可购买、可切换和可使用。修改针对同图后续回合、出生或模型生命周期退休后端后的恢复；不新增原版玩法规则。

实际 Host 原先遇到任一继承武器重绑失败，就将整名玩家的 `prepared` 清零并中断遍历。该字段又是所有客串武器的购买准入门。一把枪的失败因此会连带拒绝其他有效武器。九把已接入身份的 `CanDeploy` / `Deploy` 还只检查旧绑定，没有在明确选择时尝试重新取得当前库存权限。

本次修改：

- 真实 `guest_cof_host.cpp` 改用 `RecoverRetainedGuestInventory`。逐件恢复，分别记录成功和待重试项；单件失败不撤销已建立的玩家后端，后续库存继续恢复。
- Glock、P345、左轮、VP70、TMP、MP5、M16、G43 和 870 在明确选择且绑定已退休时，调用共同的 `RecoverOwnedInventoryBinding`。它只接受当前存活玩家实际持有的同一库存对象，再通过该枪冷 Host 获取当前权限并执行完整 `Bind`。
- 正常冷却、装填等状态不会触发重绑。弹药与库存实体保留；不重发枪、不重置弹药、不回放旧生命快照或旧延迟任务。
- 两种库存扫描都以实际引擎实体上限收束；精确用满上限且链已结束视为完成，循环链会明确结束并报告未完成。

证据与实现对应：

| 证据 | 结论 | 实现位置 |
| --- | --- | --- |
| 已发布的第二回合库存修复报告、实际 ReGameDLL `RoundRespawn` / `Spawn` 及库存消费者 | 存活玩家可以保留旧库存，但需要新生命的有效后端；旧快照仍不能跨生命 | `native/guest/cof/server/inventory_recovery.hpp` |
| 修改前实际 Host 恢复循环和 `CSOL_GuestCofCanUse` | 单件失败写入玩家级门，扩大成全武器拒购 | `native/csol/server/weapons/guest_cof_host.cpp` |
| 九身份实际 `CanDeploy` / `Deploy`、冷 Host 与 `RestoreInventoryBinding` | 明确选择时可以重新认证真实库存，不能复用退休权限 | 八个原生武器实现文件；TMP/MP5 共用自动武器模板 |
| 修改前原样本和 IDA 窗口全文核验 | 本次是宿主库存适配；不据此改写原射击、换弹、机瞄或音效 | 原武器逻辑保持，新增恢复接点单列 |

原 CoF MP 为 PE32/x86，基址 `0x10000000`，SHA-256 `0036b91c01e92ed205513f52563053a55a66a32d257efb5f476b8f1f3dde0e63`。原证复用前全文及八个区域逐项核同；本轮也读取自有 IDA 会话的工厂、预缓存与 Spawn 三个窗口。私有证据位于 `analysis/cof-weapons-20261111/availability-20261118/`，含修改前 `PREEDIT.json` 与当前 IDA 字节记录。原武器证据的生命周期背景见已发布的第二回合报告。本次不把宿主恢复声明为原 CoF 的内部代码结构。

验证分层：

- 旧代码反例 `build/cof-availability-old-20261118-01` 编译通过，并在失效后再次选择的新增检查处准确失败。
- 最终九枪组合 `build/cof-availability-runtime-20261118-03`：5,615 项 SDK 检查、真实 Host 编译通过，编译器实际依赖前后核同。包括 M16 1,031 项、G43 1,525 项、870 1,973 项组合检查；这些是分组，不能重复累加成总数。
- 最终 Glock 原指令及新增恢复检查、完整服务端 DLL 的结果在本报告末节记录。

首个对象复用请求因生成的 SDK 适配器发生变化被正确拒绝，随后完整编译。第二批编译期间进一步收窄了三把枪的重试条件，因此即使其执行结果通过，仍因源码前后变化被判无效，未用于部署或发布；最终第三批按实际依赖键重编变化对象并核同所有输入。没有放宽校验。

成本与边界：恢复只增加在出生、模型变更和失效武器的明确选择处，无新堆分配、无绘制或逐实体工作、无同步文件或网络读取。正常选择多一次当前绑定检查；失效选择扫描的最坏成本受实体数限制。本次未以微基准或 SDK 数量宣称实机 FPS 通过。真人连续回合、多人和实机性能仍待验收。
