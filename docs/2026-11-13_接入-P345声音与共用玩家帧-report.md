# P345 声音与共用玩家帧

本阶段接入 P345 的四类实际原生声音消费者、正确空击冷资源，以及借用同一玩家生命周期／输入／跳跃状态的 P345 视图。声音、原状态、SDK、资源候选与完整运行验收分开记录。P345 尚未开放购买或部署；当前 Glock 效果保持，接续顺序仍为 P345→左轮／VP70→其余武器与变体。

## Evidence

E-01：匹配原 MP `hl.dll`，x86／基址 `10000000`，SHA-256 `0036b91c01e92ed205513f52563053a55a66a32d257efb5f476b8f1f3dde0e63`。P345 虚表 `101B5464+190` 的原字节指向 `1011E4A0`，完整 81 字节 EmptyPlay 经 fresh IDA 核对：真实空击标记非零选 `weapon_fire_empty.wav`，零选 `weapon_fire_empty_noclick.wav`，普通声音发送后清标记。原袖口 `1011C3FE..1011C4BC`、拾取 `1011CC54..1011CCC6`、弹药拾取 `1011B737..1011B77A` 和 `100FC9F0` 的普通 WAV 音量转换继续复用已核证据。私有修改前映射在 `analysis/cof-weapons-20261111/p345-integration-20261113/native-sound-before.json`，fresh IDA 在同目录 `empty-sound-review.json`。

E-02：原玩家散布阶段 `100EF7B2` 在后续输入之前；按钮边沿在 `100EFCBA..100EFCE2`，实际跳跃门为 `100E5030..100E509B`，跳跃记录 `100E520F..100E522F`、落地清理 `100EB22D..100EB25E`。原状态和宿主模式约束见私有 `owner-state-implementation-gate.json`、`native-owner-preedit-gate.json`、`P345_OWNER_INVENTORY_REVIEW.md`，本轮接线审查在 `p345-integration-20261113/canonical-owner-review.json`。Native CS 移动、没有手机／物质／未知来源覆盖、有限弹药和第一人称是被宿主认证的明确模式限制，不声称原版默认值。

E-03：近战八声音顺序、RNG／发声／命中／震屏／递归伤害由原 `100F9790` 和 `100FC9F0` 建立。此前完整 33 窗口／17,013 字节核对、源码与冷资源所有者审查在 `model-evidence/melee-samples-review.md` 和身份记录。本次只把必须已经准备且存活的路径表交给原消费者，不能在热路径发现资源或回退到未准备的原路径。字段／通道不按 WAV 名称推断。

## Finding → 实现 → Path

F-01，severity=n/a_re，evidence_ids=E-01/E-03，confidence=high，status=validated（实际声音参数）。`guest_cof_p345_native_effects.*` 实现 EmptyClick、Sleeve、PickupSound、AmmoPickupSound；公共 `guest_cof_native_sound.hpp` 保存相同的权威快照／结果类型，P345 声明不依赖另一整把武器的后端。实际 EmitSound 前后检查所有者、实体序号、私有对象、地图资源代次与回调退役。保持原通道、音量、衰减、音高、字段清理和独立拾取抑制。开火声仍须经原 PlaySFX，未以普通发声代替。

`resource_catalog.hpp` 与资源候选工具补齐 P345 的两种通用空击声；已有 p345_click 资源保留其原消费者。`weapon_melee.*` 接受明确的八路径冷表，`guest_cof_melee.hpp` 给出不可变 P345 命名空间表；缺项在 RNG／音效／伤害前拒绝。P345 Prepare 同样检查冷表，袖口严格采用原 `armorvalue != 1` 分支，包括非零非 1 与 NaN；旧错误的 `==0` 不继续发布。

F-02，severity=n/a_re，evidence_ids=E-02，confidence=high，status=validated（宿主阶段／隔离）。新增 `OwnerFrameWeapon` 能力，Glock／P345 保留原 AdvanceOwnerFrame 和 Invalidate 实现；既有 `GlockOwnerRuntime` 的有界实际库存遍历按能力调用，不再只认识单一具体类。没有第二个逐玩家时钟，也不因切枪重新建立按钮边沿或跳跃状态。

`P345OwnerView` 借用按值捕获的 canonical OwnerBinding，只独立冷准备 P345 的 Stock／CSO 动作及显式伤害／24或80备弹规则。视图 key 包含不可复用代次，准备、读取、动画／实体／出生／模型／地图变更和回调退役均校验；失败不发布半个输出。视图和外部回调必须随地图所有者保留至真实实体释放完成，Invalidate 只撤销权限，不负责销毁外部存储。

P-01，path_type=callflow：原 P345 虚表与共享消费者（E-01）→冷声音目录／固定路径→真实原生发送器（F-01）→原指令参数对照；原 owner 阶段（E-02）→一个 canonical 玩家状态→真实库存能力扫描→P345 独立动作／规则视图（F-02）。实际购买、客户端事件／HUD 和多人传输仍是后续链路。
