# F2 服务端装备快照与重购

用户要求 F2 重复购买按原版 CSOL 还原。原客户端按成功购买 ID 排队、反复请求商品列表的方案已从候选源码移除；重购由服务端持有装备快照并在同一调用栈内完成。菜单内的重新购买使用独立 `rebuy_in`，发送后立即关闭。当前工作区双端构建与服务端库存SDK已通过，未部署或完成真实F2输入验收。

## 宿主适配与成本

使用匹配 ReGameDLL 的 `RebuyStruct` 存储已实现字段，在 `CBasePlayer::BuildRebuyStruct / Rebuy` 入口仅为灾变分流，普通服务器保留原路径。固定 33 槽补充刀具选装、内部交付、重放和连接身份，不增设客户端商品队列。刀默认选装对应原 index0/宿主29，但未建立快照时仍是“无记录”。缺少刀实体也不丢失实际选装。

实际购买仍调用现有库存、弹药、装备、余额和刀具服务；拆弹器、盾牌、夜视保留真实 `InternalCommand` hookchain。已实现扩展枪械的数值 ID 到宿主交付服务、会话/实体/用户/出生代次保护，以及地图重置属于明确宿主适配。各可重入步骤后检查权威，旧生命或旧连接不能继续下单或清理新连接的事务标志。

客户端每次 F2 仅发出一次命令，避开商品 JSON、图像、字体和网络商品表；按用户要求没有新增输入时间门。服务端快照和重放不新建历史 vector 或排序；库存交付自身仍可能分配和调用插件。移除旧流程的多轮网络往返有源码依据，但尚无实际游戏 CPU、延迟或帧率收益结论。
