# 文件系统资源版本缓存

严格摘要缓存的实服对照确认：尽管 236 个模型全部命中依赖清单，每次热换图仍读取约 1.2 GiB，激活阶段只减少约 8.1%。本阶段通过实际文件系统提供资源版本，减少未变输入的正文读取。

## 接口与失效规则

`GoldCraftResourceStamp001` 通过当前文件系统的 `CreateInterface` 获取，不修改原 `IFileSystem` 虚表。调用时传入当前文件系统实例，提供方仅接受自身实例，避免绑定到另一个同名 DLL 或其他 provider。

`ResourceStamp` 为 80 字节固定宽度记录：卷标识、128 位文件标识、文件长度、创建/写入/变更时间，以及 PAK 成员偏移、长度和类型。查询沿用 `Open(...,"rb",nullptr)` 的搜索顺序；不以 `GetLocalPath` 的路径推测实际资源来源。

名称查询不读取 PAK 成员正文，不移动共享归档游标，并释放查询产生的临时句柄包装。真正读取正文时，对同一个已打开句柄在读取前后取版本，避免把旧内容登记成新文件版本。查询失败、原提供方不支持此接口或版本不匹配时，回退到已验证的 VFS 正文 SHA-256 校验。

不存在的可选文件仍每图检查，因此新增 JSON、SEQ、贴图或手模配置能触发重新收集。每图重新登记下载闭包，缓存不保留上一张图的引擎资源索引。

源码、实际提供方、缓存失效、完整模块和专服对照均已验证，本地专服已更新。第一版候选的工厂返回类型不匹配在 source-03 修正，早期快照保留。正式远端由独立补丁流程更新，本地部署不代表远端已安装。

真实提供方验证另复现了既有 PAK 挂载崩溃：目录加载把原始 `FILE*` 传给需要 `CFileHandle*` 的 `Read`，匹配 PDB 调用栈落在 `PreparePackFile → Read → FS_fread → fread/_lock_file`。source-04 将普通 PACK 与 PK64 的两处目录读取改用现有 `FS_fread`，保留其他目录语义。证据为 `build/csol-fs-stamp-review-20261103/provider-01/pack-cdb.log` 与转储；这不是此次元数据接口引入的崩溃。

source-05 还处理了元数据查询可用性在同批次改变的情形：版本记录与 SHA 记录属于不同校验方法，不能直接比较后报“资源改变”。此时保留正常解析和广告，但不跨图保存该条缓存；相同方法观察到真实内容或身份变化仍拒绝。source-08 将不可复用状态保持到批次结束，避免第三次读取意外重新启用缓存；两项均有旧版失败、新版通过的反例。

PACK 挂载恢复后，真实驱动继续走到卸载，并在 `RemoveAllSearchPaths → CSearchPath 析构 → Close` 复现同型旧错误：析构将 `FILE*` 传给需要包装句柄的 `Close`。source-06 修正为传入原 `CFileHandle*`，由原 `Close` 释放文件与包装。第二份匹配栈与转储保留为 `provider-01/pack-cdb-02.log`、`pack-crash-02.dmp`；没有在测试里绕开卸载。

普通 PACK 与 PK64 的完整测试通过后，附加式 PAK 测试发现原 `PACKAPPE` 标识为固定 8 字节、没有结尾零字符；旧 `strcmp` 会继续读取紧邻的偏移字段。source-07 将它改成按字段长度比较，合法的非零低字节偏移不再被错误拒绝。未把测试的包偏移改成恰好含零字节的值来掩盖缺陷。

高精度版本检查用于受控服务器资源更新；资源应在地图加载批次之间或停服时替换。批次内复用输入观测不提供外部并发写文件的事务快照。缓存预算仍为跨图估算 16 MiB 元数据、批次留存 64 MiB 正文；这些值不是整个进程的峰值内存。

## 最终结果与部署

独立 SDK 检查通过 68,926 项（含 65,536 个输入容量逐项断言），真实资源 428 项通过；实际文件系统通过旧提供方、松散文件、PACK、PK64、两种附加包和两种非法目录组。重复查询的堆分配、操作系统句柄及共享 PAK 游标均保持。详见《2026-11-03_验证-CSOL资源版本快路-report.md》。

实服六次加载覆盖失落之城的一冷三热、切到穷途末路、返回失落之城；最终 source-08 DLL 另做一冷一热。共七次失落之城的 28 份分类广告与基线逐字段一致，穷途末路四份分类保留；474 项 HTTP 正文长度与摘要通过。最终短复测沿用相同资源的 HTTP 结果，没有重复下载。

| 观测 | 秒数或计数 |
|---|---|
| 旧版六次热加载激活阶段中位 | 4.0688455 秒 |
| 元数据快路三次热加载中位 | 2.627300 秒，较上述旧样本减少 35.43% |
