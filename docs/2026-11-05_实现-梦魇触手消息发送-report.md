血屏发送函数本身不能证明应始终显示红血：原血液策略和有效目标由触手 owner 决定。此次没有设置“默认开启”，没有省略未知分支后返回成功。

## 精确构建与自动检查

`selected-source/` 从发布基线 `a315f907445e41ffb0a462c2453f6c1d65f8f442` 只增加三个方法及声明。工作树既有 `CsoTent` 候选没有混入该快照。实际 ReGameDLL 头文件来自 `server-full-02` 的冻结清单，编译选项保持 x86/C++20/O3/ThinLTO/AVX2/precise；独立测试 EXE 不代替完整服务端 DLL。

最终结果位于 `build/teddy-message-integration-20261105/sdk04/`：

- 两个实际 SDK 翻译单元和链接成功；行为 128 项、原包对照 491 项断言，零失败。
- 原包来自 `oracle02/`：54 组原 MP 指令执行、3 个未落地/半径边界排除案例。按字节比较消息路由、负载和 PVS，涵盖动态注册编号、坐标边界、模型索引边界及两种数量。
- 空文件、截断文件和半行对照输入均按预期返回失败。独立审计发现的旧夹具假阳性已修复，不能将空对照当作原版一致。
- 消息回调释放发送 owner、修改原位置/编号及跨实例重入均已测试；写包期间不再读取已释放对象。
- 实际 SDK include 来源须以同目录 `dependency-audit.json` 为准；编译前后输入身份须全部保持。

保留了失败过程：`sdk01` 缺少无关浮动伤害链接边界；`sdk03` 实际 include 审计检出测试新增的 `iostream`、`source_location` 未预登记。最终 runner 从固定工具链环境找到这两个头，在编译前记录身份，不能把前三轮结果冒充最终完整验证。

可复核入口为 `tests/csol-scenario-teddy-messages/{main.cpp,oracle.py,run_sdk.py}`；使用方式见同目录 README。没有把原版二进制、反汇编正文或运行数据加入源码发布。
