# 客户端永夜全员随身光

本功能是用户指定的自定义玩法。2026-11-16 修改前记录：光源由客户端管理，所有玩家互相可见；服务器只低频同步阶段和配置，不执行灯光跟随或逐帧网络同步。当前优先完成自定义玩法，地图扩展暂停。实际画面、多人和 GPU 性能尚未验收，不能以代码或 SDK 测试替代。

## 修改前依据与实现约束

| 依据 | 结论 | 源码路径 |
| --- | --- | --- |
| 宿主 `enginedef.h` 的普通 GoldSrc `MAX_DLIGHTS=32` | 不占用原生动态光槽，保留枪口和爆炸 | MetaHook/Renderer SDK |
| 现有 `R_UpdateExternalSceneLights` 每次移动重建向量、排序、节点与共享灯对象 | 移动灯需要独立的有界稳定池，不能每帧重发静态场景快照 | Renderer `src/gl_scene_lights.cpp` |
| `R_AddVisibleDynamicLight` 使用眼点、视锥及 PVS | 复用实际可见光裁剪与延迟光照 | Renderer `src/gl_light.cpp` |
| `R_RenderShadowmapForDynamicLights` 动态后备分支绘制 WORLD 与 OPAQUE_ENTITIES | 移动灯不缓存旧位置的静态阴影；保留 BSP 和实体遮挡 | Renderer `src/gl_shadow.cpp` |
| 当前 `CsoEnv` 固定 32 字节、`CsoTime` 已有阶段状态 | 不更改现有包 ABI，增加独立低频控制包；不发送坐标 | `native/csol/scenario/custom` 与 `server/custom/challenge_environment.cpp` |
| SDK `ref_params_t`、`cl_entity_t` 的预测和网络实体 | 每客户端本地跟随存活玩家，拒旧帧/观战实体；无需服务端照明实体 | `native/csol/client` |

这是宿主源码适配，不使用原版 DLL 偏移，也不冒称原 CSOL 默认参数。自定义初始参数为半径 128 GoldSrc 单位、亮度 48/255、中性白色，均放在一个 gameplay.json 中，可调整。默认永夜启用；正午/黄昏/结束关闭。灯池最多 32 个，初始化后位置更新不分配、不查询配置文件、不调用网络。

## 实现与配置

客户端 `night_player_lights.cpp` 接收策略并使用本地 `ref_params.simorg` 预测位置与其他玩家的 `cl_entity.origin` 插值位置。有效消息帧、玩家身份、模型、隐身/观战、远端 solid/movetype 与本地生命值共同决定当前灯集合。CS 的远端玩家增量没有 health 字段，不能依赖该未发送字段把所有灯灭掉。宿主 `PM_LadderMove` 使用 MOVETYPE_FLY，须允许存活爬梯者；死亡的 TOSS 与非实体仍排除。重生重用固定身份，断线/PVS过期/死亡/结束和地图清理移除光源。每客户端都执行同样的选择，不只为自己点灯。

服务端 `challenge_environment.cpp` 只发布24字节 `CsoNLight`：版本、开关、阶段、亮度、半径、颜色、修订号与回合所有者。没有坐标、实体创建或玩家掩码。不可变内存配置指针变化后才重新读取三个数字，不在逐帧工作中读取JSON；无变化不发包。原32字节 `CsoEnv` 与19字节 `CsoTime` ABI保持。

Renderer新增独立 `MovingLights_API_001`，预备固定对象与完整原生灯池的可见列表容量，热更新不排序/重建BVH/分配对象。原生32灯及现有静态 SceneLights001继续工作。可见移动灯用256像素动态立方体阴影；不缓存错误位置的静态阴影，动态分支包含地图BSP与实体，并隐藏发光玩家自己的身体。最多32灯且保留视锥/PVS裁剪。此处的CPU边界测试不证明32灯的实际GPU帧时间。

统一JSON新增 `night_player_lights` 功能组与 `night_player_light_radius`、`night_player_light_brightness`、`night_player_light_color`，M管理员页有中文字段名，沿既有userid/修订/权限与异步原子保存链修改。注释仍每项最多512字节；整份文档有界容量从64增到96KiB，使全部合法注释最坏转义也能落盘再读。另保留/审阅已取证的绝命档案按位移费用schema及旧CoF单位拒绝迁移测试，完整疾跑能力仍不开放，不以本批照明宣布破坏性玩法全部完成。
