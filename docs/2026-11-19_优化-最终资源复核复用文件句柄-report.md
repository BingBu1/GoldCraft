# 最终资源复核复用文件句柄

本次保留两次完整的原生 VFS 路径解析，缩减第二次解析后的 Windows 文件重开。改动位于 `native/client/resource_cache.*` 和 `native/client/resource_update.*`。文件系统、HUD 和地图宿主的调用次序沿用已有实现。

## 宿主证据与实现

- 样本为 x86 `FileSystem_Stdio.dll`，SHA-256 `07a432b6214c6ea5ea4a988d5c8384d3ab35a531b49fe71c354f3fed5ce9f316`，IDA 基址 `0x10000000`。源码编辑前逐字核验从 `0x10002820`、`0x10006D00`、`0x10005571`、`0x10001240` 开始的 1,137 字节，覆盖打开、路径选择、定位和文件句柄初始化，另核对了 `_fileno` 导入。私有取证记录在 `analysis/map-transition-20261118/lease-host/reader-abi-verified.json`。
- 第一遍证实 SHA 后保留独立只读句柄。第二遍仍在引擎线程重新解析 VFS，并交给工作线程核对新句柄的完整元数据、卷序列号、128 位文件 ID、资源偏移与长度。全部匹配才沿用第一遍的 SHA 和只读句柄。证明失败时独立重开并重新读取 SHA，即使旧摘要仍在缓存。
- HTTP 传输开始前释放初次校验留存的句柄。最终通过的句柄持有到本次复核完成。测试覆盖同 PAK 不同偏移、高优先级路径抢占、传输期间文件变化、取消与回滚。

## 验证

组件测试使用原生 x86 文件系统和实际本地 HTTP。最终版 23 项全部通过。旧版在重复重开计数回归中失败。高优先级路径回归先为候选文件建立旧摘要，再验证首次命中和最终命中不同的情况。仍读取旧摘要的中间版在此回归准确失败。

完整 `GoldCraft.dll` 使用最后已部署版本的其余链接输入，只重编两处资源校验翻译单元。编译、链接和 PDB 身份匹配通过，478 项输入在构建期间稳定。DLL SHA-256 前缀 `94c72a40c959`。编译与组件回执在 `build/vfs-reopen-20261119-full/receipt.json` 和 `build/vfs-reopen-20261119-final-checks/result.json`。

单个沙盒 B 使用同一 ReHLDS 进程和同一份地图、引擎及其他插件。更新前核验 322 项服务端 HUD 资源。新版客户端首次入服和跨图后达到原生状态 5，实际加载的 CSOL 血量与金钱数字纹理均有效。跨图比较从 `zs_deadend` 到 `zs_lostcity`。

每轮记录实际主线程 PC、代表调用栈及进程 I/O，共 37,571 个主线程样本，采样器无失败。两轮均读到原生 GameUI 接收资源阶段。两轮进程启动与操作系统缓存状态有差异，文件重开次数可直接归因于这次改动。整段耗时需要重复的同条件对照，进度条视觉仍需界面验证。新版仍出现窗口未响应，开始接收清单前等待约 26.65 秒，原生恢复约 3.76 秒。下一阶段继续对照服务器准备和客户端原生恢复。

新版随后换回 `zs_deadend`，41.97 秒完成原生 HUD 回调确认。该次 3,481 项资源进行了 6,962 次 VFS 解析，复用 3,478 个文件句柄，血量和金钱纹理继续有效。

旧版基线客户端在换图完成后的正常退出出现 `CSOLSupport.dll+0x885F5` 访问异常。匹配符号定位到购买菜单 `Close(bool)` 的 `menuLayer` 访问。进程自行退出后再完成更新。该既有退出问题另行跟踪。实机采样、部署和故障记录留在工作区，索引见 `build/vfs-reopen-20261119-live`。正式服和公网多人验收仍开放。
