# 客户端武器模块注册

随着扩展武器增加，`client/weapons.cpp` 同时包含每把武器的头文件，并在初始化、重置、预测、状态接收、诊断、弹药和准星中重复枚举武器。这会让新增一把枪需要修改多个总控分支。本次把这组接口和呈现元数据交回各武器实现文件，通过统一模块注册接入。

## 原版依据与实现边界

IDA 可验证 CSOL 编译后的武器 ID、武器记录及虚函数消费者，无法据此还原原始 C++ 文件的 `#include` 组织。以 SKULL-5 为例，客户端虚表 `03114A1C` 的 v218 返回普通弹夹类别，实际 HUD 生产者读取它并写入武器 HUD 状态；原 HW ID112 记录提供准星 6/4/0/3。证据见 `2026-11-03_审计-SKULL5公共接线元数据-report.md`。

统一接口沿用这些已经核实的行为，但本项目的 `WeaponModule` 和注册器是现代 C++20 实现，并不声称恢复了 CSOL 原源码的注册宏或文件结构。

## 实现

- `weapon_module.hpp` 定义生命周期、预测、消息、HUD 元数据及可选呈现接口。
- 各武器 `.cpp` 持有 `constinit` 描述和一次静态注册，不需要在总控添加头文件或分支；赤血龙骧/御天绝影、两把近战分别由共享模块登记多个 ID。
- 固定大小的编号表支持 HUD 按 ID 直接查询，注册后不会在每帧分配内存；初始化和重置遍历已登记模块。
- 保留原有预测调用顺序和两阶段重置。现有预测器在不匹配武器时仍会清理动画状态，不能为了改成直接调用当前 ID 而丢掉这些副作用。
- 模块注册不调用引擎 API，不依赖跨文件静态初始化先后；编号重复、非法编号或顺序冲突在公共初始化时拒绝。

旧飞刀的内联预测目前保留；本次移出的是八个扩展实现模块的头文件及其分派链，不改变武器伤害、随机函数、动画或服务器协议。新增模块仍需纳入构建源列表，并按实际功能提供资源及服务端逻辑；注册器不代替这些工作。
