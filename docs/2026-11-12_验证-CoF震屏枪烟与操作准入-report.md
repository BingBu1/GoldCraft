# CoF 震屏、枪烟与 Glock 操作准入检查点

本检查点只交付独立组件源码与回归。当前仍是 **0 把 CoF 武器可购买、部署或实玩**；整枪验收先集中 Glock。实际枪口、冷资源、购买、灾变伤害和多人/性能仍在接入。

## 原版证据与对应实现

原 CoF `hl.dll` 为 PE32 x86，映像基址 `10000000`，SHA-256 `0036b91c01e92ed205513f52563053a55a66a32d257efb5f476b8f1f3dde0e63`；`client.dll` SHA-256 `d2a04641b301804f6f449aa68265042b13adc360925b80033d417ec9f38c9c00`。以下地址均为 VA，私有原始字节、反汇编和资源不发布。

| 证据 | 行为结论 | 实现 |
| --- | --- | --- |
| `hl.dll` `10119DE0 → 101166D0/10119680` 的完整原指令 | 仅地面玩家；半径使用严格比较；保留浮点顺序、fixed-word 编码及六字节消息 | `native/guest/cof/server/screen_shake.*` |
| `client.dll` `10080CC2` 及 Aurora 更新、删除消费者 | owner 的 `+304` 是 renderfx，不能读取 body；被跳过的系统也不能提前删除；原空系统保留到明确清理 | `native/guest/cof/client/aurora.*` |
| Glock `10046DC0`、世界状态、Deploy/Holster、Reload/Melee/Aim 与共同调用链 | 每项操作只要求该原版可达分支的资源和消费者；缺失消费者须在 RNG、扣弹和可见状态变更前拒绝 | `native/guest/cof/server/glock_weapon.*` |

Glock 构造/身份绑定不再要求当前操作不可能消费的全部效果；这没有把未实现效果伪装成成功。射击、机瞄、近战、换弹和拾取分别检查实际可达条件。原 Primary 不单独发送 Shell，第三人称弹壳属于原客户端 type3 事件消费者。

Aurora 存储改用稳定的 64 节点 slab，保留原链表顺序和空系统生命周期。首次 Prepare 冷分配，Add 仅在现有容量耗尽时增长，Frame 不分配；地图/视频清理释放多余 slab。节点属于原版仍存活的状态，未添加 TTL、去重、驱逐或提前删除。仅已获用户明确授权的未初始化控制字段和首次位置规范化为 0。

## 验证结果

- 震屏：96 个完整原函数场景、893 项实际 SDK 检查零失败；569 个实际输入当前复核一致。收据 `build/cof-screen-shake-20261112-03/receipt.json`。
- 枪烟：3,561 个连续原指令帧，状态、浮点字与 RNG 次数零差异；790 个保留链表事件、最多 192 个节点，原始状态、RNG 与 view 回调零差异。另有 34,454 项生命周期/容量检查，旧错误字段负对照失败 98 项。原 runner 曾被中断，后续完成了两项原指令对照；补充收据单独记录，不冒充原 runner 首次完整结束。
- Glock 当前组合：160 个射击、180 个世界状态、105 个切换原场景及 2,747 项实际 SDK 检查零失败；坏 oracle 仍被拒绝。收据 `build/cof-glock-20261112-current-05/receipt.json`。
- 新宿主接线另外完成了九个实际生产 SDK 翻译单元编译，666 个输入编译前后不变；它不属于本次独立组件发布的运行验收。见 `build/cof-host-current-20261112-01/receipt.json`。
- 模型完整文件/专服有效缓存前缀：10,021 项实际模型检查零失败；原生帧取消 140 项、实际 Glock/人物组合 180 项通过。对应 `build/cof-player-prefix-20261112-01`、`build/cof-native-owner-20261112-cancel-01`、`build/cof-owner-runtime-20261112-cancel-01`。

构建使用 x86 C++20、Arkari Clang、O3、ThinLTO、AVX2 和精确浮点。上述组件通过不代表完整 DLL、效果可见/可听、购买或实机性能通过；本次没有部署或启动游戏。
