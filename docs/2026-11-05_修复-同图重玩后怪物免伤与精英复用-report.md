# 同图重玩后的怪物受伤与行为复用

本阶段修复用户报告的“点击重玩此地图后，喋血和其它武器都打不死僵尸”。用户已明确自爆怪是后来改难度才刷出的，不能把后来的技能 11 拒绝解释成最初故障。完整大灾变目标仍在进行。

## 根因与原版依据

原 MP 为工作区合法副本，SHA-256 `39f962f34816411e615f01e5279d914204f7fd07c5a5112b0b303acafe0308b2`，x86，基址 `0x10000000`。以下地址均为 VA。本轮重新核对原 PE 字节与既有 IDA 范围；记录在 `build/replay-fix-20261105/evidence-before-edit.json` 和 `elite-before-edit.json`，均先于生产修改。

1. `CommitReplaySettings` 失效并替换命中奖励对象，普通怪行为却随实体池保留，伤害对象仍持有旧奖励对象。后续命中在 `Credit` 返回取消，尚未执行扣血，也没有报错。原 `11386B9A..11386C08` 在命中时调用 `10823570` 获取当前难度参数。修复将奖励 owner 的获取放到现有 `BeforeHitReward` 阶段，由当前 Session 提供；每次命中独立持有该对象，旧回调仍按既有代次和失效检查取消。伤害数值、奖励顺序、取消保护不变。这是宿主生命周期修复。
2. `RestartRound` 清除类型指针并保留行为，导致工厂不能再依旧类型判断精英类别；精英派生类错误继承普通怪的“不重建”。原构造 `10965798` 安装虚表 `11803454`，其 `+114` 指向 `106129F0`，原字节 `B0 01 C3` 返回 true；`11385644..1138566F` 据此析构旧行为并创建新行为。修复在 `CCSOLEliteMonsterBehavior` 明确覆盖该返回值，不强制所有普通怪重建。

对应生产路径：`native/csol/server/scenario_monster_damage.h/.cpp`、`scenario_monster_services.cpp`、`scenario_monster_elite.h`。构建选择保存在 `build/replay-fix-20261105/selected-01/manifest.json`，从实际部署的 full02 提取四项精确差分，不夹带其它工作树候选。
