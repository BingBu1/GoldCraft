## 分组结果

| 实际进程组 | 检查 | 结果 |
|---|---:|---|
| writer | 796 | 创建唯一 gameplay.json，注册 48 CVAR，真实异步持久写与发布 |
| reader | 374 | 第二独立进程打开同 root，恢复踢击关闭及正午 240 秒 |
| failure | 397 | 实际 deny-delete 文件句柄阻止替换，候选不发布 |
| invalid | 14 | 已存在无效 JSON 保留原字节，服务不可用、踢击关闭 |
| no-engine | 9 | 缺 GetGameDir 明确失败，不注册 CVAR/启用踢击 |

进程身份、命令、对象及输入散列均在本地收据；每组计数非空且失败为零。writer 在退出前主动 `CSOL_ShutdownGameplaySettings`，等待真实 worker 结束；reader 为新进程、新静态状态，不能依赖前一进程缓存。

F1（E1/E4）：初始唯一文件与快照一致，11 个功能加 37 个数值 CVAR 按描述目录注册一次，optional 未定值用明确 sentinel 表示；Service.Read 保留类型、范围、中文说明及 capability。只有已集成踢击可启用；未集成功能请求返回 Unavailable。

F2（E1/E2/E4）：零/非法 actor、零/过时 userid、其他模式、假客户端/退役实体、过时 CAS、未知字段、非有限值、非 bool 值和小数写整数均被真实适配器拒绝。引擎第一次 userid 查询后同槽换人时，第二次实际查询在 Store.Submit 之前拒绝。此适配器为可信服务器插件接口，AMXX `ADMIN_CFG` 权限由前一模块级验证及真实模块负责，本组不冒充管理员权限测试。

F3（E1/E2/E4）：临时控制台镜像 `kick=0` 经真实 Poll 立即输出 false，而磁盘和持久快照仍 true；改回 1 可恢复。永久保存必须走实际 Edit/Store。已排队但尚未 owner Poll 时，旧快照、CVAR 和策略输出保持不变；成功后四者一致。真实 CVAR 发布回调重入 Edit 得到 Busy，不能插入另一事务。

F4（E1/E2/E4）：目标文件由真实无 delete-share 句柄占用时，实际 worker 替换失败；主 JSON 字节、快照指针、修订、CVAR 与有效策略保留旧值，实际 Alert 收到错误。失败中间备份不被误称完全无文件变化。成功写盘后第二进程恢复同值，证明持久结果不只是内存回显。

P1，callflow：实际 factory→真实适配器 Init→真实 Store.Open/分组 JSON→CVAR 与策略初始化→Edit 两次身份验证/类型与 CAS→真实 worker 写入及原子替换→owner Poll→快照、CVAR 与策略输出→冷 shutdown→第二进程重新 Open。每一步分别有文件/状态/输出断言，不用直接改快照代替消费者。
