# 错误资源自动更新与下载计数

用户明确要求保留错误资源来验证自动修复，不接受手动修复包代替该功能。本轮结论：**已发布客户端不能自动修复已有错误资源；独立 SHA 更新模块可以，但完整游戏接线尚未完成。** 不将组件测试、手动脚本或文件替换称为入服修复。

## 现象与证据

受保护原客户端只读检查发现：购买菜单 `models/csol/buymenu_v10.json` 实际是 76,184 字节的 TGA，SHA `5a8dcca2b0c023d3d9b5b10fac5536baad88232fca929e8dd6f38c4af2114ce7`，与服务器 `gfx/csol/buy/w112.tga` 正文相同；正确 JSON 为 4,763 字节，SHA `6a439941ac6d3699a0aac02afd8184e0108f42ee1b75bc0b1a2b47026b8bb0de`。HUD JSON 也被另一张 TGA 替代，部分图片和 WAV 同样内容错位。

实际全 SHA 对照 4,476 文件，242 不同；其中 224 从正式 HTTP 取回后与当前服务端参考 SHA 相同，18 返回 404，不能认定这 18 项都是当前服务器正在下发的坏资源。坏菜单/HUD 的写入时间早于本次并行插件构建和安装，因此不能据此断言它们由新插件写错。

发布版 ParallelDownload 使用 `FileExists` 跳过已有文件，未接期望 SHA。`native/client/precache_client.cpp` 虽有 v4 接收和回调接口，但没有实际 `set_resource_sync` 接线；`native/engine/GoldCraftEngine.targets` 的 v4 默认关闭，`CSOL_RESOURCE_REFRESH` 也默认关闭。因此普通重连不会修复这些错误。没有放宽 JSON 校验或 consistency 来掩盖错误。

原宿主证据复核：工作区 hw SHA `9ba9a2db5e07598fd59afa35507a98c86162e4e15b3835177b78c11842cd2295`；IDA `0x10196F70` 先 `SPR_Init` 再调用 native HUD，调用点 `0x101A7966` 在资源请求之前。不能只重下文件后假设 HUD 自动重建。新增原证保留在 `analysis/resource-repair-20261108/hud-entry-evidence.json`；复用前核对了原模块身份。完整生命周期合同仍见 2026-11-05 的资源接线、原生 HUD 和消费者事务报告。

## 本轮实现与验证

- `tests/resource-update/main.cpp` 增加真实坏文件批量模式；`captured.py` 只读复制错误样本，只提供正确大小/摘要，不提供修复正文。生产 `resource_update`、WinHTTP/CNG 和精确原版 x86 FileSystem 负责全部识别、下载和最终 VFS 读取。
- `tests/resource-update/run.py` 改为直接编译项目源、记录前后输入身份，不再复制组件或整个 SDK 到 build。
- 224 个捕获错误文件全部自行从正式 HTTP 下载，实际 VFS 逐项匹配期望 SHA；取消后仍读到原错误样本，再次启动全部复用已验缓存、下载数为零。**2,028 项检查通过**，受保护原件及隔离错误样本全部未改。证据：`build/resource-update-captured-20261108/{run.log,receipt.json}`。
- 当前项目源码的 16 组真实 FS/HTTP 回归通过，包括同尺寸错误、PAK 覆盖、错误 SHA、取消、缓存损坏、同代次变更、硬链接隔离和事务回退。证据：`build/resource-update-current-20261108/result.json`。这些都不包含真实游戏资源 owner 的刷新。

下载计数的独立根因是 `IPanel` 为 null：BaseUI 传入的工厂列表没有提供 vgui2 的接口，Paint 因此提前返回。`native/parallel_download/plugin.cpp` 按实际 SDK 和 VGUI2Extension 工厂用法，从已加载 `vgui2.dll` 的 CreateInterface 补取 `VGUI_Panel007`。仅改变用户要求的自定义下载界面，不改 CSOL HUD 布局。

单 B 用候选 DLL `443c3c648e1ae50bf06b88026b2175005b77e367cce4d7fb072b242ab792a9dc` 实测取得非空 IPanel 和可见 LoadingDialog，10 文件下载零失败并自动重连。后续仅压缩诊断输出的最终候选 `f47902b0b4b23c42c736220562438d85aee6cce4f64fb38facfc31947c767b4b` 已编译，94 网络检查和 46 生产桥接检查通过；最终候选未替换正在运行的 B。**尚未取得下载框截图，不宣称位置/字体已视觉验收。** 证据在 `build/parallel-download/ui-02`。
