# 扩展玩家资料容量

2026-10-19 已部署本地CS B及ReHLDS：玩家资料存储扩为1024字节（含NUL），单键／单值仍小于127字节，客户端为服务端身份预留32字节。实机客户端保存978字节，130个短测试字段全部经连接投影和126条补发到达服务端；队列清空、拒绝0，933资源及MC配对正常。连接前投影222字节，真实网络补发已跨过原256字节限制。同一130字段通过CS重连仍在服务端全部保持；之后正常退出码0并清除本地测试字段，测试字段没有留在正式配置。旧端接新端仍待验。证据 `build/userinfo-fields-20261019/final-runtime.json`、`live-fields-reconnect.json`、`live-clean-exit.json`。

实机暴露两个服务端接线问题：`FCVAR_SERVER`仅供服务器规则查询，注册并不会写入客户端读取的`fullserverinfo`；现初始化时显式写入容量，保留USERINFO更新语义。旧`SV_BroadcastCommand`会向Bot未初始化的netchan写入，现场补公告触发致命错误；现统一排除Bot，并将原128字节临时消息区扩大到格式化命令上限加消息号。在25角色在线时重复原命令，RCON持续响应。失败转储与最终实机结果均保留，不将此前失败隐藏为成功。

重复键检查表按1024字节容量提供256项，保留重复键、单字段长度与非法字符规则。客户端新版本连接旧服务器的933资源／MC配对也有实际记录；旧客户端连接新服务器、删改／容量拒绝和完整多人负载仍待验收。最新累计候选 `build/candidates/combined-userinfo-live-20261019/manifest.json`。本次未追加离线回归批次。

原生连接包继续使用 256 字节的完整键值投影，优先保存名字、认证和资源解码能力。Steam 认证及原连接包预算保持原路径。扩展字段在服务器认可 `_gcu=1` 后，通过可靠的原生 `setinfo` 命令补发，每帧最多两条。因此认证前插件只能看到初始投影；不能把它当成支持任意大认证字段的连接协议。

服务端以独立存储保存完整资料，`client_t.userinfo` 仍是原来的 256 字节成员。`GetInfoKeyBuffer` 地址及 ReAPI 的偏移保持；标准 `InfoKeyValue`、设置、打印和用户资料变化回调可访问扩展值。直接复制这个原始成员的第三方代码仍只得到兼容投影。超容量设置在删除旧值前拒绝。

向支持扩展的客户端发送完整 `svc_updateuserinfo`，向旧客户端发送完整键值的 256 字节投影。字段传输白名单及下划线私有字段过滤沿用引擎规则。可靠缓冲区空间不足时按接收者／来源槽位合并待发状态，每帧每个接收者最多补发两条，发送时重新取最新身份和资料。客户端保留原玩家结构，用独立存储接收资料；名字、模型、颜色、Steam 身份及 `PlayerInfo_ValueForKey` 读扩展数据。断线、换服、槽位重用清理连接数据，本机设置仍参与原 `setinfo` 保存路径。

客户端仅对已核验 HL10210 启用：模块身份、19 处本机引用、玩家资料复制调用与函数入口由独立引擎副本核对，元数据通过 MetaHook `ResolveGameSymbol` 解析。原安装不修改。未知引擎或缺元数据时不公告扩展能力。

源码位于 `native/include/goldcraft/userinfo.hpp`、`native/client/userinfo_client.cpp` 与 `native/engine/userinfo.cpp`；引擎接线保存在 `patches/rehlds-goldcraft.patch`。分析记录和构建日志位于本地 `build/userinfo-20261019`，不发布引擎二进制或反编译内容。

剩余实机：客户端完整资料查询接口的逐值核验、在线删改及容量拒绝、换图清理、旧端并存和消息预算。按用户要求不追加离线测试批次；编译通过不代表这些玩法路径已验收。

最终生产日志：`client-build-final.log`、`server-build-frozen.log`。元数据生成核对129符号、108个字节区间；这是安装匹配检查，不是新的玩法验收。运行更新计划只替换GoldCraft DLL、ReHLDS swds DLL及两份对应元数据，并更新部署记录。

退出生命周期：MetaHook在`ExitGame`之后卸载引擎，再调用`Shutdown`。引擎补丁恢复和引擎／Renderer相关清理必须在`ExitGame`内完成；`Shutdown`只停止插件自己的服务。上一部署批次的退出记录显示调用已卸载引擎的Cvar函数，源码中重复的后处理清理已移除；本候选的userinfo补丁恢复也移到卸载前。此后另抓到Steam异步模块在客户端DLL卸载后读取其好友上下文，现于HUD_Shutdown原回调前解除IAT/VFT钩子并清空上下文；真实调试关闭走完ExitGame/Shutdown且无AV，常规启动自然退出码0。
