# 扩展玩家资料容量

2026-10-19 候选：GoldCraft 客户端与配套 ReHLDS 将玩家资料存储扩为 1024 字节（含结尾 NUL）。单键、单值保持匹配 ReHLDS 的小于 127 字节限制；客户端预留 32 字节供服务器写入身份。客户端与ReHLDS生产构建通过；39项累计候选已冻结，尚未部署或完成扩容实机验收。

重复键检查表也已按扩展容量分配，避免旧表在130个短字段仅占780字节时仍拒绝合法资料。每个非空键值对至少需要四字节，因此1024字节容量最多需要256项检查空间；重复键、单字段长度和非法字符校验保持。配套ReHLDS生产构建通过，最新累计候选为`build/candidates/combined-userinfo-fields-20261019/manifest.json`，包含前述退出修正；超过旧字段数量的实机收发仍待验证，未追加离线回归批次。

原生连接包继续使用 256 字节的完整键值投影，优先保存名字、认证和资源解码能力。Steam 认证及原连接包预算保持原路径。扩展字段在服务器认可 `_gcu=1` 后，通过可靠的原生 `setinfo` 命令补发，每帧最多两条。因此认证前插件只能看到初始投影；不能把它当成支持任意大认证字段的连接协议。

服务端以独立存储保存完整资料，`client_t.userinfo` 仍是原来的 256 字节成员。`GetInfoKeyBuffer` 地址及 ReAPI 的偏移保持；标准 `InfoKeyValue`、设置、打印和用户资料变化回调可访问扩展值。直接复制这个原始成员的第三方代码仍只得到兼容投影。超容量设置在删除旧值前拒绝。

向支持扩展的客户端发送完整 `svc_updateuserinfo`，向旧客户端发送完整键值的 256 字节投影。字段传输白名单及下划线私有字段过滤沿用引擎规则。可靠缓冲区空间不足时按接收者／来源槽位合并待发状态，每帧每个接收者最多补发两条，发送时重新取最新身份和资料。客户端保留原玩家结构，用独立存储接收资料；名字、模型、颜色、Steam 身份及 `PlayerInfo_ValueForKey` 读扩展数据。断线、换服、槽位重用清理连接数据，本机设置仍参与原 `setinfo` 保存路径。

客户端仅对已核验 HL10210 启用：模块身份、19 处本机引用、玩家资料复制调用与函数入口由独立引擎副本核对，元数据通过 MetaHook `ResolveGameSymbol` 解析。原安装不修改。未知引擎或缺元数据时不公告扩展能力。

源码位于 `native/include/goldcraft/userinfo.hpp`、`native/client/userinfo_client.cpp` 与 `native/engine/userinfo.cpp`；引擎接线保存在 `patches/rehlds-goldcraft.patch`。分析记录和构建日志位于本地 `build/userinfo-20261019`，不发布引擎二进制或反编译内容。

待实机：超过 256 字节的保存／入服补发／服务端查询／玩家资料更新，删改及容量拒绝，重连换图清理，旧端并存和消息预算。按用户要求不追加离线测试批次；编译通过不代表这些玩法路径已验收。

最终生产日志：`client-build-final.log`、`server-build-frozen.log`。元数据生成核对129符号、108个字节区间；这是安装匹配检查，不是新的玩法验收。运行更新计划只替换GoldCraft DLL、ReHLDS swds DLL及两份对应元数据，并更新部署记录。

退出生命周期：MetaHook在`ExitGame`之后卸载引擎，再调用`Shutdown`。引擎补丁恢复和引擎／Renderer相关清理必须在`ExitGame`内完成；`Shutdown`只停止插件自己的服务。上一部署批次的退出记录显示调用已卸载引擎的Cvar函数，源码中重复的后处理清理已移除；本候选的userinfo补丁恢复也移到卸载前。修正尚待自然退出实机复验。
