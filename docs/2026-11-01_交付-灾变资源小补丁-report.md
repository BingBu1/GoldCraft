## 更新范围

共 111 项、8,829,765 原始字节：102 项新增、9 项同名旧版本替换。包含 11 张启动表、56 项购买菜单资源、12 项人物/手模/目录资源、30 项 K3/黑龙炮资源，以及实际模型依赖解析发现的 2 张 BMP。

基线按已安装顺序合成 `20261024-CSOL` 和 `20261101` 灾变包。880 项相同资源已核两包真实 ZIP 内容的 SHA，约 1.46 GB，无须再次装入补丁。安装前逐项核对它们，并检查稳定 mp.dll、swds.dll、Start-Scenario.ps1、启动器签名清单和 CSOLSupport 发布 blob 共 5 个版本锚点。

更新只写 `cs/cstrike` 资源目录。原 HTTP 直接从相同资源根提供客户端文件，端口不变。纯 CS mode2 入口、配置、管理员、密码、Minecraft、DLL 与启动器核心发布保持原样；不会混入正在开发的新购买/技能 DLL。角色 JSON、目录文本和 6 个手模需要替换，不能仅按文件名存在就跳过。

先运行原 `Stop.cmd`，将补丁解压到服务器目录之外，再运行包内 `Update-Server.cmd` 并选择包含原 `Start.cmd` 的根目录；成功后使用原入口启动。见[操作说明](../tools/scenario-update/RESOURCE_REPAIR.md)。

## 安装验证

使用两份实际 ZIP 构成完整基线，在 Windows PowerShell 5.1 执行交付脚本，10 项行为检查通过：只看计划零写入、错误省略基线拒绝、真实共享句柄引发的中途失败完整回滚、111 项新资源哈希、880 项原资源与 5 个锚点保持、用户配置和旧模式回滚记录保持、硬链接旧手模原子拆分、重复更新全跳过、重复运行零变更及恢复原始资源。

夹具预置 1 项已更新文件，正常应用处理其余 110 项，约 20.90 秒；重复校验约 16.41 秒，资源恢复约 1.99 秒。时间仅代表本机隔离目录。`requiredBaseline` 对全部 885 项检查，未在测试里删减校验范围。

资源修复使用独立 `.bingsang-resource-updates` 事务目录，保留之前灾变模式更新的回滚入口。包内 118 个 ZIP 条目及 111 项 payload 全量读取核 SHA；不含 DLL、EXE、JAR、凭据、PDB 或日志。

测试只复用文件 ID、完整 SHA 和两个已知所有者均核实的冻结资源硬链接；其他基线从 ZIP 独立展开，成功后逐文件验证并清理本次临时大基线，清理独立逻辑字节 1,469,414,608。交付 ZIP 也以已核文件身份的硬链接复用。没有把逻辑字节量声称为实测 NTFS 簇释放量，原安装和运行服务器均未修改。

证据在 `build/remote-scenario-catalog-fix-20261101/package-01/receipt.json`、`tests-01/result.json` 与 `delivery-final.json`。来源闭包、部署回执与模型依赖说明见[领域资源报告](2026-11-01_修复-远程灾变服务端资源闭包-report.md)；其 11 项 Python 防漏检查通过，本轮未重复执行。
