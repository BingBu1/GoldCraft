# 远程灾变差异更新与冰桑核心发布

本批为已应用 `20261024-CSOL` 的远程服务器生成差异 ZIP，切换首图至 `zs_deadend`、模式至原生 CS 大灾变，并发布冰桑启动器的核心 DLL 清单 `2026110104`。包已生成，远端尚未应用，也未进行真实公网入服验收。

## 交付与使用

交付文件为 `server-packages/update-20261101-Scenario/冰桑-远程灾变更新-20261101.zip`，95,131,883 字节，SHA-256：

```text
e9b47a0c162847c4dc8c0126cd24c4b7e7629fdb34b0d0be6a03370d1c6591ec
```

先用原 `Stop.cmd` 停服；把 ZIP 解压到原服务目录之外，运行 `Update-Server.cmd` 并选择包含原 `Start.cmd` 的目录；成功后继续用原 `Start.cmd`。必须运行脚本，单纯复制 `payload` 不会合并模式和启动配置。详细步骤见[更新说明](../tools/scenario-update/README.md)。

本包含 492 个 payload 文件，原始大小 189,201,838 字节。以用户确认成功应用的旧包为基线，省略 14 个相同文件共 17,696,908 字节，其中 12 个是资源、2 个是匹配的 AMXX/ReAPI 运行组件。安装前验证这些省略项，缺失或不同则整批停止；不能把本地的“只新增两条 WAV”当成远端差异。本批没有获取远端当前完整文件清单，HTTP 404 也没有用作磁盘缺失判断。

## 版本与启动行为

| 组成 | SHA-256 前缀 |
| --- | --- |
| 服务端 mp.dll | a3e32ab1 |
| ReHLDS swds.dll | 9b091487 |
| 启动器发布 CSOLSupport.dll | ace18e1c |

远端启动命令在首图预缓存之前设置 `-csol_game_mode 2 +csol_weapons 1`；模式插件放在 AMXX 主插件表第一项，以已有策略暂停 ZP/Nade Modes，SyPB 配额为 0。地图轮换固定为本包的 `zs_deadend`。公网地址、HTTP 端口、密码、管理员和其他用户设置保留。

本地已验的是**纯原生 CS 大灾变**。新启动分支不启动 Minecraft，不读 MC 地图登记、JVM 或维度配置，也不改 MC 文件；原双服分支完整保留。首轮曾准备 MC 维度的 `package-01` 已作废，不能交付。`package-02` 已纠正并经过实际脚本检查。

冰桑启动器 EXE 保持既有版本，在服务器应用本包后，通过已有 HTTP 端口获取签名序号 `2026110104`。清单只允许原先的 19 个核心 DLL；已验证 RSA 签名、bundle 身份及新 CSOLSupport 哈希。界面、错误提示和用户偏好不显示 HTTP 入口；联网目的地址并不是能够对客户端保密的凭据，更新真实性依靠签名和哈希。私钥不在包中。

## 已执行的检查

在隔离目录用真实 Windows PowerShell 5.1 运行更新器，20 项行为检查通过：计划零写入、缺失基线/未列出文件拒绝、真实文件句柄占用引发的中途失败完整回滚、配置与凭据保留、全部文件哈希、模式前置、原双服分支保留、没有 MC 维度、原启动入口的纯 CS `-CheckOnly`、重复运行零变更、恢复旧版以及硬链接目的文件原子拆分。

本机夹具首次应用约 24.54 秒，重复运行约 9.57 秒；这些是本机安装耗时，不是远程服务器性能承诺。路径校验改用 .NET 文件属性读取，仍逐层拒绝 reparse point，避免反复调用 PowerShell 文件系统提供程序。写入采用独立临时文件及原子替换，完整事务日志支持失败恢复。

证据保存在 `build/remote-scenario-package-20261101/tests-02/result.json` 与 `delivery-final.json`；旧 `tests-01` 的重复运行失败保留，未算作通过。最终 ZIP 全量解压内容按清单核 SHA-256。没有重复构建或启动游戏，没有修改本地运行服或原 Steam 安装。

打包使用 421 对经 SHA/文件 ID 核实的不可变资源硬链接，避免重复逻辑字节 146,570,822；最终 ZIP 也以硬链接交付，避免另复制 95,131,883 逻辑字节。未据此声称 NTFS 实际簇占用减少同样字节；本轮未单独测量物理分配。可变 DLL、配置及编译输出没有共享写入。
