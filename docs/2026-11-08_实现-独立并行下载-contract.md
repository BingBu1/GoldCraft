# 独立并行下载：实现前合同

本功能是用户要求的宿主扩展，不冒充 CSOL 原版实现。生产源置于 `native/parallel_download`，不修改 Renderer、CSOLSupport 或现有未启用的资源 v4 事务。

## 已核证据

宿主为工作区 Steam HL10210 x86 `hw.dll`，SHA-256 `9ba9a2db5e07598fd59afa35507a98c86162e4e15b3835177b78c11842cd2295`，基址 `0x10000000`，CRC64 `6ef7192cd8254e2d`。私有 IDA 记录位于 `analysis/parallel-download-20261108`，包含反编译与原字节。

- VA `101A62C0`：重置管理器、枚举缺失资源、入队；有 HTTP 队列后记住服务器 URL，主动 `CL_Disconnect`，显示下载页。因此服务端收到 `Client sent 'drop'` 是此原生阶段的预期行为，不能据此诊断崩溃。
- `101A67B0` / `101C7440`：遵守下载开关、已存在文件及 HTTP 已尝试记录；HTTP 失败后重连走原生剩余文件回退。
- `101C75D0` 入队，`101C7480` 返回等待数量；`101C6180` thiscall 重置释放所有请求；取消命令 `101C7490` 直接调用该重置并清理已尝试记录。
- `101C7530` 每帧调用 Update `101C4540` 和 Start `101C6800`。Start 在 `101C6850` 检查活动数小于 **5**，原引擎已经并行，不是串行。
- `101C5640`：I/O 失败或空完成事件直接返回，不标记对应项失败。`101C4540` 不包含自己的超时，只回收 success/error 状态；活动列表和待启动队列均空才关闭进度并发 `retry\n`。这是可导致停滞的代码路径，尚无用户故障现场内存证明本次一定命中。
- UI 包装 `1022B510(float)`、`1022B530(text)`、`1022B590()` 分别更新次进度、文本和关闭下载页；重连命令缓冲 `101B4CA0(const char*)`。

用户提供正式服务状态：TCP 28080，3103 资源，442 loads/0 failures、455 requests/0 rejected。直连用户实际 HTTP 地址，截图 WAV HTTP200/67362B/约1.077秒；状态接口200。此前本机默认代理下超时不能作为服务器不可用证据。

## 宿主扩展设计

保留原生资源枚举、许可校验、HTTP尝试标记、断线/重连及剩余资源回退。独立插件替换队列/计数/每帧推进，并拦截原管理器重置保证取消和退出覆盖。所有引擎/VGUI操作仅主线程；网络线程仅持有字符串、独立临时文件和共享作业状态，不能访问引擎对象。

自定义默认8路，有界队列和单文件大小、连接/读取超时和总时限；失败有限重试后终止该项并保留原生回退。临时文件完整写完才能原子发布；取消的旧批次禁止发布或触发重连。失败不能计入成功数量。加载页右上方显示成功/总数与剩余，按实际面板位置布局。具体参数为本项目设计，不是原版证据。
