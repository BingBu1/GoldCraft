# 下载队列取消后旧回调误重连

已修复独立 ParallelDownload 插件的确定性生命周期错误：原生进度界面取消、替换队列或递归推进后，旧 Tick 仍可能把已清空的队列当成全部完成，关闭界面并发送 retry。旧生产实现已在新夹具中准确失败；新 DLL 已构建并部署到单个本地 B，实际模块与四个下载钩子核同。真实缺失七资源的 v4 下载、完整校验和返回游戏通过。正式服本轮只有只读诊断，没有安装此修复；用户报告的具体中断尚无现场调用链，不能宣布它必定由这个队列错误导致。

## 原版依据与宿主适配

原宿主为 Steam HL10210 x86 `hw.dll`，ImageBase `0x10000000`，SHA-256 `9ba9a2db5e07598fd59afa35507a98c86162e4e15b3835177b78c11842cd2295`。既有 IDA 调用上下文及消费者见 [独立并行下载合同](2026-11-08_实现-独立并行下载-contract.md)。修改前重新核同 Queue `101C75D0`、Count `101C7480`、Reset `101C6180`、Tick `101C7530`、命令缓冲 `101B4CA0`、次进度 `1022B510`、文本 `1022B530`、关闭 `1022B590`、原并发分支 `101C6850` 和主进度 `1022B400`。

原 `101A62C0` 在 HTTP 入队后主动断开游戏连接，再显示下载页。因此服务端的单条 Client sent 'drop' 是可能出现的正常阶段，不能单凭它判断下载失败或崩溃。真正需要核实的是后续队列、下载界面及完成重连。这次修复属于用户要求的下载扩展和宿主生命周期适配，不宣称修改来自 CSOL 原实现。

私有修改前记录为 `analysis/download-drop-20261118/PREEDIT.json`；原 IDA 正文仍留在 `analysis/parallel-download-20261108` 和 `analysis/download-drop-20261115`，不随源码发布。

## 源码行为

主线程批次 revision 在取消前、成功追加唯一资源后更新。Tick 在文本和次进度分派返回后立即核对 revision；在原生文本回调期间用 shared_ptr 保持正在显示的作业存活。正常完成先退休一次队列，关闭界面后再核对所有权才发 retry。异常若发生在已取消／替换的 UI 回调之后，不再清理、关闭或重连新的会话。

不改变八路协程、有限重试、网络超时、完整文件原子发布、原生失败回退、SHA／VFS 校验或下载数量语义。revision 只在主线程访问；新增工作是每 Tick 有界的标量比较及至多一个共享引用，不增加逐资源磁盘／网络查询、分配或轮询计时器。本轮没有以此宣称加载速度或帧时间改善。
