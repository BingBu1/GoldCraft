# 断线模型所有权与渲染资源退休

本阶段修正入服资源更新的两处宿主生命周期缺口，并整理 Renderer 资源释放接口。v4 仍未接通运行版本；没有部署或游戏验收，不改变 CSOL 地图与武器行为。

## 依据与实现

原宿主 hw SHA-256 为 `9ba9a2db5e07598fd59afa35507a98c86162e4e15b3835177b78c11842cd2295`，x86、基址 `0x10000000`。修改前映射保存在本机 `build/resource-sync-20261105/disconnect-owner-evidence.md`，原证见两份原生 HUD 生命周期/初始化顺序报告。

| 依据 | 结论 | 实现 |
|---|---|---|
| 原 `R_UnloadSpriteTextures 102417B0` 直接解引用 `cache.data`；断线 `CL_Disconnect 101A2A50 → Host_ClearMemory 101D2590 → Mod_ClearAll 1023E500` 已清空普通 SPR 指针 | 下一安全帧不得把空 header 传给原卸载入口；仍须退休使用者及版本状态 | `native/client/resource_model_cache.cpp` 仅对非空 SPR 调用卸载，保留正常 needload 与 CRC 重新校验 |
| 当前 `precache_client.cpp` 的 `reset_client` 关闭 extended，但 `extra_models` 的稳定对象继续存在 | 活动连接的索引范围不是全部资源对象的生命周期范围 | 新增独立 `GoldCraftModelOwnersAPI`，按真实原生与扩展集合提供稀疏索引上限；原 `GoldCraftPrecacheAPI` 与连接容量语义保持 |
| 匹配 Renderer 的 Studio/SPR、异步工作项、外部材质与骨骼所有权 | 主缓存释放前必须结束读取它们的任务，立即删除 GL 对象并清除所有引用 | `src/resource_refresh.inc` 和四个调用点，在 GL 主线程内层 HUD_Frame 提供预检/退休接口，拒绝绘制中、错误上下文或不完整对象集合 |
| 原 v3 解析、扩展清单完整性合同与已发布 SHA 协议 | 收齐清单后才能暂停原下载器并异步验证；未接好所有依赖不得宣告支持 | `precache_client.cpp/.hpp` 接收 v4 值副本并提供恢复/取消回调；无回调时能力为 0 |

Renderer 退休会先标记绘制对象关闭，等待异步任务退出，再删除并清零 VAO/VBO/EBO；包括已经被替换、但排队任务仍持有的对象。随后清除材质、皮肤、骨骼、纹理及借用 header。引擎主块和低位 Hunk 仍归引擎所有，不由 Renderer 释放。完整集合只在正文变化时退休，不能每次换图无条件执行。
