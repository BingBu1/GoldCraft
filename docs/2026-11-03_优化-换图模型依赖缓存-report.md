# 换图模型依赖缓存

服务器原先在每次地图激活时，对每个特殊模型重新读取、解码、合并 SEQ、解析 JSON 并遍历贴图依赖；多个武器共享的资源也会重复处理。逐模型 `dependencies=… added to downloads` 输出进一步增加控制台开销。

当前候选将依赖清单保留到下一张地图，并在一个地图激活批次内共享输入检查。Windows 使用游戏实际文件系统读取正文并计算 SHA-256；不通过物理路径猜测 PAK 与松散文件的优先级。每次新批次重查所有参与解析的输入：包括不存在的可选 JSON、SEQ、纹理以及实际读取的模型、配置正文。输入变化便重新收集；缺失必需文件仍按原逻辑拒绝。

## 实现范围

- 跨地图只保留路径、存在性、正文摘要与依赖清单，最多 512 条、估算 16 MiB 元数据；不保留模型或引擎指针。
- 每批次最多保留 64 MiB 原始正文、65,536 条输入记录。超限放弃缓存并走原读取路径；原单文件 128 MiB 限制保持。
- 共享正文只在预算内复用。较大输入可重复读取，不能把此实现描述为所有资源永远只读取一次。
- 依赖下载登记按原首次出现顺序去重，每张图仍重新建立完整资源表。
- 默认仅输出一条汇总：模型数、缓存命中、重建数、唯一依赖登记数、读取次数/字节和批次耗时。SEQ 合并详情降为开发日志。
- 非 Windows 环境目前保守禁用跨图正文缓存，不以弱摘要替代检查。

## 证据与边界

| 证据 | 发现 | 实现路径 |
|---|---|---|
| `build/csol-dependency-cache-20261103/source-01/before.json` | 旧实现逐模型调用真实依赖收集器并输出日志 | `native/engine/csol_loader.cpp` |
| `build/csol-dependency-cache-20261103/source-01/after.json` | 输入跟踪、跨图清单缓存与批次生命周期已接线 | `native/engine/csol_dependency_cache.hpp`、`native/engine/csol_loader.cpp` |
| `build/csol-dependency-cache-20261103/patch-01/review.json` | 公开 ReHLDS 补丁还原并应用成功；只增批次 Begin/End，未夹带工作树认证候选 | `patches/rehlds-goldcraft.patch` |

严格摘要版本已通过独立失效/预算/真实收集器验证（合成断言 66,795 项，其中 65,536 项为输入容量边界；真实资源 428 项），完整引擎及 A1/B/A2 三组专服对照。12 次加载的完整下载广告相同，新版 474 项 HTTP 全长与摘要验证通过，临时文件均恢复。

旧版六次热加载的激活阶段中位为 4.069 秒，新版三次为 3.739 秒，减少约 8.10%。但新版每次仍读取约 1.2 GiB，因此这只是已验证的中间阶段，尚未满足进一步缩短换图的交付目标。详见《2026-11-03_验证-换图依赖缓存-report.md》。正式远端未更新。

后续正在加入可选的文件系统资源版本接口，由实际 VFS 提供文件身份及高精度修改信息，减少未变化资源的正文读取；接口不可用时回退本报告的严格 SHA 路径。新接口仍须独立验证及实服对照，不能沿用严格版本的通过结果。冷启动仍需要完整解析，模型加载、地图实体初始化与其他插件耗时也须区分。
