# 独立并行下载与下载停滞处理

用户要求新建 MetaHook DLL 并行下载资源，在原加载对话框右上方显示完成/总数与剩余。随后报告 HTTP 下载页停滞、服务器显示 `Client sent 'drop'`。

## 结论与修改

已创建独立 `ParallelDownload.dll`，生产代码在 `native/parallel_download`。不修改 Renderer、CSOLSupport 或其他未完成资源事务。默认 8 个后台传输槽；取消、操作超时、总时限、有限重试和失败状态明确终结作业；下载内容流式写入临时文件，主线程完整发布后才计成功。既有资源不覆盖，失败维持原生剩余资源回退。界面代码以实际 LoadingDialog 尺寸定位计数，未使用绝对屏幕坐标。

原引擎已经同时处理最多 5 个 SteamHTTP 请求。IDA 确认下载队列建立时主动断线，全部请求结束才发 `retry`；故 `drop` 不是崩溃证据。I/O 失败回调存在不更新请求终态的路径，Update 没有自己的超时，这是一条停滞风险，但未取得用户现场内存，不能认定本次唯一根因。用户实际 HTTP 地址的截图 WAV 直连 200/67362 字节/约1秒；本机代理造成的早先超时已排除为服务端证据。

完整精确模块身份、原始函数地址和调用生命周期见[实现前合同](2026-11-08_实现-独立并行下载-contract.md)。补充主进度消费者为 `1022B400(const char*, int, float)`，仅读取后两个实参调用 GameUI ContinueProgressBar；独立目录包含11项符号与10段核验。Reset保留原thiscall的整数返回值。
