用户于 2026-11-12 明确要求“跳过这个逻辑”“武器后面再加”。本轮先暂停礼盒转为地面武器的奖励分支，继续地图与 BOSS 测试；这属于用户授权的临时差异，不宣称与原版奖励行为一致，也不关闭完整还原目标。

## 仓库边界

CSOL 账号仓库尚未接入：账号持有数量、持久保存和仓库选装均未交付。原礼盒的本局 `GiveNamedItem`/实际入包链不经过账号仓库，当前本局购买与地面拾取也不能算作仓库实现。武器奖励延期不改变这一事实；三把奖励枪及账号仓库继续单列未完成范围。

## 验证与下一步

修改前已读核上述原调用链及当前实际创建、移除和能力检查。后续验证分别记录编译、真实 SDK、部署及地图玩法结果；源码修改或组件通过不能代替整局 BOSS、通关、重玩、换图和多人验收。

## 本轮实际验证

`tests/csol-scenario-teddy-bear/run_components.py` 在项目原位编译三份实际生产源和真实 SDK 夹具，复用明确逐 SHA 封存的 426 个旧 SDK 支持输入。它保留之前完整构建的广域拒绝，不把这些支持对象重新标成当前完整服务器已通过。

最终收据为 `build/teddy-deferred-components-20261112-03/receipt.json`：五组共 210 个行为检查、16,476 个 SDK 检查，零失败，实际依赖前后稳定。四个新对象和实际执行 EXE 均封存，并在每组前后复核；EXE SHA-256 为 `ae17abb03b5a0c387952f21f3fac4736c9c67eea28da83a312b09c6a610a1a82`。

- 实际房间 0 允许创建陨石，缺失/不匹配房间和访问撤销分支分别保留。
- 奖励礼盒完成火花和删除，未调用发枪或爆炸；非奖励礼盒仍走真实伤害。
- 创建取消覆盖原对象删除、同槽位复用和旧租约；新实体不被误改或误删。
- 火花和真实伤害、中毒、击退组通过；伤害组没有独立逐字节验收最后两个爆炸包，不扩大结论。

前两次失败是旧夹具把“烧手阶段限定的两次 owner 查询/房间查询”错误延长到新准入的实际实体工厂；只修复夹具采样范围，生产逻辑没有为测试改成固定成功。失败日志和拒绝收据保持原样。

本轮没有部署或游戏实测。`map_support.hpp` 仍未开放 `zs_nightmare/subtype1`，Session 还保留 11 个奖励模型的存在性/冷准备要求；这两处须随地图准入和依赖一致化继续处理。当前生产改动仍在完整 owner 的待发布闭包中，本阶段独立发布的是验证入口与本报告，不宣称完整地图源码组合已构建或已交付。
