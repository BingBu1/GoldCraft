# 高清静态与 GIF 喷漆

CSOLSupport 在原“多人联机”选项页增加图片选择、预览和上传进度，使用原 T 键喷到服务器判定的墙面。双方都需要对应的客户端和服务端扩展。普通客户端继续使用原生喷漆，无法显示高清图片。

选择图片后点击“应用”保存并上传。“取消上传”停止当前传输并保留已保存选择，再次点击“应用”可重试。服务端原有 `sv_allowupload` 和 `sv_send_logos` 必须允许上传和分发。传输走当前游戏连接，不需要另外配置 HTTP。

图片大小按原始像素换算：1 像素对应 1 个 GoldSrc 世界单位。例如 256×128 图片的墙面宽高均为 128×64 图片的两倍。传输时缩小纹理只降低清晰度，不改变墙面尺寸；超出实际 BSP 面的部分会被裁剪。

| 项目 | 限制或行为 |
| --- | --- |
| 图片格式 | Windows WIC 支持的 PNG/JPG/BMP/GIF/TIFF 等；GIF 保留动画，其余多页格式取首帧 |
| 文件与上传 | 原文件和整份编码载荷分别最多 10 MiB（10,485,760 字节），等于上限允许 |
| GIF | 最多 256 帧，逻辑画布最多 8,388,608 像素 |
| 传输纹理 | 最长边最多 512，整份动画解码后最多 32 MiB，帧数多时进一步缩小 |
| 共享预算 | 服务端编码资源及上传预留合计 128 MiB；客户端共享解码资源 128 MiB |
| 落点 | 服务端最多保存 32 处；换图和服务端重启清空 |
| 上传节流 | 每 25 ms 最多 3 条 48 字节片段；服务端每 25 ms 最多分发一个 176 字节片段 |

10 MiB 载荷在理想调度下约需 30.3 分钟上传、24.8 分钟向每个接收者分发，实际还受帧率和网络影响。连续 120 秒没有有效数据会释放上传预留，总时限按 10 Hz 调度预算计算。设置页显示百分比并允许取消；内存预算不足时拒绝载荷，不无限积压。

GIF 导入合成透明、局部差分帧、局部色表、交错像素和 disposal 0/1/2/3。延时 0/1 厘秒按 100 ms 处理，其余保持原延时；没有循环扩展时播放一次，循环计数 0 为无限，正数为重复次数。有限动画结束停在最后帧。同一图片的多个落点共享已解码帧和 GPU 纹理，不在每帧重复解码、上传。

协议及设置版本为 v3，保留 v2 和旧 flag 0/1 设置读取。旧文件缺失的原图尺寸无法反推，重新选择原文件才能记录；仅加载旧设置不会写回。客户端不能提交落点，原 impulse 201 / CSprayCan 射线及冷却决定是否喷出。服务端检查会话、玩家身份、偏移、大小、CRC 和像素编码；CRC 只用于传输完整性检查。

生产入口分别为 [客户端协议](../native/csol/client/hd_spray.cpp)、[WIC 导入](../native/csol/client/hd_spray_import.cpp)、[选项页](../native/csol/client/hd_spray_options.cpp)、[BSP 渲染](../native/csol/client/hd_spray_gl.cpp) 和 [服务端权威分发](../native/csol/server/hd_spray.cpp)。路径为选图 → WIC 合成 → 有界 QOI 载荷 → 引擎可靠通道 → 服务端校验及射线落点 → 接收端共享纹理与 BSP 裁剪。

准备好项目固定的 x86 Clang 和依赖后，在项目根目录执行：

```powershell
pwsh -NoProfile -File tools/Test-CSOLHDSpray.ps1 -Output build/hd-spray-check -Only all
```

截至 2026-10-30，对应生产模块的离线证据为：247452 项编码/动画、1683 项匹配 SDK 服务端、5031 项客户端协议/设置、496 项真实 WIC、71 项 BSP/共享资源检查；选项页对匹配 VGUI SDK 编译通过。完整本地候选的 x86 客户端和服务端构建也通过，但候选另外包含尚未发布的 K3/购买菜单依赖。本次公共树将同一 HD/GIF 模块接入已发布基线，完整补丁应用及源码依赖检查不等于对公共树重新做完整构建。

动态画面、实际上传取消/重试、双客户端及晚加入/重连/换图、移动 BSP、GL 性能仍需实机验收。既有静态喷图人工反馈不能替代这些项目。相关 BGM 命令修复及验证边界见 [音乐测试说明](../tests/csol-scenario-music/README.md)。
