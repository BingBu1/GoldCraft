## 修改

客户端 Append 成功后传递 `requireTagged`，不再紧接着重复扫描一次全轨 RLE。`PreparedSequenceModel::Read` 仍完整检查最后的真实字节，且要求附加输出带有效安全 metadata；失败不会开始或替换 model owner。`plugin.cpp` 源码不改，但作为改动头文件的实际消费者一同重编。

量化冲突跟踪从每字节 `unordered_map` 节点变为连续 occupancy 字节。occupancy 与值分离，编码值 0 不表示未写入；奇地址、部分共享、header/sample 重叠仍逐字节验证。仅当尺度不等才分配，保留浮点表达式、舍入、量化范围、错误文案、严格校验与不支持轨道策略。旧/new 完整源码都保留在冻结证据目录。

调用路径 P1：读 MDL/SEQ → 原有 decode/Append 与 RLE 校验 → 最终 PreparedSequenceModel 完整验证 → required-tag 门 → BeginLoad → 宿主原 loader → CompleteLoad。E2 约束验证/owner 次序，E3/E4 只优化 Append 内部临时冲突结构。
