# 灾难先兆墙面红色脉动

截图里的耐久提示已经收到墙体状态。《灾难先兆》首章的 BSP 为 27 段 `zbsbreak` 设置了 `renderfx=24`，RGB 为 225/25/25 或 255/25/25。三个章节共 38 段使用此效果，其中 29 段不透明、5 段为镂空材质、4 段为半透明材质。首章 BSP SHA-256 为 `c10c6f91418eb237079583e2c2de85fe0f1666802eb63d57a2fcb0e04b29527a`。截图中的具体实体索引待游戏复验。

## 修改前证据

使用项目现有 CSOL x86 `hw.dll.i64` 主库。PE32 模块基址 `0x37100000`，输入 SHA-256 `c7bddfda93c2e0877ea126a15a318b83cce74c59bb95e38a7301b08033ac7783`。下表均为 VA。

| 观察位置 | 行为与对应实现 |
| --- | --- |
| `0x3770E5ED` 调用 `0x3770F810` 后进入材质绘制，`0x3770FAF6` 将 `RenderColor` 参数传到 `0x37AD0990` | 颜色作为每个画刷绘制参数。现有宿主通过 `R_DrawWorldSurfaceModel` 的实体 UBO 传值，普通模式在 `R_SetRenderMode` 初始化为白色。 |
| `0x3770F977–0x3770FA2A` 和 `0x3788B847–0x3788B91A` | 两条路径均读取实体的效果 24、RGB 和透明度。RGB 归一化后乘 `(sin(time * 3.5) * 0.5 + 0.5) * 0.3 + 0.7`。三角函数入口 `0x37F53E1C` 指向 `_libm_sse2_sin_precise`，时钟变量 `0x39A7FDA0` 在 `0x3789FD9F–0x3789FDA7` 累计帧时间。 |
| `AddToFullPack` 和 `delta.lst` | 宿主已把 `renderfx`、`rendercolor` 和 `renderamt` 写入实体状态并序列化。使用该快照字段直接驱动画刷颜色。地图实体显隐、复位和耐久仍由现有实体生命周期驱动。 |

关键指令字节可从主库复核。`0x3770E5ED` 为 `E8 1E 12 00 00`，`0x3770F977` 为 `8B 86 34 03 00 00 83 F8 18`，`0x3788B847` 为 `83 BE 34 03 00 00 18`。已从原 PE 数据段核对 `3.5 / 0.5 / 0.3 / 0.7` 四个双精度常量。

## 宿主接入

在已有画刷参数上传中消费效果 24。多面墙和多个视图共用同一客户端时刻的脉动倍率。保留不透明与镂空材质的覆盖通道，半透明材质使用实体透明度。前向与 GBuffer 共用该实体颜色。 [Renderer 源码补丁](../patches/renderer-goldcraft.patch)

## 构建与验证

Renderer_AVX2 已使用 17:40 分配的 x86 Release 缓存完成单对象编译和链接。构建前后的源码、补丁和构建输入哈希一致。候选 DLL 为 `1e01e7d2…`，匹配 PDB 为 `8d75afab…`，CodeView GUID 为 `9A50F53E-359C-FC18-4C4C-44205044422E`，Age 为 1。本地构建回执保存在 `build/leon-character/wall-candidate/receipt.json`。

使用生产绘制入口中的同一段参数更新代码核对了 28 项颜色通道值，覆盖普通墙、不同脉动相位、镂空、半透明、阴影和时钟归零。RTX 4090 的隐藏 OpenGL 4.6 上下文使用生产画刷顶点与片段着色器，48 项像素通道值通过。前向和 GBuffer 中均呈现红色脉动，镂空像素保持裁掉，半透明保留实体透明度。本地通道结果见 `wall-ubo-values.json` 和 `wall-offscreen-gl.json`。

## 实际地图和重玩

独立 ReHLDS 与一个图形客户端在第一章、第三章分别校验 3,733 和 3,769 项资源并完成挂载与 HUD 提交。探针找到真实地图实体，将存活 CT 放在视线首先命中目标墙的位置。固定视角采集最终送显的 1280 × 720 帧，对比关闭效果 24、自然脉动、玩家伤害击破、同图重玩后的画面。

| 地图实体 | 最终画面和对照结果 |
| --- | --- |
| 首章不透明门 `*17` | 同一扇灰蓝色门在地图效果开启后变红。所选门板区域六帧的红通道均值为 71.59 至 102.16。 |
| 首章镂空墙 `*24` | 固定区域内 32,682 个像素明显偏红，17,529 个背景像素在中性、红色和破墙画面中保持一致，逐通道容差小于 4。 |
| 第三章半透明墙 `*37` | 原值为 125/255。对同一面完好的墙另采透明度 0 与 255 的对照，绿色和蓝色通道的背景拟合权重均约为 0.495，墙后车辆仍然可见。六个自然相位中红通道均值为 69.15 至 85.96。 |

玩家身份经该墙原有的 `TakeDamage` 回调造成伤害，三面墙均丢失碰撞并隐藏。通过 `amx_scenario_replay` 走正常同图重玩后，实体重获碰撞，生命值分别恢复至当局原值 50、50、100，客户端重新画出红墙。两章的独立服务端和客户端正常退出，每次临时部署的 52 项均已还原。测试为自动控制的单客户端。截图中玩家先前所指的那一面墙没有单独辨认。

画面和像素回执分别保存在工作区 `build/leon-character/wall-map-frames.jpg` 与 `wall-live-pixels.json`。公开补丁在锁定的 Renderer 上游修订 `872d151c` 上完整应用成功。相对于此前公开版本，生产源文件增加 23 行，包含数学头文件及画刷参数上传前的颜色分支。

## 沙盒 B 生效范围

沙盒 B 的 DLL 与配套 PDB 已备份并原子替换。常用服当时在第三章运行，实读完整 HUD 337 项。B 连接常用服时校验并挂载 3,788 项，内存中的 Renderer 调试标识与候选一致。独立桌面的选人页失焦后按设计暂停响应翻页，首次验证已回滚。随后使用隔离服原有选人命令让同一份 B 正常出生，最终从进程内再次核对 Renderer 标识，3,769 项资源全部通过，角色 1001、100 血、可见余额 7,500，延迟渲染已开启。B 正常退出并恢复玩家配置。旧 Renderer 与匹配符号保存在工作区 `build/leon-character/wall-local-b/rollback/`。
