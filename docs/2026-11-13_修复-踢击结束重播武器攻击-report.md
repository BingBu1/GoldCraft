# 踢击结束后重播武器攻击

用户确认故障发生在踢完之后：旧武器攻击动画从头播放。先前应急恢复保存了动画编号，却通过 SVC_WEAPONANIM 重新发出；引擎将动画开始时间清零。扩展武器预测器在模型从脚模切回枪模时，还会再次对齐同一个序列，形成第二处重播路径。

本次恢复原武器的视觉时间线，继续保留应急动作中的当前弹药、换弹提交和射击计时，不调用 Deploy，也不退回库存快照。该覆盖层是用户应急规则的宿主适配；原版踢击完成会 Deploy，不能把本次当前动作恢复称为原版 Deploy 的等价实现。

## 同步与生命周期

客户端冷解析两个动画全局，仅在精确匹配可用时设置 `csol_kick_phase=1`。服务端每次释放读取该能力，在回调后重新核对玩家、武器和地图；这不赋予客户端伤害或体力权限。完成时只为同一合法恢复武器附加一次 `ResumePhase`，随后发送普通 v1 完成包，防止用户信息遗留于旧客户端时卡在 Active。原10字节包框架与 v1 版本保留。

客户端只保留一个视觉租约，绑定服务器生命、武器、模型、序列和原始开始时间。旧脚模预测仍模拟数值但不呈现；真正恢复模型后的第一次有效预测对齐可保留时钟，之后退休票据。真实新攻击、不同序列、换枪、死亡、新生命、地图/资源退休和未匹配引擎均有独立拒绝/清理路径。连续踢击可在渲染器尚未替换脚模的短窗口内利用已确认的模型身份，不能将脚模当原枪保存。

常态预测只做线程/固定状态检查；没有待恢复票据时不查询模型目录。符号解析只在初始化，一次踢击只发状态变化消息，增加的普通完成包用于旧客户端回滚兼容。没有每帧磁盘/网络查询或临时堆分配；未据这些成本说明宣称实机 FPS 通过。
