# CSOL 还原：先取证，后实现

用户于 2026-11-04 再次明确：**有原版 IDA 证据才允许写还原代码，不能凭猜测实现，也不能先写代码再寻找支持它的证据。** 本规范是持续项目约束，不只适用于本次近战修复。

适用于 CSOL 武器、人物技能、动作、声音、模型与 SPR 特效、HUD、菜单、地图实体、灾变规则、怪物与 BOSS AI，以及这些功能的后续修复。主代理、子代理、恢复后的会话和外部代码交接均须遵守。用户明确要求的自定义差异单独记录，不冒充原版行为。

## 修改前必须具备的证据

1. **样本身份。** 记录实际原版模块名称、版本或来源、SHA-256、架构和映像基址；地址同时明确是 VA 还是 RVA。不同版本不得直接套用偏移。只分析工作区副本，不修改受保护安装。
2. **IDA 控制流。** 保存相关函数地址、反汇编或反编译结果及关键原始字节；核对调用者、被调用者、参数、分支条件、返回值和后续处理。反编译类型或字段含义有疑点时回到指令验证。
3. **实际消费者。** 表项或资源必须追到原版使用它的代码。WAV 名称不能决定是挥动声还是命中声；刀具选装表不能证明重复选择会重建、拒绝或直接成功；截图不能决定时序、伤害和生命周期。
4. **相关状态与时序。** 按本次改动覆盖创建、选装、切换、攻击、命中、计时、预测/消息、死亡和清理等有关路径。检查重复请求、取消、切回及调用后的副作用；不得只截取一个提前返回便宣布整个操作无副作用。
5. **可追溯结论。** 修改前先记录“证据 → 行为结论 → 对应实现位置”，列清已证事实和未定部分。证据中的数值、顺序、音频通道、透明方式和镜像条件应能对应到代码；不以“看起来差不多”替代。

已有证据可以复用，不要求每次重新建立数据库；但必须核对样本身份、证据正文、适用武器/角色/模式及完整调用上下文。旧报告中的结论不等于其依据已验证。证据缺失时继续使用 IDA 查明，不能用资源名、原 CS 的习惯写法或个人印象补齐。

## 证据不足时怎样推进

保持待还原行为未实现，记录缺少哪段调用链、字段或运行条件，继续取证及不依赖该结论的工作。允许调查脚本、只读诊断和验证夹具用于取证，但不得把试验假设混入生产行为。

若发现已有候选来自猜测，应隔离或撤回该候选，保留撤回记录，禁止进入构建、部署和发布。测试只能验证被执行的实现；即使通过很多断言，也不能证明一个未经原版取证的实现符合 CSOL。

移植到 ReGameDLL/MetaHook 所需的接口、生命周期保护和内存安全处理，应明确标注为宿主适配。以对应 SDK/源码和回归测试验证，不能宣称这些适配就是原 CSOL 的源代码结构，也不能借适配改变已证实的游戏行为。

## 验证与交付

每次报告分别列出原版证据、源码修改、编译、自动化检查、部署和真实游戏验收。可使用原指令回放或原版运行采样核对，相关回归应能检出旧错误；不为低影响文档变更增加无意义测试。画面截图失败或录音无效时，明确保留视觉/听感待验。

交接须包含样本 SHA-256、关键地址、证据保存位置、结论与源码对应关系、验证结果及剩余未知。接收方先审证据再合并，不能因其他模型或代理声称“已修复”就直接部署。源码可发布；原版 DLL、反编译正文、游戏资源、运行数据与秘密不随源码上传。
