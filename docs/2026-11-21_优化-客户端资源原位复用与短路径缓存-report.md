# 客户端原位读取和短路径缓存

可正常读取且与服务器清单相符的资源继续使用原游戏目录、下载目录和 PAK 中的文件。新下载或修复的资源进入 `Half-Life/gcr`，保留扩展名。测试中的呼吸音存为 `gcr/cd8edaa6.wav`，其绝对路径从嵌套缓存的 220 字符、上一版的 166 字符缩至 81 字符。完整 SHA-256 相同的旧缓存可原位使用。引擎无法打开过长的旧路径时，从已校验的读句柄复制到短目录，原文件保留。

## 下载目录中的同名资源

R3 按服务器清单中的逻辑路径查找已有文件。GoldSrc 默认读到的内容符合清单时直接使用。如果游戏目录或 PAK 的同名旧版本遮住下载目录，后台会打开 `cstrike_downloads/<逻辑路径>` 并核对完整 SHA-256，匹配后引擎直接读取原文件。后续清单要求游戏自带版本时，客户端也会重新检查上一次覆盖之下的原生文件。更新或取消时仍校验最终引擎视图并按需回滚。索引保持为 `gcr/index.bin`。只有 v4 修复下载或引擎打不开的过长文件才需要新的短缓存对象。

用沙盒 B 的两份 `models/w_zombibomb.mdl` 在实际 x86 文件系统中验证。两份原文件分别为 288,336 和 38,400 字节。按清单先选下载版，再选回游戏目录版，合计 0 次 HTTP 请求，未生成模型副本。同一进程保留挂载再次校验下载版时，VFS 打开 1 次，重新计算摘要的字节数为 0。同大小损坏的独立用例发起 1 次修复下载，保留原文件。40 组 x86 文件系统与 HTTP 用例和 40 组资源桥与进度用例通过。本轮未进行公网实机计时。

本轮累计包为 `GoldCraft-Server-Update-20261121-ShortCache-R3.zip`，SHA-256 为 `529d160e42e479c440d7877fab3c55b2696c3170183a26aff7f2727a7d6b7eb8`。沿用下文的服务端安装入口。原冰桑启动器在隔离安装目录从签名序号 2026112102 升至 2026112103，下载 1 个 GoldCraft.dll，再次检查的核心文件下载数为 0。源码提交 3c8dc486。本地回执位于 build/downloads-index-20261121 的 real-model.json、regression-final/result.json、upgrade-ok/receipt.json 和 shipping.json。

## 索引与校验

`gcr/index.bin` 把逻辑路径、长度和 32 字节完整 SHA-256 放在一起。3,611 项实机清单的索引占 255,528 字节。后台整批读取，成功提交后的清单发生变化才原子替换。索引文件丢失或损坏时会在下次校验成功后重建。磁盘索引仅用于选择校验流程。文件名取 SHA-256 前八个十六进制字符，同名前缀通过完整摘要区分并分配独立位置。

每轮由主线程按引擎实际搜索顺序解析每个逻辑路径，后台读文件和计算 SHA-256。进程内仅在文件身份、变更时间、大小和 PAK 范围匹配时复用已算出的摘要。清单相同、或只移除未挂载的条目时，保留资源各验证一次。需要修复时先检查已下载的原文件、短缓存和两种历史缓存，再按需下载。挂载改变后重新验证全部逻辑资源。失败或取消会恢复上一轮挂载。

原冰桑启动器经真实签名发布测试从序号 2026112003 升到 2026112102，下载 1 个 DLL，核验 20 个核心文件与 266 项配套资源。再次启动复用现有文件。本地受管专服通过同一安装入口自动退出、更新、重启，重新查询地图成功。重复安装保持原进程。兼容旧停服脚本退出时读取不到启动时间的情况，只有先前所有角色的本次正常退出记录齐全、相关进程都已结束，才会再次执行原停止脚本予以确认。
