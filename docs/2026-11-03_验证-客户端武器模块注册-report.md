证据到结论的链条：

1. 实际八个模块 `.cpp` 的静态构造经过 ThinLTO，测试入口观察到八个模块、十个 ID；因此组件链接没有丢弃注册对象。725/726 和 1022/1023 分别共用自己的模块。旧内联飞刀 220 与普通 CS 武器仍不登记为模块。
2. 编译器入口探针记录真实 callback 函数进入次序；Initialize、Video、Receive、Diagnostic 均保持 10–80 顺序，Reset 先全部 reset 再执行 CannonEffects。Predict 保留截至命中模块的完整前缀，普通/未知 ID 访问全部八个 cleanup predictor。
3. 新旧同组消息和命令产生相同 HUD、SPR/准星绘制参数、弹药、预测字段、动画/声音计数和最终诊断串；包括 `cl_lw=0/1`、攻击、换弹、冷却、重放、切回和地图清理。静止 K3 切普通刀时只同步正确 idle，后续命令不重复同步；晚到自定义事件不播放到刀上。
4. 不修改公共 controller 即可注册第九个合成弹夹模块；RGB(17,37,57) 被实际绘制消费者用于五个数字、图标和分隔线，证明接口没有继续硬编码红色通道。
5. 独立非法注册用例证明失败不会发布部分映射，且初始化在回调执行前拒绝冲突。固定表查询、遍历和无分配回调的 lifecycle 观察为零堆分配；这不代表所有实际武器绘制均零分配。
