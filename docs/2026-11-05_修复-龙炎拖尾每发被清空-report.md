# 修复：龙炎右键拖尾火星每发被清空

用户 2026-11-05 报告：龙炎（Balrog-Ⅺ）右键龙息弹与原版不符，具体是“太暗太淡、没有拖尾火星”。

## 原版核对（未发现参数差异）

原 MP `39f962f3…`、原 client `f4145136…`，复用 `analysis/csol-model-20261017/balrog-fidelity-20261103` 与 `skull-balrog11-20261102` 证据，本轮重新阅读：

- Spawn `10624980`：movetype 9、solid 1、模型 `sprites/flame_puff01.spr`、rendermode 5、renderamt 90、framerate `RANDOM_LONG(1,30)`；随后 `11493570` 广播 TempEmit（interval .01、life .3、flags 0x30、fps100、mode5、alpha40、颜色 255、spread16、size40）。
- Think `10624210`：每次把 pev `+154/+158/+15C` 写为 0.8（CSO entvars 的 scale 三分量），推进帧，恢复初速，到期删除。
- Touch `10624450`：无视觉效果，只在 BSP 上删除自身。
- 客户端绘制 `1DE2F10`：flags&0x10 用 rendercolor；`Color4f(r/255,g/255,b/255,alpha/255)`；半尺寸 .5；RenderMode 取粒子模式，CullFace(TRI_NONE)，QUADS。

这些都与现有实现一致，不能靠调亮度、尺寸或透明度来“修”。

## 实机采样定位

用户同意后，结束 B（PID 38284），以 `CSOL_DIAGNOSTIC_PATH=sandbox/cs-client-b/logs/csol-diagnostics.json` 重启（PID 43476），连现有专服。用户右键 5 次后读到：

```
"balrog11Flame":{"received":25,"emitted":105,"retired":0,"invalid":0,"exhausted":0,"draws":1015}
"clockCorrections":1,"largeClockCorrections":1
```

25 条消息（5 发×5 道火焰）全部收到，但每道火焰平均只生成约 4 个粒子；火焰寿命为 0.75 秒，按 .01 秒间隔本应有几十个。`retired` 为 0，说明发射器从没走到正常退出，而是被整体清空。帧时钟倒退只有 1 次（连接时）。

## 根因

`native/csol/client/balrog11_flame.cpp` 的 `Receive` 拿消息解析时的 `GetClientTime()`（收包时间）和上一帧的插值时间比较，一旦更早就调用 `ResetBalrog11Flame()`。收包时间正常就略早于上一帧插值时间，所以**每收到一条 TempEmit，就清空所有正在飞的拖尾和粒子**。`native/csol/client/session.cpp` 的 `SynchronizeFrameSession` 早已记录同一规律：“User messages observe packet time, HUD_Frame observes interpolated time”，并规定只在换关时重置。这个时间比较是移植时自行加上的生命周期判断，原版没有。

## 改动

- `Receive`：删除收包时间与帧时间的比较和清空。
- `Advance`：帧时间倒退时视为网络时钟校正，只更新 `lastTime` 并跳过这一帧，不清空，也不让粒子倒退移动；非有限时间仍清空。换图/会话仍经 `SynchronizeSession → ClearScene → ResetBalrog11Flame` 清理。
- `tests/csol-skull-balrog/flame.cpp`：把旧的“时间倒退即清空”断言换成两条回归：收包时间早于上一帧时，已有发射器和粒子保留，并继续发射；帧时间倒退时保留状态，下一帧正常发射。

- 客户端：以 B 已部署的 `build/skull3-audit-20261105/client-full-02`（CSOLSupport `4a061818…`）为基线，只用其冻结头文件的逐字节副本重编 `balrog11_flame.cpp`、`elite_visuals.cpp` 两个 TU，其余 204 个对象与原链接参数不变：`build/csol-balrog-trail-20261105/client-dll-03`，DLL `5be5fa8a…`、PDB GUID 匹配。两文件在构建前被另一会话改为“时钟倒退时保留 lastTime、跳过本帧”，测试按该版本重跑：龙炎 648/0、原版粒子 432/0、BOSS 尾迹 426 通过。
- 部署：备份 `sandbox/cs-client-b/backups/csolsupport-20261106-094645`，校验后原子替换 B 的 DLL/PDB。
- 专服当时已停止；`Start-Sandbox.ps1` 因 swds.dll 与 `rehlds-deployment.json` 登记不符拒绝启动（未改该校验）。用户同意后照 `build/replay-fix-20261105/live/launch.json` 原命令与 HTTP 环境重启，记录 `build/csol-balrog-trail-20261105/server-launch.json`（PID 33936，zs_2gate，模式 2）。
- 实机：45 道火焰生成 1775 个粒子、45 个发射器正常退出；`capture-03` 截图证实拖尾已绘制。
- 剩余的“太暗”：B（与用户普通安装相同）配置 `r_gamma_blend 0`、`gamma 3`。Renderer `triapi_shader.frag.glsl` 在该模式下把顶点色（Color4f 的 r·a=0.157）和贴图都转到线性空间（`GammaToLinear`，指数取 `gamma`）后再叠加，低透明度加法粒子被压暗约两个数量级。原 CSO hw `378EDD90` Color4f 为 `glColor4f(r·a,g·a,b·a,1)`，`378EE07D` TransAdd 为 `glBlendFunc(GL_ONE,GL_ONE)`，即伽马空间叠加。用户在 B 控制台设置 `r_gamma_blend 1` 后确认火焰与原版一致。这是显示配置差异，不是龙炎代码；未修改任何配置文件。
