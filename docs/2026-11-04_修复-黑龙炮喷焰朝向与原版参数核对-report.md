# 黑龙炮喷焰朝向与原版参数核对

2026-11-04。范围为 `native/csol/client/cannon.cpp` 的客户端喷焰、数字枪口与烟雾参数审查。实际 SDK 编译和原指令对照已通过；已随完整客户端 54f07fd9 部署到本地单 B，本报告不宣称游戏画面已经与原版完全一致。

## 结果与变更

原版喷焰把随机数写入 `entity.angles`，当前实现误写入 `entity.baseline.angles`。后者在临时实体更新中是角速度，导致原本固定随机朝向的粒子不断旋转。修复后保留原版 `FTENT_ROTATE`，只改正确的字段。

另外修正原版散射系数、玩家速度继承的浮点运算顺序，并保留分配器清零的 baseline alpha。没有扩大喷焰尺寸、增加数量、延长寿命、修改 Renderer 或资源。

- 生产文件：`native/csol/client/cannon.cpp`，SHA-256 `a1b0c49ea5e867169edf684d342adabf9ace8f54774d937af8acb663445a5053`。
- 独立原指令夹具：`tests/csol-weapon-slots/cannon_effects.cpp`；在现有 `CSOL_BUILD_WEAPON_SLOT_TESTS` 开关内增加 `csol_cannon_effects_probe`，使用真实 MetaHookSv SDK。
- 既有 `tests/csol-weapon-slots/client.cpp` 增加初始朝向与零角速度断言。本轮未重新构建整套该测试程序；新独立夹具直接编译和执行了生产实现。
- 仅冻结上述生产文件到 `build/csol-cannon-fx-20261104/source-cannon/`。与已部署 `client-hud-full-01` 的逐行差异保存在 `source-cannon/cannon.diff`。

## Findings

**F-01，已验证，高置信度，关联 E-01/E-02/E-03/E-06/E-07。** 初始朝向误写为角速度。生产修正使用 SDK 命名字段 `entity.angles`，不把 CSO 原始偏移带入 CS 1.6 ABI。原版 `SPR_VP_PARALLEL` 在 roll 非零时按朝向 sprite 绘制，因此这是实际表现相关的字段错误。

**F-02，已验证，高置信度，关联 E-04/E-05/E-06/E-07。** 原版散射角常量与标准 π/180 不同，且继承速度有明确的 float/double 舍入边界。使用原始常量，并关闭该函数的 clang FMA contraction。该差异很小，不能单独解释“特效不够饱满”。

**F-03，参数及资源审查通过，关联 E-08/E-09。** 不应凭视觉描述任意增大特效。现有资源身份一致，参数应保持如下原版值：

| 效果 | 原版参数 | 本轮处理 |
|---|---|---|
| flame_puff01 | 12 个；20 fps；22 帧；初始 scale 0.3–0.8，目标 1.5–2；每次更新加 0.03；additive；renderamt 150；FadeSlow | 修朝向与运算，保留数量/尺寸/帧率 |
| flame 碰撞 | 速度乘 0.01；framerate 改 60；不另改 die | 原指令对照通过 |

## 验证方法与边界

`flame_oracle.py` 在 Unicorn 中执行原版 client 的生成/grow/hit 指令，并跨模块执行真实 HW 的分配、清零、DefaultSprite 参数与寿命路径。资源查询、随机数、CRT sin/cos、memset 和池耗尽使用受控服务边界。随机取值每个粒子仍严格检查原调用参数范围，使用固定种子，涵盖 owner 1–32、站立/蹲下、容量 0/1/7/12、上下限随机值、不同时间、更新次数和碰撞。

对比字段包括数量、分配调用次数、flags、die、frameMax、fadeSpeed、bounceFactor、frame、framerate、scale、target、render mode/amount/baseline amount/fx/color、owner、origin、angles、angularVelocity、velocity。比较浮点按 float 位模式处理。

可在本工作区重现最终对照：

```powershell
python build/csol-cannon-fx-20261104/flame_oracle.py build/csol-cannon-fx-20261104/final/probe.exe build/csol-cannon-fx-20261104/final/recheck.json
```

依赖已保留的、身份匹配的私人原始样本和 Python Unicorn/Capstone；不上传 DLL、反汇编或游戏资源。单独编译命令保存在 `final/build.json`，其 Arkari 参数为 x86、C++20、O3、ThinLTO、AVX2、precise float。构建结束后重新核对 `final/inputs.json` 所列输入，未发现漂移。

Renderer 的只读审查显示 `gl_sprite.cpp` 的 additive 使用 `GL_ONE, GL_ONE`，透明度乘入 RGB，depth mask 关闭；TransAlpha 使用 `SRC_ALPHA, ONE_MINUS_SRC_ALPHA`。sprite roll 通过 `entity.angles[2]` 决定带朝向绘制。该结论不是运行中 GL 状态或原版亮度的实测证据，因此本轮没有修改 Renderer，也不对“视觉完全一致”作验收。
