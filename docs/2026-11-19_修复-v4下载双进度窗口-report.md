# v4 下载双进度窗口

下载时使用 GoldSrc 原生双进度窗口。上栏和右上角计数读取已完成文件数与当前已发现的下载队列。下栏显示最早提交的在途文件、实际传输字节比例和 GameUI 自己估算的剩余时间。初次本地校验仍可能发现新的缺失文件，队列总数会随之增加。

## 原生接口与实现

在工作区副本中核对 Steam HL10210 的 PE32 模块。两份模块的映像基址均为 `0x10000000`，下列地址为 VA。IDA 提取的 13 个指令及虚表窗口，共 1,684 字节，与 PE 文件原字节一致。私有证据位于 `analysis/download-dual-ui-20261119`。

| 证据 | 原版行为 | 对应路径 |
| --- | --- | --- |
| GameUI SHA-256 `b9b8c0c36bd19681627001c06ce2a15496da06b72315d561a12a3964e0265811`。`0x1002B3F0` → `0x1002DE80`，`0x1002B430` → `0x1002DFE0`，`0x1002DAC0` | 次栏从小于等于 0.99 的比例开启，读取原生普通或 VAC 双进度布局。进度下降时重新开始计时，文件名写入次栏标签。 | `resource_bridge.cpp` 调用 `GameUI007` 槽 18 和 19。先提交零再提交实际比例，每次更新复核连接代次。 |
| hw SHA-256 `9ba9a2db5e07598fd59afa35507a98c86162e4e15b3835177b78c11842cd2295`。`0x101A6441`，`0x101C6AB1–0x101C6AF3` 和 `0x101C4540` | 原生下载提交下载文案、当前文件名及已收字节比例。 | `resource_update.cpp` 从在途任务取得常数时间快照。在首遍校验期间已经启动的 HTTP 作业也会显示进度。 |
| GameUI `0x1002B820` 和 `0x1002B960`。hw `0x101CEC00` | Start 重用当前布局。Stop(false) 释放当前面板和模态状态。引擎的已有连接重连分支可保留窗口。 | HTTP 结束后关闭双栏，再启动复核进度。旧连接退役后的布局由下一次取得窗口控制权的 v4 校验清理。 |

GUI 更新在游戏主线程执行。连续的字节变化以约 30 Hz 刷新，校验、下载和交接的布局变化即时发布。继续使用现有并发传输、校验及准入流程。

## 验证

- 完整 x86 Release GoldCraft 构建通过。按发布源码重链接的候选 DLL 921fbb35fdfb 通过 37 项桥接回归，其中 8 项覆盖双栏。初次打开上栏就触发取消的负对照出现两个错误，修正状态后通过。回执见 build/download-dual-ui-20261119/relink-final/receipt.json。
- WinHTTP 和真实 VFS 的 24 个集成用例通过。慢下载读到了部分文件的真实字节，此时完成数为零。取消清除了旧任务，下一次同代次会话重新下载并通过了最终 VFS 复核。其他用例包括八路并发、503 重试和损坏缓存修复。
- 本地专服的 322 项 HUD 资源闭包通过预检，经回环 FastDL 下载的测试文件与源文件 SHA 一致。客户端运行画面、实际取消按钮和正式服分发待验。武器验收期间沙盒 B 由另一对话使用。

构建及测试回执位于 `build/download-dual-ui-20261119`。可以从 Git Bash 对当次完整构建运行以下测试。

```bash
ctest --test-dir build/download-dual-ui-20261119/client \
  -R 'goldcraft_(resource_bridge|precache_client)' --output-on-failure
```
