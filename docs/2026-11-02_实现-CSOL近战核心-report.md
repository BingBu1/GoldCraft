# 青龙偃月刀与旋风：近战核心

本阶段公开两刀的攻击时序、伤害配置、预测字段适配、基础资源身份和 HUD 资源接线。服务端实体、刀槽发放事务与客户端攻击表现仍在工作区整合，不能将本提交视为已部署或可完整游玩。

## 原版依据

匹配的 x86 MP SHA-256 为 `39f962f34816411e615f01e5279d914204f7fd07c5a5112b0b303acafe0308b2`。IDA 读取两属性构造、四攻击入口、四延迟命中与原刀分派，164 段共 24,760 字节逐段核对原 PE；补充核对 49 段 3,951 字节。出现栈分析警告的伪码没有用作实现依据。

- 青龙入口 `110B6490/110B6670`：左键交替动画 1、2，延迟 0.6、0.3 秒；右键动画 4，延迟 0.66 秒。
- 青龙完成函数 `110B7740/110B8040`：第二刀仍减去固定参数 0.6，不能把两次左键都设为相同总冷却；右键完成动画为 5。
- 旋风入口 `110D2540/110D26C0`：左右键均延迟 1 秒，距离分别 95、78，完整扇区角分别 90°、200°；左键空挥与接触后的动画不同。
- 原刀型 16、10 与原物品 483、363、InGameID 4016、4010 分开保存。1022、1023 是本项目桥接 ID，不冒充原版武器 ID。

两个 JSON 保留原基础伤害和模式倍率，管理员可调整伤害。原 CSO 模式号与本项目模式枚举不同，必须由宿主明确转换。坏配置不会覆盖现有有效配置。

预测适配依据实际 GoldSrc `weapon_data_t` delta：动画及交替位使用 `m_iWeaponState`，序号使用 `fuser2/8`，延迟使用 `fuser1`。不使用未传输的 `iuser2/iuser3`，也不改引擎 ABI。

## 已有验证与边界

核心测试 28 项通过，实际客户端组件 119 项通过，其中预测量化覆盖全部 65,536 个序号。核心源文件与对应冻结构建输入的 SHA-256 已逐项复核一致。本次没有因为提交重复运行未变化的测试。

证据位于本地 `build/csol-melee-20261102/core-01`、`sdk-06`、`sdk-07/audit-corrected.json`；IDA 原字节记录位于 `analysis/csol-model-20261017/melee-20261102`。游戏资产、DLL、逆向数据库和原始反汇编不发布。

原刀描述符只有一个卡片区域与死亡图标名称。新增转换保留原图集与坐标，用同一张卡适配 CS 的 `weapon`/`weapon_s` 两个选择角色，不添加弹药。击杀图标使用原 `hud.txt` 的 `d_dragonsword` 与 `d_skullaxe` 行。现代 HUD 导出也从原刀描述符裁图并读取原中文名称，资源命名空间与普通 CS 图集隔离。

新资源收集器 8 个 TU 与链接通过；完整 inventory/pickup/death 客户端 TU 的受控检查 61 项通过，覆盖两种屏宽、选择与拾取、死亡图坐标及稳定列表指针。资源审计覆盖 13 处 Precache、36 项目标和 317 个输入；旋风模型完整闭包 16 项通过，青龙缺失音效时原目录收集明确失败。M249EX 与 Balrog11 的原 HUD 描述和资源映射一并供收集器消费，不代表两枪实体已激活。

公开源码未激活服务器或客户端入口。发放回滚、实际刀槽替换、完整 DLL、玻璃与墙遮挡、多人扇区命中、人物动作及下载仍需分别验证。集中资源目录缺少模型事件引用的 `dragonsword_stab.wav`，不以其他音效替代。两刀购买价格尚无闭合原证，当前不添加猜测价格的商品。

## 原包音效核查

本机当前游戏的 6 个 NAR 与 122 个资源 PAK 已重新解码索引，共 75,435 项；另核对 6 个旧 NAR 备份，共 26,098 项。全部 134 个包、101,533 项均没有 `sound/weapons/dragonsword_stab.wav`。当前 `cstrike.nar` 确实包含 `dragonsword_stab_hit.wav`，但它是不同的资源名，不能据此改名代替。

证据 E-01：`build/csol-melee-20261102/stab-archive-search-01/result.json` 保存当前包路径、数量、索引名称摘要及相关匹配；每个索引都从原包重新读取，未沿用旧索引 JSON。E-02：同目录 `reference-result.json` 保存旧备份结果及原模型的事件。两个旧备份并非标准文件名前缀，初次严格解析失败保留在 `backup-nars.json`；后续按文件中真实路径解码成功，没有把解析失败计作不存在。

调用路径 P-01：原 `v_dragonsword.mdl` → 序列 4 `stab` → 第 8 帧 → 事件 5004 → `weapons/dragonsword_stab.wav`。从当前 `cstrike.nar`、`estrike.nar` 读取的模型载荷均通过储存 CRC 和解码大小校验，两版都含此引用。common 模型 SHA-256 为 `270283dd20fb39ef4e86a11ea6b29f95aab725af0a72d8ab8576f7cf8db1fc57`，与 `cstrike.nar` 版逐字节一致。

结论 F-01（依据 E-01、E-02）：此次 common 缺项不是漏提取该文件；原模型本身引用了本机当前原包中不存在的路径。尚未证明原客户端会忽略或改播此事件，因此不能把“原模型遗留引用”当作已证实的运行时行为。用户在核查后明确要求“那就不用这个音效了”，这成为本项目的处理依据，不冒充原版播放语义。

按此要求，`studio_sound.hpp` 统一限定模型 `models/v_dragonsword.mdl`、事件 5004、选项 `weapons/dragonsword_stab.wav` 三个条件。依赖收集器不导出该项，客户端事件入口不继续转发该事件；路径比较支持 ASCII 大小写和分隔符差异。其他模型、事件、命中音效及必需资源检查不受此例外影响。原资产不修改，不创建占位音效。资源审计记录原模型事件及明确排除原因，不能把被用户排除的音效报告成已找到。

该窄修已通过实际 SDK 布局与生产事件入口截取的 106 项检查；截取在测试构建时生成 `studio_sound_entry.inc`，后续渲染处理只作为观察边界。资源收集器增量编译、链接通过，7 个真实模型直接读取 common 均成功：35 个唯一目标、317 个输入摘要保持，明确省略 1 项，无占位文件或其他缺失。额外 3 个实际收集器负例验证其他模型、其他文件名及 5005 事件仍会拒绝缺文件。证据为 `studio-sound-01`、`collector-02`、`resources-06` 与 `resources-06-negative`；这是组件及资源验证，不是实机听音或正式部署。

复核入口为本地 `build/csol-melee-20261102/search_stab_archives.py` 与 `check_stab_references.py`。前者使用首次运行的独立证据目录，重复执行应使用新目录以保留历史。工具依赖本机原包与已有解码研究脚本，游戏包和原始索引不随公开源码分发。
