## 结论与调用路径

**F-01（validated，n/a_re，置信高，E-02/E-03）**：主目标启用模板后使用 `GL_DEPTH32F_STENCIL8`，普通深度目标仍使用 `GL_DEPTH_COMPONENT`。直接深度 blit 不兼容，失败后旧深度保留，因而会影响依赖该副本的遮挡判断。位置为 `RenderTarget.copyDepthFrom`、AAA `RenderUtil.copyDepthSafely` 和 `copySafely`。

**F-02（candidate，n/a_re，置信中，E-01/E-02）**：上述路径能解释现场错误，但没有录到报错瞬间的原始 FBO 绑定与调用栈，不能将全部日志唯一归因于某一个模组。NightFall 也调用标准复制入口；其每种特效的现场目标与完整画面不在本次自动证据范围内。

**P-01（callflow）**：TACZ 客户端初始化启用主目标模板（E-02）→ AAA 创建普通深度副本（E-02）→ 复制方法提交不同格式的深度 blit（E-02）→ 独立 GPU 复现 1282 和未更新的深度（E-03/F-01）→ 候选通过共同转换入口执行深度采样写入，并验证实际 AAA 调用与像素（E-04）。

## 修复及边界

`DepthCopy` 在 Minecraft 目标分配时记录深度纹理格式、尺寸与身份，在删除时移除记录。普通同格式复制保留原路径。只有已登记的两个单采样目标、完整矩形、最近邻及仅深度或颜色加深度复制，才在格式不同的情况下使用 GPU 深度转换。

转换使用源深度纹理写入 `gl_FragDepth`；组合复制先完成颜色部分，深度阶段不写颜色或模板。测试涵盖双向格式、缩放、scissor、rasterizer discard、两个颜色附件、模板值保留，以及深度测试/写掩码、裁剪平面、采样状态、视口、纹理与绘制缓冲恢复。矩形裁剪之外的像素保留；未知目标、部分矩形、模板复制或无效过滤继续由原调用验证，不吞掉其错误。

标准 `GlStateManager` 入口与 AAA 绕过它的三条 LWJGL 调用共用同一实现。AAA 使用可选 Mixin，并验证了实际重载选择；不安装该模组时普通目标注入仍正常。HUD 诊断增加 `depthFormatConversions`，供后续现场确认。退出时释放转换资源。

转换资源复用，纹理格式只在分配时查询。开发类连续 256 次转换的 Java 分配为 0；最终生产类同样本合计 928 字节，低于测试的 1024 字节总上限，未见按次增长的缓冲视图分配。此为转换路径的分配检查，不是实际游戏 FPS 验收。
