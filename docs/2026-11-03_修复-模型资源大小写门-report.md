# 模型资源识别大小写修复

SKULL5 的真实内嵌贴图名为 `CSO_HighQ_Hand_512.BMP` 和 `CSO_Girl_Hand_long.bmp`。原依赖收集器能够识别这些名称，但专服 loader 的提前检查使用区分大小写的 `strncmp`；没有旁挂 JSON 的该模型因此被提前跳过，未广告换手贴图和模型 5004 动作音效。

实现方将入口检查改为 `Q_strnicmp`。匹配的 ReHLDS Windows SDK `public/strtools.h` 将其映射为 `_strnicmp`，没有新增或猜测引擎 ABI。独立验证未修改生产实现。

## 验证

`engine-resources-component-05` 使用当前已发布缓存夹具、实际完整 loader、收集器与 ReHLDS SDK，共 488 项、0 失败：

- 小写、大写、混合 `cso_` 均进入资源收集；普通、伪前缀模型仍跳过。
- 实际 SKULL5 没有旁挂模型/手模/来源 JSON，冷、热两次广告与真实收集器结果一致。
- 广告包含 `skull5_draw.wav`、`skull5_boltpull.wav`、`skull5_clipin.wav`、`skull5_clipout.wav`，以及 `MaleShort.tga`、`FemaleLong.tga`。原文件均非空并另存完整 SHA-256。
- `engine-resources-negative-02` 仅在冻结副本恢复旧区分大小写入口，大写首轮即在“应有一个模型进入收集”的检查失败；不是修改期待值后通过。

完整引擎 `engine-resources-full-02` 以已验证 HTTP/缓存版 `e98e69dd…` 为基线，重编 loader 和最新已验依赖收集器，2 TU 加链接通过。6,498 项登记输入保持，实际链接仅替换 `csol_loader.obj`、`dependencies.obj`；其他对象和库的路径及 SHA 保持，包括 HTTP 路由。x86 PE 与 PDB GUID/age 匹配，两个产物均为独立文件。

- swds.dll：2,366,976 字节，SHA-256 `57e105da01dddca609c1e6988e1d9f304013a0e2afcd61b93070644426a47422`。
- swds.pdb：19,750,912 字节，SHA-256 `60172bf750896c82a34b2e8ec481eb55684e0e2e7dcd8da1cdcb0683208406db`。

编译沿用 x86 C++20/O3/ThinLTO/AVX2/precise 参数及原浮点约束。父独立回读构建结果中 1713 个引用及最终交接 11 个引用，全部匹配。

随后单专服实测 `server-live-04` 已加载新引擎：704 项预期资源全部登记；491 段 WAV 和句子 JSON 共 492 个 HTTP 完整正文、40744638 字节与源 SHA 一致。本地两文件原子部署回执在 `deploy-engine-02`，原其他 525 项配套文件保持。B 尚未完成首次下载及 J/技能验证，不能将服务端 HTTP 探针当作游戏验收；正式远端未更新。

## 保留的准备失败

component-01 使用旧缓存头而缺少 metadata 字段；02 复用对象用了相对路径；03 旧夹具没有新缓存所需的文件系统 globals。04 补齐后通过，但使用旧私有夹具；最终05改为明确冻结当前已发布夹具，移除临时 globals，再通过同样488项。八个收集器对象只在实际源码/include/SHA核同后复用。完整引擎01在准备时因环境身份记录含额外 `links` 字段导致字典比较失败，内容 SHA 未变；02改为核验字节数与 SHA。首败均保留，生产没有为测试作调整。

复现入口为 `tests/csol-model-resource-gate/run.py` 和该目录说明。证据位于 `build/csol-emotion-integration-20261103/engine-resources-*`；SDK、原资源、DLL、对象和本机环境不进入源码发布。
