# 滑行接口与共享粒子运行接线

泰迪熊滑行已接入实际 TempEmit 接收器、共享 128 槽发射器与普通粒子 owner。
先闭合原接口获取链及消息戳语义，再使用匹配宿主的 `cl_parsecount` 和 SDK 命名字段。
5288 项 SDK 与原版 10 场景 / 50 次调度对照通过；完整 x86 客户端构建与输入封存通过，未部署或实机验收。

## 宿主 ABI 与实现

匹配宿主的完整 `1019EB50..1019EFA9`、`1019FD20..101A00BD`、`101960B0..101960E1`
分别为 273 / 218 / 18 指令。未掩码计数写 `11282A84`，packet `+0C` 写同值，
85 dwords 复制到实体 `+2B0`；原点 `2C0/2C4/2C8 → B48/B4C/B50`。
这与实际 SDK 的 `curstate`、`curstate.messagenum`、`origin` 和 `sizeof(cl_entity_t)`
断言分别核同。原 CSOL 的 `2E0/C7C/1014` 不套到宿主实体布局。

运行源码为 `native/csol/client/scenario/core/particle_effects.cpp`。
仅接 `sprites/ef_bat.spr` 的已证严格 82B 形式，复用独立 Sliding Read/Spawn/Tick。
共享 emitter variant 增加 Sliding payload，粒子使用明确类型包装区分有限火花与循环滑行，
没有第二份容量或逐帧资源加载。模型使用已核的 15 帧契约。

每次合格发射从当前实体 render origin 加未旋转 offset 生成世界位置。
已经发射的粒子不重新附着；alpha 保留 wire255 钳至 250、fps30 循环、零重力/无碰撞、
size50/growth.2/fade.2、三次发射/间隔.1/life.5。spread 为零仍消费三次 spread RNG 和 mass RNG。

原版在 null entity 上直接解引用。宿主将该情况记为无效并停止本次发射 pass，
保留已经消费的次数和时间；这是明确的内存安全适配，不宣称原版能优雅忽略，也不返回假的
stamp/origin/成功。每个 owner、时间、RNG 回调后的 generation 取消沿用既有宿主生命周期保护。
普通地图/场景/退出清理不新增猜测规则。

## 复现与后续

```bash
.tools/hlam-venv/Scripts/python.exe -B -X utf8 tests/csol-teddy-sparks/sliding_runtime_oracle.py \
  --executable build/teddy-sliding-runtime-sdk-20261112-04/client.exe \
  --client analysis/csol-model-20261017/balrog-visual-20261104/client.dll \
  --output build/teddy-sliding-runtime-repro/result.json
```

需匹配私有样本和已保存 IDA；输出目录不得已存在。源码直接在项目原位编译，不创建源码副本。

热路径每个滑行发射记录一次实体查询与一次标量比较，固定连续池 O(1) 分配/退役，
逐帧不读取磁盘网络或解析目录。新接线未进行实际 CPU/调用栈/帧时采样，不宣称取得性能收益。

原版 Sliding 获取链不再是未知；仍须部署配套 client/目录与全部必要双端 owner/HTTP，
验证真实滑行、地图/断线和多人。Meteor hand/stop 的公共 emitter 接线、完整原断线、
