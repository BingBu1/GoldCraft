# 870 装填、开火与八霰弹组件

870 的逐发装填、开火、延迟泵动抛壳和八霰弹弹道已经实现并通过原指令对照。**本阶段尚未接入整枪 SDK、购买、资源作者或客户端路由，也没有构建部署新的游戏 DLL。** 当前试玩仍为此前配套八枪；M16/G43 最低 3 级 CS 材质穿透见 [八枪部署记录](2026-11-16_部署-CoF八枪与步枪穿透-report.md)。完整范围保持 [CoF Goal](COF_GOAL.md)。

## 范围与样本

用户授权继续移植其提供的 CoF 武器，合作模式表现为准；长枪推搡共用现有 CSOL 体力。此次仅完成 870 的独立组件及实际 ReGameDLL 弹道适配，没有接入 CoF 怪物 AI、寻路、受击任务或独立体力恢复。私有范围及时间线在 `analysis/cof-weapons-20261111/shotgun-20261116/{scope.md,timeline.md}`。

原版 CoF `hl.dll`：PE32/x86，基址 `0x10000000`，SHA-256 `0036b91c01e92ed205513f52563053a55a66a32d257efb5f476b8f1f3dde0e63`。所有地址均为此样本 VA。使用工作区只读副本和既有 IDA 会话，未改原安装。

原函数对照使用 Unicorn 执行匹配样本指令，记录有序回调、回调时状态、浮点位型和消息字段。边界中的动画/音频/调度与实体消费者受控；它们不代表真实播放或地图命中。八霰弹检查覆盖每颗取消、一次 Clear/Apply、嵌套伤害寄存器恢复；旧单发和原 CS 左轮/两种步枪材质调用回归同时通过。

首轮射击组 `-01` 正确检出抛壳差异。`-02` 曾交换夹具向量而通过，随后审查真实 SDK 布局发现语义不正确，已撤销其通过资格并保存证据。最终 `-03` 恢复正确夹具、修改生产泵动几何后才通过，没有把错误夹具当验收。

保持 C++20、x86、O3/ThinLTO/AVX2、precise FP 与 `ffp-contract=off`。新组件仅固定大小状态，射击 10000 次未新增分配；弹道编译期固定 1/8 颗，原事务内循环，未增加热路径配置解析、资源读取、动态缓存或线程。这些成本检查不等于实机性能通过；此次没有 CPU/帧时采样。

## 复现与接续

从项目根目录直接使用 Git Bash；三个测试 README 给出完整参数。装填/射击分别使用 `PREEDIT-control.json` / `PREEDIT-shot.json`；弹道使用 `PREEDIT-ballistics.json`。全部输出必须是新建的工作区 build 子目录。最终源码及依赖核验在 `build/cof-shotgun-components-publication-20261116-01/validation.json`。

继续闭合 870 机瞄与完整派生/common 帧，再接真实 SDK 武器、人物模型与 CSOL 动作、共享体力、工厂/资源/音效、HUD/购买和配套构建。技能扩容弹匣的宿主保护必须在 SDK 层处理；原组件保留原 5 发等值判定，不能直接据此把扩容弹匣启动普通装填。完整 25 库存身份/变体、丢拾、多人权威和真实性能保持开放。
