# 原生 CS 在 Minecraft 液体中游泳

用户确认问题发生在原生 CS 形态、约一格深的水中。匹配 ReGameDLL 的 `PM_CheckWater` 在站立玩家脚底上方 36 个 GoldSrc 单位取腰部样本；一格 MC 水源表面约为 28.44 单位。旧桥接如实报告水体，但原生移动只把它判为涉水，不执行 `PM_Jump` 的游泳上浮分支。

共享 `fluids::MovementScope` 现在仅对 MC 液体中的腰部判定补充 0.4 格（12.8 单位）浮力门槛。水深超过该值且脚底也在同种液体中时，允许原生水中移动和跳跃上浮。客户端预测与专服使用同一段代码，MC 控制形态不启用这个适配器。

头部采样仍使用真实水面，浅水不会被标成全身淹没。`PM_TruePointContents`、实体/地图碰撞 hull、原生 BSP 水与固体优先级不变。没有扩大液体几何，也没有新增游泳姿势或绕过碰撞。低于门槛的薄水层继续涉水；失效租约、切世界和停用适配器沿用现有清理。

## 验证

`goldcraft_fluid_movement` 从固定 ReGameDLL 源码提取实际 `PM_CheckWater`、`PM_Jump`、`PM_WaterMove` 和 `PM_CategorizePosition`，使用匹配 PM SDK，生成内容只留在构建目录。35 项检查覆盖旧路径浅水负对照、新路径上浮、深水与原生水逐值对照、浅水头部、熔岩、下蹲、死亡/观察者、不扩大真实水体、碰撞回调及嵌套恢复。跟随原有 `goldcraft_fluid_volumes` 的 4045 项协议、租约、片段与 BVH 检查。

这些是实际函数配合确定性引擎回调的自动测试，不是运行游戏、真实网络预测或真人操作验收。下一次联合更新需实测单 B 原生形态的一格水跳跃上浮、深水、薄水层、进出水及形态切换，并观察服务端纠正和卡顿。源码、生产 DLL、部署和实机结果分别记录于连续性文件；当前候选尚未部署。
