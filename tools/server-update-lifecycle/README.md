# 补丁自动停服与恢复启动

当前 CS 1.6 大灾变累计包以 `-CsOnly` 管理 `cs/hlds.exe`。更新器先校验补丁和现有文件，再调用服主原有脚本停止运行中的 CS 专服。安装成功或完整回滚后自动重启。原本已停服的实例保持停止，重复安装已是最新版的补丁时可继续游戏。[累计包安装说明](../../docs/release-20261123-cof.md)

启停沿用原服务器的 `scripts/Stop-Servers.ps1` 和 `scripts/Start-Servers.ps1`，即标准 Stop.cmd／Start.cmd 调用的入口。使用原 `.state` 的角色、PID、创建时间与可执行文件路径确认身份；不按进程名批量结束，不强杀服务端，不改变端口、模式、密码或管理员。原启动脚本自身的配置与就绪检查仍然生效。

- `-Plan` 只读预检，不停服、不启动。
- 默认安装及 `-Restore` 都自动管理此前运行的服务。
- `-NoRestart` 仍保存停服和安装，但完成后保持停止。
- 预检失败不停止服务；正常写入失败且完整回滚后恢复旧服务，同时保留失败退出码。
- 停服失败不覆盖文件；回滚失败保持停服和备份。启动失败单独报错，保留已验证安装和备份，不声称服务器已经就绪。

只识别既有受管服务器。运行中的实例没有可信 `.state` 记录，或者缺少原启停脚本时拒绝自动操作；不能擅自猜测进程或启动参数。强行关闭更新器或机器断电不具备自动恢复执行上下文，重试前应检查事务和服务状态。标准脚本的 map/reset 规则仍适用，重启会结束当前对局。

打包入口在计算 SHA 或生成 ZIP 前调用 `package.py::enable(package)`，它适配当前事务以及已交付包继承的同类事务，并携带 `Lifecycle.ps1`。未知模板明确拒绝。当前累计包、Nightfall、Nightfall 热修复（含下载恢复）和 GuestBootstrap 四条生成路径均已接入。历史已封存 ZIP 不回写。

真实 WinPS／隔离进程回归入口：`python tests/server-update-lifecycle/run.py --output build/<fresh-directory>`。测试进程使用与原 Stop-Servers 相同的命令文件协议，持有真实 Windows 文件锁；不启动游戏或修改正式服务器。
