`ReadCsv` 接收解码后的 CSV 字节，不转换字符集。原始内容、记录偏移、空字段、重复字段和记录顺序均保留；支持 CRLF、LF、CR、带引号的逗号/换行和双引号转义。输入错误时返回字节位置与错误信息，并保留调用方上次成功结果。文件、行数、列数和字段长度有明确上限。整数导入采用完整字段校验，不模仿 `atoi` 对非法后缀的静默截断。

`ReadWaves` 保留每行并建立 `waveID → spawnPoint → 行索引列表`。同点重复行不能去重。权重保存为原有符号字节及按字节相加的总和；本层不随机选怪、不解释事件内容、不把权重总和当怪物数量。`spawnPoint=9999` 为事件行。原始时间保持不变，事件分支的运行时间变换留给后续调度实现。超出支持范围的权重、负数/过大的间隔会明确拒绝。

`ReadRounds` 保留表头之前的 metadata，包括重复的 `wall`，以及表头和全部属性列。当前只提取轮次和按原顺序排列的 wave 引用；保留属性列不等于已经实现升级、经济或回合状态机。

`SpawnPoints` 的键使用原 `int16(id)` 与 `int8(team)` 符号扩展的位模式。怪物点按注册顺序后者覆盖前者并清额度；人物点追加。`ConsumePointQuota` 在原逻辑中早于实体创建，因此消耗量不是存活怪物数；零上限不累计，缺点也通过额度检查，调用方必须单独确认点存在。priority=2 跳过额度的规则、playerspawn完整ID为−1的过滤、team默认值、普通出生点回退与占位实体移除都属于后续实体接线，不能隐含到容器里。

`FindMissingReferences` 保留每次引用的轮次和来源记录，区分缺波次与缺出生点，排除事件点9999。它不删除缺失引用、不合成替代波次或出生点。缺引用是诊断，不等于原版加载失败：原MP对未定义wave建立空程序，并在第一次调度时移出活动列表。资源版本须另核，不能用别的归档中恰好存在的同名行拼表。

`WaveRunner` 执行一个确定存在的wave：point按首次出现顺序，future行阻挡同point后续行；到点先推进时钟再调用handler，迟到只推进、不补发，end在handler之后检查。事件点9999且首类型非9999初始next增加2秒；部分reset只恢复未结束行的原始时间。该模块已通过98项单元、106项真实行检查及2840/84组原MP行时钟/部分reset对照，详见波次验证（工作区历史记录）。handler目前在测试中为capture，不能据此认定已刷怪。

新增 `WaveController` 负责普通活动wave列表，保留ID顺序及重复引用；相同16位key共享同一程序。源表与活动ID均按相同16位身份匹配，缺ID保留诊断并按空程序完成。完整 `Activate` 会重新装入本轮程序，不用部分行reset代替开局。当前只覆盖普通wave分支，不包括专用模式、动态事件增删wave和回合胜负。

`WaveSchedule` 将开局时间、最近非负elapsed及半秒门控分开保存。`BeginWaveRound` 仅设 `now + mp_freezetime`，保留nextThink；冻结期不写elapsed，等于门限可执行，handler之后重新采样引擎时间调用 `FinishWaveSchedule`，得到 `now + 0.5`。全新地图/会话创建新对象。`SpawnPoints::ResetMonsterQuotas` 只清生成额度，保留全部点位。原开局顺序为设时间原点→完整装入wave→刷新活动摘要→清额度；游戏接线尚未实现。

游戏工程已登记本数据层的编译项，完整DLL尚未构建或启用。独立构建入口为本目录 `CMakeLists.txt`，测试使用相同生产源码；原始游戏文件只作为工作区本地外部测试输入，不进入源码发布。

资源入口 `ReadWaveResource` / `ReadRoundResource` 接收游戏文件系统从集中目录读到的原始 `.cso` 字节：使用共用 `config_codec.hpp` 的32轮TEA解码私有副本，去掉尾部NUL，再走同一CSV/schema校验。无格式魔数、IV或校验和，调用者必须明确选择加密入口，不能按猜测自动识别。8字节不对齐、空文件、超过8MiB或解码后含内部NUL会明确拒绝且保留旧表；不重现原函数对不足一块的越界访问。该入口已通过七图14个真实文件的独立读取验证，尚未连到专服文件加载回调。

波次时间按原CSV整数读取函数的`atoi`前缀规则处理：`5.5`得到5，`0.1`得到0，空白得到0，不先转换为浮点数。生产仍拒绝无数字的非空时间、int32溢出、负间隔和大于32767的间隔，这些是明确的安全边界。普通行可省略末尾的空`eventmessage`，保留原CSV列数与字节。七个wave、六个普通round的完整文档/类型行/分组经独立130565项对照通过；生化魔方`gametype=4`的房间表由普通round入口明确拒绝。完整关卡和专用房间模式尚未实现。

`MapResources`通过与引擎`pfnLoadFileForMe`/`pfnFreeFile`相同的函数签名读取相对路径`maps/zbs_wave_<map>.cso`和`maps/zbs_<map>.cso`。`BeginMap`清除上一个地图会话，包含同名地图重开；`Reload`在本会话的两张表都成功后才提交，失败保留此前的完整表对。每个非空引擎缓冲恰好释放一次，仅使用返回的length，忽略引擎在length之外附加的NUL。已通过364项独立函数表检查及穷途末路288/2行真实资源17项检查；尚未接入GameRules生命周期或在真实专服执行。最新测试首图为用户指定的`zs_deadend`（gametype=1），专用推进/BOSS仍待实现。

上段是历史双表入口。当前MapResources同时加载wave/round/types，并按resolved subtype1/3/4/10条件加载TRG，全部提交才更换本会话数据。`BeginMapFromCatalog`可先读`resource/maplist.csv`，保留原数值ID首次匹配，并仅在同名文件候选SubType一致时解析宿主mapname。原管理器SubType来自该表第58列，不是round表gametype；穷途末路为1。自动入口失败不继承旧图，也不允许未解析类型直接Reload为0型。400/1055只验证独立生产代码与受控文件回调，非真实专服搜索路径或关卡玩法。
